### 조심할 것 — 확정은 `reserved` 를 먼저 줄인다

`ProductVariant_reserved_check` 가 `reserved <= stock` 을 **문장마다** 검사한다. 재고 1 · 예약 1
에서 `stock` 을 먼저 0으로 내리면 그 순간 `reserved(1) > stock(0)` 이라 **제약이 확정 자체를
거절한다.** 순서는 예약 → 재고다.

같은 제약이 기존 검사 하나의 이름도 바꿔 달았다. 음수 재고는 이제 `ProductVariant_stock_check`
가 아니라 `ProductVariant_reserved_check` 로 거절된다 — `0 <= reserved <= stock` 이
`stock >= 0` 을 함의하기 때문이고, 둘 다 위반이라 어느 이름이 나오는지는 Postgres 의 검사
순서다. 제약을 더할 때 **기존 S5 스펙이 이름으로 단언하고 있는지** 먼저 보는 편이 좋다.

준비중일 수 있어야 하고, B 만 취소할 수 있어야 하며, 정산도 판매자별로 나간다(D-023).

**배송 정책 컬럼을 여기서 만들었다.** F2 가 계산 엔진과 1원도 다르지 않기를 요구하는데 그 엔진은
배송 정책을 입력으로 받고, 그것을 만들어 주는 것이 아무 데도 없었다. TASK-0108 이 M09 로 미룬 것은
판매자 **설정 화면**이고, 화면보다 먼저 필요한 것은 값이 놓일 자리다. M09 는 이제 컬럼이 아니라
화면만 붙이면 된다.

**주문 생성은 재고를 한 개도 차감하지 않는다.** 예약을 잡고 `PAYMENT_PENDING` 으로 남는다. 원장에
적히는 것도 없다. 「주문했는데 재고가 그대로다」는 결함이 아니라 D-026 의 구조다 — 확정은 결제
승인(M08)의 일이고, 결제가 오지 않으면 TASK-0051 이 TTL 만료로 푼다.

**M11 을 위해 안분 경로를 미리 만들어 뒀다.** 쿠폰도 적립금도 아직 없지만 `OrderService.create` 는
할인 목록을 인자로 받고, 컨트롤러가 빈 배열을 넘길 뿐이다. 나중에 붙이면 그 시점에 이미 저장된
주문들이 안분액을 갖지 않는다.

### 장바구니 화면이 열렸다 — 담기도 이어졌다 (2026-09-05, TASK-0046)

`/cart` 가 껍데기에서 실제 화면이 됐고, 상품 상세의 「장바구니 담기」가 실제로 담는다. 남은 껍데기는
`/checkout` 하나다.

**합계를 화면이 계산하지 않는다.** `packages/shared` 의 `calculateOrder` 를 그대로 부른다 —
무료배송 판정이 쿠폰까지 반영한 상품금액 기준이고 적립금은 물건 값을 먼저 덮는데, 그 규칙이 화면에
두 번째 구현으로 생기면 「장바구니가 보여 준 금액과 결제 금액이 다르다」가 된다. **신고되지 않는
종류의 버그다** — 사는 사람은 결제 금액이 맞는 줄 안다.

**응답이 싣는 것은 계산된 배송비가 아니라 정책**(`shippingFee` · `freeShippingThreshold`)이다.
합계는 고른 항목에 대해서만 내는데 선택은 브라우저에 있고, 서버가 계산해 보낸 숫자는 체크 하나를
푸는 순간 틀린 값이 된다.

**장바구니의 `stock` 만은 실물 재고로 남겼다.** 예약은 15분짜리이고 장바구니는 며칠씩 머무는
곳이라, 남이 잠깐 주문서에 들고 있다고 「품절」이라고 쓰면 기다리면 오는 것을 안 온다고 말하는
것이 된다. 실제로 막는 것은 주문 시점의 예약이다.

### 조심할 것 — 같은 곳으로 가는 두 번째 링크는 이름이 없으면 axe 가 잡는다

### 조심할 것 — 「분기 100%」를 I/O 가 있는 파일에 걸지 않는다

### R2 공개 도메인이 404 다 — **객체는 있다, 경로만 없다**

`R2_PUBLIC_BASE_URL` 이 `https://cdn.demo-shopping.com` 인데 그 호스트가 404 를 준다.
**객체는 버킷에 있다** — `shopping-dev` 에 서명 GET 을 보내면 200 · `image/svg+xml` 로 나온다
(2026-09-05 실측). 업로드는 S3 엔드포인트로 가므로 성공하고, **저장된 공개 URL 만 안 열린다.**
지금은 시드 이미지도 판매자가 올린 이미지도 화면에 나오지 않는다.

404 가 R2 의 것이 아니라 **Cloudflare 엣지의 것**이라는 증거가 응답에 있다 — `content-type` 이
`text/html` 이고 `cf-r2-request-id` 헤더가 없다. 즉 DNS 레코드는 있는데 그 호스트가 버킷으로
라우팅되지 않는다.

**할 일**: R2 → 버킷 `shopping-dev` → Settings → Public access → **Custom Domains → Connect
Domain** → `cdn.demo-shopping.com`.

걸릴 만한 지점 둘:

- `cdn` DNS 레코드가 **이미 있다**(그래서 지금 Cloudflare IP 로 뜬다). 연결할 때 덮어쓸지 묻거나
  "record already exists" 로 거절한다 — 기존 레코드를 지우고 다시 연결한다. CNAME 은 R2 가 만든다.
- `demo-shopping.com` 존이 **버킷과 같은 Cloudflare 계정**에 있어야 목록에 뜬다.

도메인 없이 넘어가려면 같은 화면에서 `r2.dev` 공개 URL 을 켜고 `R2_PUBLIC_BASE_URL` 을
`https://pub-<해시>.r2.dev` 로 바꾼다.

**재업로드는 필요 없다** — 키가 내용 해시라 이미 올라간 156개가 그대로 열린다. 시드도 이것과
무관하게 동작한다: 올린 키를 DB 에 기억하므로 공개 URL 에 물어보지 않는다.
