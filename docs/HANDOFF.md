### 3.2 Vercel 프리뷰에서는 로그인이 성립하지 않는다

Google 은 와일드카드 리다이렉트 URI 를 허용하지 않는데 프리뷰 URL 은 배포마다 바뀐다. 그런데 **문제는
리다이렉트 URI 가 아니다** — 콜백은 API 하나이고 그 주소는 고정이다(TASK-0021 4장).

진짜 막는 것은 **프리뷰용 API 가 없다**는 것이다. Render 는 운영만 띄우므로 프리뷰 프론트는 운영 API 를
부르게 되고, 그러면 콜백이 `corsOrigins` 에서 고른 **운영 앱 오리진**으로 돌아간다. 프리뷰 화면으로는
영영 돌아오지 못한다.

| 필요한 것 | 주인 |
| --- | --- |
| 프리뷰 API 배포(또는 프리뷰가 부를 API 결정) | **미정** — 배포 구성이므로 TASK-0012 영역에 가깝다 |
| 프리뷰 오리진을 허용 목록에 넣는 방법 | 위가 정해진 뒤 |

TASK-0021 은 이것을 R3 으로 열어 둔 채 닫혔다. **프리뷰에서 로그인을 시연할 일이 생기면 그때가 정할
시점**이고, 그때까지는 로컬과 운영에서만 동작한다.

## 4. 사용자가 할 일

**막고 있다 — Render 에 `JWT_SECRET`.** TASK-0022 가 이것을 **필수**로 만들었다. R2·Google 과 달리
없으면 API 가 **부팅을 거부한다** — 로그인은 선택 기능이 아니라서, 없는 채로 뜨면 인증된 요청이 전부
500 이 된다. 이 브랜치가 머지되기 전에 넣어 두는 편이 안전하다.

```bash
openssl rand -base64 32
```

Render 대시보드 → `shopping-api` → Environment → `JWT_SECRET`. **로컬과 다른 값을 쓴다** — 같으면
로컬 키가 새는 순간 운영 토큰을 위조할 수 있다. 로컬 값은 이미 넣어 두었다.

**Google 로그인을 브라우저로 확인하려면 리다이렉트 URI 를 더 등록해야 한다.** 등록된 것은
`http://localhost:4000/...` 하나인데 워크트리마다 포트를 밀어 쓰므로(`PORT_OFFSET`) 실제로는 4005 ·
4006 이 나간다. Google 웹 클라이언트는 포트까지 정확히 일치해야 해서 `redirect_uri_mismatch` 가
난다. Console 의 승인된 리디렉션 URI 에 쓰는 포트를 추가하면 풀린다. **자동화 테스트는 포트를
대역화하므로 영향받지 않는다.**

동의 화면이 아직 테스트 모드라 Google Cloud Console 에 **테스트 사용자로 등록한 계정만** 로그인된다.
