## 1. 목적

리뷰·문의·상품에 대한 신고를 접수하고 관리자가 처리하게 한다.

## 2. 범위

### 포함
- `Report` — 대상 유형(리뷰/문의/답변/상품), 대상 ID, 신고자, 사유, 상태
- 신고 버튼 (리뷰·문의·상품)
- 중복 신고 방지 (같은 사용자·같은 대상)
- 관리자 신고 목록·처리 (숨김 / 삭제 / 반려)
- 처리 결과 이력
- 다수 신고 시 자동 임시 숨김 (임계치)
- 신고 처리 알림

### 제외
- 자동 필터링·AI 판정

## 3. 요구사항

- [ ] 리뷰·문의·상품을 신고할 수 있다
- [ ] 같은 대상을 중복 신고할 수 없다
- [ ] 관리자가 숨김·삭제·반려를 처리할 수 있다
- [ ] 일정 수 이상 신고되면 자동으로 임시 숨겨진다
- [ ] 처리 이력이 남는다

## 4. 설계

```
신고 접수 → (임계치 도달 시 자동 임시 숨김) → 관리자 검토 → 숨김 확정 / 삭제 / 반려(복구)
```

**자동 임시 숨김을 두는 이유**: 관리자가 즉시 대응할 수 없는 시간대에 악성 콘텐츠가 노출된 채 남는다. 임계치(예: 3건)를 넘으면 일단 가리고 검토한다. 반려하면 복구된다.

**신고 남용 방지**: 중복 신고를 막고, 반려된 신고가 반복되는 사용자를 관리자가 확인할 수 있게 한다.

## 5. 구현 계획

1. 스키마·마이그레이션
2. 신고 접수 API + 중복 방지
3. 신고 버튼 UI (3개 대상)
4. 자동 임시 숨김 로직
5. 관리자 처리 화면
6. 처리 이력·알림
