## 1. 목적

상품 열람 이력을 기록하고 보여준다. 개인화 기능의 기초 데이터가 된다.

## 2. 범위

### 포함
- `RecentlyViewed` — 사용자, 상품, 최근 조회 시각 (사용자+상품 unique)
- 상품 상세 조회 시 기록 (비동기, 조회 성능에 영향 없게)
- 최근 본 상품 페이지 (최대 50개, 오래된 것 자동 정리)
- 홈·상세 하단의 최근 본 상품 스트립
- 비로그인은 localStorage 에 기록, 로그인 시 병합
- 개별·전체 삭제

### 제외
- 추천 알고리즘

## 3. 요구사항

- [x] 상품을 보면 기록된다
- [x] 같은 상품을 다시 보면 시각만 갱신된다
- [x] 기록이 상품 상세 응답 속도에 영향을 주지 않는다
- [x] 비로그인 이력이 로그인 시 병합된다
- [x] 최대 개수를 넘으면 오래된 것이 정리된다

## 4. 설계

기록은 **비동기로 처리**한다. 상품 상세 조회에 쓰기 작업이 끼면 응답이 느려지고, 실패 시 조회 자체가 실패할 수 있다. 조회 응답을 보낸 뒤 기록한다.

사용자+상품 unique 로 두고 upsert 한다. 같은 상품을 10번 봐도 행은 1개다.

### 4.1 답을 만든 뒤에 적고, 던지지 않는다

상품 상세는 기록을 **기다리지 않는다** (F3). 그리고 기록하는 함수 자체가 예외를 삼킨다 (F4) — 사람이 보려던 것은 상품이지 이력이 아니고, 이력 때문에 상품이 안 열리면 그것은 훨씬 나쁜 고장이다.

### 4.2 로그인하지 않은 사람의 이력은 서버에 없다

브라우저가 들고 있다가 로그인할 때 합친다 (F6). 합칠 때 **더 최근 쪽이 이긴다** — 브라우저에 남아 있던 옛 기록이 방금 본 것을 뒤로 밀면 안 되고, `GREATEST` 가 그것을 한 문장으로 만든다.

**없는 상품이 섞여 있어도 통째로 실패하지 않는다.** 브라우저에 오래 남아 있던 이력에는 그 사이 지워진 상품이 있을 수 있고, 그것 때문에 병합 전체가 실패하면 그 사람의 이력은 영영 합쳐지지 않는다.

### 4.3 정리는 한 문장이다

「몇 개인지 세고 → 넘으면 지운다」가 두 문장이면 그 사이에 남이 끼어들 수 있다. 넘지 않으면 아무것도 지우지 않는다 (F5).
