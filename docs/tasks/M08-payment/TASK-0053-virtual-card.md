## 1. 목적

가상 카드를 발급하고 한도·사용액을 원장으로 관리한다. 환불이 제대로 됐는지 **카드 잔액으로 눈으로 확인**할 수 있게 한다.

## 2. 범위

### 포함
- `VirtualCard` — 카드번호(가상), 브랜드, 유효기간, 한도, 사용액, 상태
- `VirtualCardTransaction` — 승인·취소·환불별 금액과 잔액
- 발급 API (한도 지정, 사용자당 최대 개수 제한)
- **데모 계정 발급 시 1장 자동 지급** (TASK-0024 연동)
- 카드번호 생성 규칙 (실제 BIN 과 겹치지 않게)
- 사용 가능액 계산, 한도 초과 검증
- 카드 정지·삭제

### 제외
- 결제 승인 로직 (TASK-0054)
- 관리 화면 (TASK-0058)

## 3. 요구사항

- [ ] 카드를 발급하면 한도가 설정된다
- [ ] 사용액이 한도를 넘을 수 없다
- [ ] 모든 승인·취소·환불이 원장에 남는다
- [ ] 원장 합계와 사용액이 일치한다
- [ ] 데모 계정 발급 시 카드 1장이 자동 지급된다

## 4. 설계

```
카드번호: 9999-XXXX-XXXX-XXXX   ← 실제 카드 BIN 과 겹치지 않는 접두어
사용 가능액 = creditLimit − usedAmount
```

**실제 카드번호 형식과 구분되게 만든다.** 실제 BIN 을 쓰면 진짜 카드처럼 보여 오해를 부른다. 화면에도 "가상 카드"임을 명시한다.

원장은 재고·적립금과 같은 원칙이다 — 잔액이 있는 것은 원장을 둔다. 각 행에 `balanceAfter` 를 저장해 대사 가능하게 한다.

## 5. 구현 계획

1. 스키마·인덱스·마이그레이션
2. 카드번호 생성기
3. 발급 API + 개수 제한
4. 원장 서비스 (승인·취소·환불, 트랜잭션)
5. 한도 검증
6. 데모 발급 연동
7. 정합성 점검
