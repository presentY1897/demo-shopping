## 1. 목적

가상 카드 프로바이더를 구현한다. **실패 시나리오를 의도적으로 만들 수 있는 것**이 이 TASK 의 핵심 가치다.

## 2. 범위

### 포함
- `VirtualCardProvider` 구현 (authorize/capture/cancel/refund/getStatus)
- 결제 승인 시 카드 원장 차감, 재고 예약 확정 연동
- **실패 시나리오 재현 장치**
  - 한도 초과 / 잔액 부족
  - 승인 거절 (카드 상태·랜덤)
  - 승인 지연 (N초 지연 후 응답)
  - 타임아웃
- 실패 유도 방법: 특정 한도 카드, 또는 개발용 헤더/플래그
- 취소·부분 환불 시 원장 복구
- 결제 화면 (카드 선택 → 즉시 승인)

### 제외
- 토스 연동 (TASK-0055)
- 실패 후 복구 처리 전반 (TASK-0057)

## 3. 요구사항

- [ ] 가상 카드로 결제하면 즉시 승인된다
- [ ] 한도를 넘으면 거절된다
- [ ] 승인 지연·타임아웃을 재현할 수 있다
- [ ] 취소·환불하면 카드 잔액이 복구된다
- [ ] 승인 시 재고 예약이 확정된다

## 4. 설계

| 실패 시나리오 | 유도 방법 |
| --- | --- |
| 한도 초과 | 한도가 낮은 카드를 발급해 사용 |
| 승인 거절 | 카드 상태를 BLOCKED 로 변경 |
| 승인 지연 | 데모 화면의 "지연 재현" 옵션 (개발·데모 환경만) |
| 타임아웃 | 지연 시간을 타임아웃 초과로 설정 |

**이 장치를 두는 이유**: 토스 테스트만으로는 실패 경로를 보여주기 어렵다. 결제가 실패했을 때 재고 예약이 풀리는지, 주문이 올바른 상태로 가는지를 시연할 수 있어야 한다. 포트폴리오에서 설명거리가 가장 많은 부분이다.

**운영 환경에서는 지연·랜덤 거절을 비활성화**한다. 한도 초과·카드 정지는 정상 기능이므로 유지한다.

## 5. 구현 계획

1. 프로바이더 구현체 골격
2. 승인 로직 (원장 차감 + 예약 확정)
3. 실패 시나리오 장치
4. 취소·환불 (원장 복구)
5. 결제 화면 (카드 선택·승인)
6. 실패 케이스 테스트
