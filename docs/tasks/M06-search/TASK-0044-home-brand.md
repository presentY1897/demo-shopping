## 1. 목적

첫 화면과 브랜드관을 만든다. 방문자가 처음 보는 화면이므로 **디자인 방향과 밀도 3단계를 가장 먼저 알아채는 지점**이다.

## 2. 범위

### 포함
- 홈: 히어로 영역, 신상품, 인기 상품, 카테고리 바로가기
- 밀도 3단계 반영 (미니멀은 큰 이미지 소수, 맥시멀은 조밀한 다수)
- 브랜드관 `/brands/[sellerId]` — 판매자 소개, 상품 목록, 팔로우 버튼 자리
- 데모 계정 발급 유도 배너 (첫 방문 시)
- 밀도 토글 안내 (첫 방문 1회)

### 제외
- 관리자 큐레이션 도구
- 개인화 추천 (M13 이후 검토)
- 팔로우 실제 동작 (M13)

## 3. 요구사항

- [x] 홈에서 신상품·인기 상품이 보인다
- [x] 밀도 단계에 따라 홈 구성이 달라진다
- [x] 브랜드관에서 해당 판매자 상품만 보인다
- [x] 첫 방문자에게 데모 발급과 밀도 토글이 안내된다

## 4. 설계

홈의 섹션 구성은 **정적으로 정의**한다(신상품·인기·카테고리). 관리자 큐레이션 도구는 범위 밖이며, 필요하면 이후 마일스톤에서 붙인다.

인기 상품 기준은 `salesCount` 다. 시드 데이터에서 판매량 분포를 만들어 두므로(TASK-0037) 초기에도 의미 있게 보인다.

**첫 방문 안내**는 두 가지만 노출한다 — 데모 계정 발급, 밀도 토글. 이 사이트의 두 특징이고, 그 이상은 미니멀 원칙에 어긋난다.

### 4.1 홈 섹션 API 는 새로 만들지 않는다 (2026-09-05 확인)

5장 1번이 「홈 섹션 API」를 말하지만 **필요한 것이 이미 있다.** 신상품은
`GET /search?sort=newest`, 인기는 `?sort=sales` 이고 둘 다 공개이며, TASK-0039 가 그 경로의
A1·A5 를 이미 쟀다. 응답은 `SearchHit` 이라 TASK-0040 의 카드가 그대로 그린다.

엔드포인트를 새로 내면 같은 질의를 두 이름으로 부르게 되고, 「인기」의 정의가 두 군데가 된다.

### 4.2 브랜드관에는 두 가지가 없다 (2026-09-05 정정)

| 없는 것 | 어떻게 |
| --- | --- |
| 판매자별 상품 조회 | 색인에 `sellerId` 가 이미 **필터 가능**한데 질의 생성기에 절이 없다. `searchQuerySchema` 에 `sellerId` 를 더하고 절을 하나 만든다 |
| 판매자 소개를 읽는 공개 라우트 | `GET /sellers/me` 는 자기 것뿐이고 `/admin/sellers/:id` 는 관리자다. TASK-0042 4.2 · TASK-0043 4.1 과 같은 모양으로 공개 라우트를 낸다 |

공개 판매자 응답은 상점이 그리는 것만 담는다 — `brandName` · `slug` · `introduction` ·
`logoUrl`. 수수료율·상태 사유·신청 이력은 콘솔의 것이다. **`ACTIVE` 가 아닌 판매자는 404** 다:
심사 중이거나 정지된 가게의 존재를 상점이 알려 줄 이유가 없다.

**경로 파라미터는 `sellerId` 다** — 2장이 그렇게 적고 있고, TASK-0043 이 이미
`/brands/{seller.id}` 로 링크한다. `Seller.slug` 가 「이름을 바꿔도 링크가 살아 있도록」
존재한다는 것은 안다(erd.md). 그쪽으로 옮기는 것은 URL 정책이므로 **TASK-0102(SEO)의 몫으로
남긴다** — 여기서 바꾸면 이미 나간 링크와 갈린다.

### 4.3 밀도 안내는 이미 있다 (2026-09-05 확인)

2장의 「밀도 토글 안내 (첫 방문 1회)」는 TASK-0018 R1 이 만들었다 —
`components/layout/density-hint.tsx` 와 `lib/density-hint.ts` 가 그것이고, 셸에 붙어 있어 홈이
따로 할 일이 없다. **이 TASK 가 더하는 첫 방문 안내는 데모 발급 쪽 하나다.**

## 5. 구현 계획

1. **`sellerId` 검색 필터 + 공개 판매자 라우트** (4.2)
2. 홈 레이아웃 + 밀도 분기 (섹션 데이터는 검색 API — 4.1)
3. 히어로 영역
4. 브랜드관 페이지
5. 데모 유도 배너 + 첫 방문 기록 (밀도 안내는 이미 있다 — 4.3)

**F6 은 이 TASK 의 통과 조건이 아니다** (2026-09-05 정정). [품질 게이트 2장](../QUALITY-GATES.md)이

악화)의 **대응은 그대로 한다** — 그건 게이트가 아니라 설계다.

**TASK-0101 F4 는 그대로 지켰다.** 그쪽이 「`HomePage()` 가 Promise 를 반환하지 않고, 호출해도
요청이 나가지 않으며, `/` 가 정적 프리렌더된다」를 **구조로** 못박아 뒀고, 그 이유는 콜드
스타트다 — 서버에서 기다리면 90초짜리 기상을 5초 타임아웃으로 맞이한다. 홈에 데이터를 붙이면서
그것을 뒤집을 수는 없으므로 **섹션은 브라우저에서 읽는다.** `pnpm build` 가 여전히 `/` 를
`○ (Static)` 로 표시한다.

> **열린 질문 — 크롤러는 상품 줄을 보지 못한다.** 마크업에 있는 것은 셸·히어로·카테고리이고
> 상품은 마운트 뒤에 온다. 그것을 HTML 에 넣으려면 TASK-0101 F4 를 바꿔야 하고, 그건 결정이
> 필요한 일이지 이 파일을 조용히 고칠 일이 아니다. **TASK-0102(SEO)로 넘긴다.**
