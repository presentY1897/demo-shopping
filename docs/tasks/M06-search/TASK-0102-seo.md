## 1. 목적

구매자 앱(`apps/shop`)의 검색 노출 기반을 만든다. 개별 화면 TASK 에 흩어진 메타 태그를 하나의 전략으로 통합한다.

## 2. 범위

### 포함
- 메타 태그 규약 — title / description / canonical, 페이지 유형별 템플릿
- Open Graph · 트위터 카드, **동적 OG 이미지** (상품명·가격·이미지 합성)
- 구조화 데이터 — `Product`, `BreadcrumbList`, `Organization`, `AggregateRating`
- `sitemap.xml` 동적 생성 (상품·카테고리·브랜드관)
- `robots.txt`
- **검색 결과·필터 조합 페이지는 `noindex`** — 중복 콘텐츠 방지
- **판매자·관리자 앱 전체 `noindex`**
- 렌더링 전략 — 상품 상세는 ISR, 카테고리는 SSR
- 이미지 alt 전수 점검
- 다국어 대비 `hreflang` 자리 (D-014, 지금은 ko 만)

### 제외
- 외부 링크 빌딩·콘텐츠 마케팅
- Search Console 등록 (배포 후 수동)

## 3. 요구사항

- [x] 상품 상세가 검색엔진에 유효한 구조화 데이터를 제공한다
- [x] 필터 조합 URL 이 색인되지 않는다
- [x] 콘솔 앱이 색인되지 않는다
- [x] sitemap 에 상품·카테고리가 자동 포함된다
- [x] OG 이미지가 링크 공유 시 표시된다

## 4. 설계

| 페이지 | 색인 | 렌더링 | canonical |
| --- | --- | --- | --- |
| 홈 | ✓ | SSG + 재검증 | 자기 자신 |
| 카테고리 | ✓ | SSR | 필터 없는 기본 URL |
| 상품 상세 | ✓ | **ISR** | 자기 자신 |
| 브랜드관 | ✓ | SSR | 자기 자신 |
| 검색 결과 | **noindex** | SSR | – |
| 필터 적용 목록 | **noindex** | SSR | 기본 카테고리 URL |
| 마이페이지·주문 | noindex | – | – |
| seller / admin 앱 | **전체 noindex** | – | – |

**필터 조합을 색인하지 않는 이유**: 속성 필터가 자동 생성되므로(TASK-0039) URL 조합이 수백 개가 된다. 전부 색인되면 거의 같은 내용의 페이지가 대량 생성되어 중복 콘텐츠로 평가가 떨어진다. 기본 카테고리 URL 로 canonical 을 걸어 신호를 한 곳에 모은다.

**상품 상세를 ISR 로 하는 이유**: 재고·가격이 바뀌지만 매 요청마다 서버 렌더링을 하면 콜드 스타트 영향까지 겹친다. 짧은 재검증 주기(예: 60초)로 정적 제공하되 최신성을 유지한다.

### 4.1 홈의 상품 줄은 마크업에 없다 — 사이트맵이 답이다 (2026-09-05, TASK-0044 이월)

TASK-0044 가 이 질문을 여기로 넘겼다. 홈의 신상품·인기 줄은 **브라우저에서** 읽는다 —
TASK-0101 F4 가 「서버 렌더는 아무것도 기다리지 않는다」를 구조로 못박아 뒀고, 이유는 콜드
스타트다(90초짜리 기상을 5초 타임아웃으로 맞이한다).

**F4 를 바꾸지 않는다.** 크롤러에게 URL 목록을 주는 것은 페이지 안의 링크가 아니라
`sitemap.xml` 이고, 그것은 이미 이 TASK 의 범위다. 사이트맵은 상품·카테고리·브랜드관 전부를
직접 넘기므로 홈이 링크를 몇 개 그리는지와 무관하다.

정리하면 — **홈은 진입 경험이고 사이트맵은 색인 경로다.** 둘을 같은 수단으로 풀려던 것이 잘못된
전제였다.

### 4.2 브랜드관 URL 은 `sellerId` 로 둔다 (2026-09-05, TASK-0044 이월)

`Seller.slug` 가 「이름을 바꿔도 링크가 살아 있도록」 존재한다는 것은 `erd.md` 가 적어 뒀고,
TASK-0044 가 이 결정을 여기로 넘겼다. **옮기지 않는다.**

| | |
| --- | --- |
| 옮기면 얻는 것 | 읽을 수 있는 주소 |
| 옮기면 드는 것 | TASK-0043 이 이미 내보낸 `/brands/{id}` 링크에 리다이렉트가 필요하고, 판매자 라우트가 id 와 slug 둘 다 받아야 한다 |

canonical 은 id 주소를 가리킨다 — 한 페이지에 주소가 둘이 되지 않게. slug 로 옮기는 것은 그때
리다이렉트와 함께 하는 별도의 일이고, 컬럼은 그날까지 그대로 남는다.

### 4.3 F8 은 Lighthouse 로 재지 않는다 (2026-09-05 정정)

Lighthouse SEO 점수는 **실제 브라우저와 떠 있는 서버**를 요구한다. 이 저장소는 같은 비용을 접근성
(P2)에서 이미 거절했고 — 스토리마다 axe 를 돌리는 쪽이 값싸고 실제로 회귀를 잡았다 — 성능에서도
거절했다([품질 게이트 2장](../QUALITY-GATES.md)).

그리고 Lighthouse 의 SEO 감사는 사실상 **목록**이다: title 과 description 이 있는가, canonical 이
맞는가, `robots` 가 크롤을 막고 있지는 않은가, 이미지에 alt 이 있는가, 링크에 이름이 있는가.
전부 마크업에서 확인되는 것이고, 그러므로 **검사로 잰다.** 점수 대신 그 목록을 항목별로 잰다 —
「95점」보다 「무엇이 빠졌는가」가 고칠 때 쓸모 있다.

## 6. 완료 기준

### 6.1 기능

| # | 기준 | 측정 방법 | 목표 | 실측 | 충족 |
| --- | --- | --- | --- | --- | --- |
| F1 | 구조화 데이터 | 상품 상세의 JSON-LD | 오류 0건, Product 인식 | TASK-0043 이 만들었고 여기서 그대로 쓴다. `Product` + `AggregateOffer`, 가격 범위는 **주문 가능한 것만**, 리뷰 0이면 `aggregateRating` 없음 | [x] |
| F2 | OG 이미지 | 카드에 실리는 값 | 이미지·이름·가격 | 카드 데이터를 검사로 잰다 — 이름·브랜드·**주문 가능한 최저가**·첫 이미지. 그려진 PNG 자체는 배포에서 확인할 것(아래) | [x] |
| F3 | sitemap | `/sitemap.xml` | 상품·카테고리 전부 | 홈 + 카테고리 **전 노드**(잎까지) + 상품 + 브랜드관. 브랜드는 상품에서 파생한다 — 빈 가게로 크롤러를 보내지 않기 위해서다. 읽기 실패는 **짧은 사이트맵**이지 500 이 아니다 | [x] |
| F4 | 필터 noindex | 카테고리·검색의 메타 | `noindex` + canonical | 검색은 `noindex, follow`, 카테고리는 필터가 걸려도 canonical 이 **필터 없는 주소**다. **`noindex` 와 canonical 을 함께 걸지 않는다** — 둘은 다른 말이고 같이 걸면 canonical 대상까지 빠질 수 있다 | [x] |
| F5 | 콘솔 차단 | seller·admin | Disallow + noindex | **둘 다.** `robots.txt` 는 크롤러가 읽고 따를 때만 듣고 메타 태그는 가져온 뒤에야 읽힌다 — 하나만 있으면 각각 빈틈이 있다 | [x] |
| F6 | ISR | 재검증 창 | 갱신 반영 | **원인을 잰다** (아래). 페이지가 내건 창과 요청이 보내는 창이 같은지를 음성 대조군까지 확인했다 | [x] |
| F7 | alt | 전 이미지 점검 | alt 누락 0건 | 홈·상품·브랜드관을 훑어 `alt` 없는 `<img>` 0건. 장식 썸네일은 `alt=""` 여야 한다는 것까지 잰다 | [x] |
| F8 | ~~Lighthouse SEO~~ | ~~주요 4화면~~ | ~~95점 이상~~ — **점수 대신 항목으로 잰다** (4.3) | [-] |
| F8b | 메타 전수 | 주요 4화면의 메타데이터 | title·description·canonical·robots 가 유형별 규약대로 | [ ] |
| F9 | 절대 URL | canonical · OG · sitemap | 전부 절대 URL 이고 같은 오리진 | [ ] |

**F6 은 「원인」을 잰다.** 재검증이 실제로 도는 것은 배포에서만 보이지만, 그것이 **돌 수 없게 되는**
경우는 코드에 있고 조용하다 — 페이지가 `revalidate = 60` 을 내걸어도 그 안의 요청이
`cache: 'no-store'` 면 아무것도 캐시되지 않는다. 경고도 없고 빌드 출력도 같다.

실제로 그 상태였다. 공용 클라이언트가 `cache: 'no-store'` 를 **모든 요청에** 박아 두고 있었다 —
세션과 장바구니에는 옳은 기본값이지만, 그것 때문에 어떤 페이지도 캐시될 수 없었다. 캐시를
**옵트인**으로 바꾸고, 상점의 공개 읽기만 창을 지정한다.

그리고 **Next 는 `revalidate` 를 리터럴로만 받는다** — 상수를 import 하면
「Invalid segment configuration export」로 빌드가 깨진다. 그래서 숫자는 두 번 적히고,
`isr-window.spec.ts` 가 그 둘이 같은지를 잰다. 모듈이 될 수 없는 것을 검사가 한다.

**배포에서 확인할 것 둘** — 이 저장소에서 잴 수 없는 것들이다:
- 링크를 공유했을 때 OG 카드가 **한글로** 그려지는가 (글꼴을 요청 시점에 받는다. 못 받으면
  카드를 만들지 않고 404 를 낸다 — 두부로 채운 그림보다 낫다)
- 상품을 고친 뒤 60초가 지나 새 값이 보이는가
