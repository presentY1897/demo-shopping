## 1. 목적

카테고리 탐색 경로를 만든다. 검색 페이지와 같은 필터·목록을 쓰되 진입 맥락이 다르다.

## 2. 범위

### 포함
- `/categories/[slug]` — 하위 카테고리 전체 상품
- 카테고리 네비게이션 (헤더 메가메뉴 또는 드롭다운)
- 브레드크럼
- 하위 카테고리 바로가기
- 필터·정렬·목록 (TASK-0041 컴포넌트 재사용)
- SEO — 메타 태그, 구조화 데이터
- 존재하지 않는 slug 404

### 제외
- 카테고리별 배너·큐레이션

## 3. 요구사항

- [x] 상위 카테고리에서 하위 상품이 모두 보인다
- [x] 브레드크럼으로 상위로 이동할 수 있다
- [x] 검색 페이지와 동일한 필터 동작을 한다
- [x] 비활성 카테고리는 접근되지 않는다

## 4. 설계

카테고리 페이지는 **검색 API 에 `categoryId` 를 고정한 것**이다. 별도 API 를 만들지 않는다. `path` 기반 하위 포함 조회를 검색 필터로 표현한다.

### 4.1 「하위 포함」은 색인 쪽을 한 번 고쳐야 성립한다 (2026-09-05 정정)

**지금은 성립하지 않는다.** TASK-0039 의 질의 생성기가 `categoryId = 3` 이라는 **정확히 일치**
절을 만들고(`search-query.ts`), 색인은 조상 이름의 배열(`categoryPath`)만 갖고 있어 걸 수 있는
것이 없다. 이대로면 F1(최상위 카테고리 진입 → 하위 전체 상품)이 빈 목록을 낸다.

고칠 곳은 한 군데다. **문서에 조상 id 사슬을 필터 가능한 배열로 싣는다.**

| | |
| --- | --- |
| 무엇 | `categoryIds: [1, 5, 12]` — 루트부터 자기 자신까지. `Category.path` (`/1/5/12/`) 가 이미 그것이다 |
| 어디 | `search-source.ts` 의 조상 서브쿼리에 이름과 나란히 id 를 담는다. 그 서브쿼리는 이미 조상 전체를 훑고 있다 |
| 질의 | `categoryId = 3` → `categoryIds = 3`. Meilisearch 의 배열 멤버십이라 **문법도 API 계약도 그대로다** |

`searchQuerySchema.categoryId` 는 정수 하나로 남는다 — 화면이 하위 id 를 모아 보내는 방식은
쓰지 않는다. 40개짜리 분류에서도 최상위 하나가 26개 id 를 실어 보내게 되고, 카테고리가 하나
늘 때마다 링크의 뜻이 달라진다.

**검색 화면의 동작도 함께 바뀐다.** 「코트」로 좁힌 검색이 그 하위 카테고리 상품까지 포함하게
된다 — 그쪽이 옳다. 카테고리를 골랐다는 것은 그 가지를 골랐다는 뜻이지 그 노드에 직접 매달린
상품만 보겠다는 뜻이 아니다.


### 4.2 카테고리 목록에 손님이 닿을 수 없다 (2026-09-05 정정)

`GET /categories` 는 `catalog.read` 를 요구하고, 그 퍼미션은 BUYER·SELLER·ADMIN 에게만 있다.
**로그아웃한 방문자와 검색 크롤러는 401 을 받는다** — 상점 앞 카테고리 내비게이션과 카테고리
화면이 성립하지 않는다.

`@PublicEndpoint` 와 `@RequirePermission` 은 한 핸들러에 같이 걸 수 없다(가드가 500 으로
거절한다). 그래서 **상점용 읽기 라우트를 따로 낸다** — `GET /categories/tree`.

| | |
| --- | --- |
| 왜 기존 라우트를 열지 않나 | 콘솔이 `?includeInactive=true` 로 부르는 그 라우트다. 공개하면 손님이 폐기된 카테고리를 열거할 수 있다 |
| 새 라우트가 못 하는 것 | **`includeInactive` 매개변수가 아예 없다.** 표현할 수 없는 것은 틀릴 수도 없다 |
| 응답 | `categoryTreeResponseSchema` 그대로. 새로 선언하는 모양이 없다(C1) |

## 5. 구현 계획

1. **색인에 조상 id 사슬을 싣고 질의를 배열 멤버십으로 바꾼다** (4.1)
2. 카테고리 라우트 + 데이터 로딩
3. 브레드크럼·하위 바로가기
4. 헤더 카테고리 네비게이션
5. 필터·목록 재사용 연결
6. SEO 메타·구조화 데이터
7. 404·비활성 처리
