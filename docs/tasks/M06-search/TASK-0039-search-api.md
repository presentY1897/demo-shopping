## 1. 목적

검색·필터·정렬·패싯을 하나의 API 로 제공한다. 필터 항목은 **카테고리의 속성 정의로부터 자동 도출**된다.

## 2. 범위

### 포함
- 검색 API — 키워드, 카테고리, 가격 범위, 속성 필터, 재고 유무, 정렬, 커서 페이지네이션
- **패싯 집계** — 필터 후보별 개수 반환
- 필터 스키마 API — 해당 카테고리에서 노출할 필터 정의(`isFilterable=true`)
- 자동완성 API (접두어 검색)
- 오타 보정 동작 확인
- 검색어 로깅 (인기 검색어 기반 데이터)

### 제외
- 화면 (TASK-0041)
- 개인화 추천

## 3. 요구사항

- [x] 오타를 입력해도 결과가 나온다
- [x] 카테고리마다 다른 필터 목록이 반환된다
- [x] 패싯에 각 값의 상품 개수가 포함된다
- [x] 정렬(관련도·최신·가격·판매량·평점)이 동작한다
- [x] 필터를 걸어도 응답이 빠르다

## 4. 설계

```
GET /api/v1/search?q=코트&categoryId=3&price=50000..200000&attr.fit=오버&sort=price_asc&cursor=...

응답: { items, facets: { brandName: {...}, fit: {...} }, total, nextCursor }
```

필터 스키마는 `AttributeDefinition` 의 `isFilterable` 을 그대로 쓴다. **관리자가 속성에 필터 노출을 켜면 검색 화면에 필터가 생긴다.** 코드 변경이 없다.

#### F2 — 오타 보정은 기본 설정으로는 한국어에서 거의 안 걸린다

Meilisearch 는 **5자**부터 오타 하나를 허용하고, 길이를 문자 수로 센다. 한국어는 한 음절이 한
문자이므로 세 음절 단어는 3자이고 관용이 **0** 이다. 같은 픽스처에서 한 음절씩 바꿔 재 봤다.

| 질의 | 기본 (5 / 9) | 낮춘 값 (2 / 5) |
| --- | --- | --- |
| 레트루 → 레트로 | **0건** | 1건 |
| 러니 → 러너 | **0건** | 1건 |
| 발마간 → 발마칸 | 1건 | 1건 |
| 더불 → 더블 | 1건 | 1건 |

즉 임계값을 내리는 것이 실제로 두 경우를 살린다. `1` 도 재 봤고 모든 쌍에서 `2` 와 **동일**해서
보수적인 쪽을 뒀다.

**이 문서가 예로 든 「코투」→「코트」는 어느 값에서도 안 된다.** 바람이 아니라 측정을 적는다 —
검사에도 그렇게 적어 뒀으므로, 엔진이나 토크나이저가 바뀌어 되기 시작하면 그 검사가 빨개진다.
