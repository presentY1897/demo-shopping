## 1. 목적

상품 카드와 목록 그리드를 만든다. **밀도 3단계가 실제로 보이는 첫 컴포넌트**이고, 이후 모든 목록 화면이 이걸 쓴다.

## 2. 범위

### 포함
- 상품 카드 — 밀도 단계별 표시 항목 분기
- 목록 그리드 (**밀도 × 브레이크포인트 매트릭스** 기반 열 수)
- 카드 내부는 **컨테이너 쿼리**로 자기 폭에 반응
- 이미지 lazy loading, 종횡비 고정 (레이아웃 이동 방지)
- 위시리스트 버튼 자리 (M13 연결)
- 빠른 담기 버튼 (맥시멀 단계에서만)
- 스켈레톤·빈 상태·에러
- 무한 스크롤 연결

### 제외
- 검색 페이지 (TASK-0041)
- 위시리스트 실제 동작 (M13)
- 빠른 담기 실제 동작 (M07)

## 3. 요구사항

- [x] 밀도 단계별로 표시 항목이 달라진다
- [x] 데이터는 항상 전부 내려받고 표시 여부만 바뀐다
- [x] 이미지 로딩 중에도 레이아웃이 흔들리지 않는다
- [x] 세 단계 모두 3개 뷰포트에서 정상이다

## 4. 설계

| 항목 | 미니멀 | 표준 | 맥시멀 |
| --- | --- | --- | --- |
| 이미지 | 대형 | 중형 | 소형 |
| 상품명 | ✓ | ✓ | ✓ |
| 가격 | ✓ | ✓ | ✓ |
| 브랜드 | 호버 시 | ✓ | ✓ |
| 할인율 | ✗ | ✓ | ✓ |
| 평점·리뷰수 | ✗ | 평점만 | ✓ |
| 색상 칩 | ✗ | ✓ | ✓ |
| 판매량·배지 | ✗ | ✗ | ✓ |
| 잔여 재고 | ✗ | ✗ | ✓ (임박 시) |
| 빠른 담기 | ✗ | ✗ | ✓ |

**데이터를 전부 내려받는 이유**: 밀도를 바꿀 때마다 재요청하면 전환이 느려지고 캐시가 3벌이 된다. 페이로드 차이는 작다.

**열 수는 밀도 × 뷰포트 매트릭스를 따른다** (`docs/design/pages.md` 참조).

| | ~639 | 768 | 1280+ |
| --- | --- | --- | --- |
| 미니멀 | 1 | 2 | 3 |
| 표준 | 2 | 3 | 4 |
| 맥시멀 | 2 | 4 | 6 |

**표시 항목은 밀도만 따른다.** 모바일에서 열 수를 줄이면 카드가 커지므로 맥시멀 정보도 들어갈 자리가 생긴다. 카드 내부 배치는 컨테이너 쿼리로 폭에 맞춘다 — 1열이든 6열이든 같은 컴포넌트가 알아서 대응한다.

`sizes` 속성에 밀도별 열 수를 반영해 뷰포트에 맞는 이미지 크기를 내려받는다.

## 5. 구현 계획

1. 카드 컴포넌트 + 밀도 분기
2. 그리드 (밀도별 열 수, 반응형)
3. 이미지 최적화 (lazy, 종횡비, blur placeholder)
4. 스켈레톤·빈 상태·에러
5. 무한 스크롤
6. 9조합(밀도 3 × 뷰포트 3) 검증
