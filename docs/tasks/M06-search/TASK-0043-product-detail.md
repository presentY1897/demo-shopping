# TASK-0043: 상품 상세 (밀도 3단계)

| 항목 | 내용 |
| --- | --- |
| 마일스톤 | M06 검색·탐색 |
| 상태 | 승인됨 |
| 작성일 | 2026-09-02 |
| 브랜치 | `feature/product-detail` |
| 선행 작업 | TASK-0040 |

## 1. 목적

상품 상세 페이지를 만든다. **미니멀↔맥시멀 대비가 가장 극적으로 드러나는 화면**이다.

## 2. 범위

### 포함
- 이미지 갤러리 (확대, 썸네일, 스와이프)
- 옵션 선택 → Variant 확정, 재고에 따른 선택 제한
- 존재하지 않는 조합 처리
- 가격 표시 (정가·할인가·할인율)
- 상품 정보 (설명, 속성 표)
- 밀도 3단계 레이아웃 분기
- 장바구니 담기·바로구매 버튼 자리 (M07 연결) — **모바일은 하단 고정 바, 데스크톱은 우측 패널**
- 위시리스트 버튼 자리 (M13)
- 리뷰·문의 영역 자리 (M13)
- 판매자 정보·브랜드관 링크
- SEO·구조화 데이터 (Product 스키마)

### 제외
- 장바구니 실제 동작 (M07)
- 리뷰·문의 실제 동작 (M13)
- 추천 상품 (M13 또는 M15)

## 3. 요구사항

- [ ] 옵션을 고르면 해당 Variant 의 가격·재고가 반영된다
- [ ] 품절 조합은 선택할 수 없다
- [ ] 밀도 3단계에서 정보량과 레이아웃이 달라진다
- [ ] 모바일에서 이미지 스와이프가 동작한다

## 4. 설계

| 영역 | 미니멀 | 표준 | 맥시멀 |
| --- | --- | --- | --- |
| 레이아웃 | 이미지 전면, 긴 스크롤 | 좌 이미지 / 우 정보 | 좌 이미지 / 우 정보 + 사이드 정보 |
| 속성 표 | 접힘 | 주요 항목 | 전체 표 |
| 배송 정보 | 최소 | 요약 | 상세 + 예상 도착일 |
| 리뷰 | 링크만 | 요약 + 3건 | 요약 + 분포 + 5건 |
| 추천·묶음 | ✗ | ✗ | ✓ |
| 구매 유도 배지 | ✗ | 일부 | 전체(판매량·조회수·재고임박) |

**옵션 선택 로직**: 첫 옵션을 고르면 그와 조합 가능한 두 번째 옵션만 활성화한다. 존재하지 않는 조합을 고를 수 없게 한다.

### 4.1 손님이 상품을 볼 수 없다 (2026-09-05 정정)

`GET /products/:id` 는 `product.read` 를 요구한다. 카테고리 트리와 같은 문제다 — 로그아웃한
방문자와 검색 크롤러가 401 을 받고, 색인 대상인 화면이 성립하지 않는다. 게다가 그 라우트는
**초안과 판매중지 상품도 내려준다**. 상점이 그것을 보여 주면 검색에서 뺀 의미가 없다
(TASK-0038 F3 이 색인에서 뺀 바로 그 상태다).

TASK-0042 4.2 와 같은 모양으로 상점용 공개 라우트를 낸다.

| | |
| --- | --- |
| 라우트 | `GET /products/:id/detail` — 공개 |
| 무엇 | `ACTIVE` 만. 그 외는 **404** 다. 「없음」과 「보이면 안 됨」을 구별해 주면 비공개 상품의 존재가 새어 나간다 |
| 응답 | `{ product, seller: { id, brandName } }` — 판매자 정보·브랜드관 링크(2장)에 필요한 최소 |

### 4.2 R2 는 이미 해결돼 있다 (2026-09-05 확인)

「조합 맵을 서버에서 만들어 내려준다」는 TASK-0032 가 이미 했다.
`productVariantSchema.optionValueIds` 가 그 상품 자신의 축 순서대로 담긴 조합이고,
`options[].values[]` 가 축과 선택지다. **조합 맵을 새로 만들 것이 없다** — 화면은 variant 목록을
축별로 뒤집어 「이 값을 고르면 남는 조합이 있는가」를 답하면 된다.

`isActive` 와 `stock` 이 나뉘어 있는 것도 그대로 쓴다. F2(품절)와 F3(없는 조합)은 **다른 상태**다 —
품절은 있는 조합이고 없는 조합은 아예 SKU 가 없다. 화면도 다르게 말해야 한다.
