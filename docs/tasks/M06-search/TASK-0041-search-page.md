# TASK-0041: 검색 페이지 · 자동완성 · 필터

| 항목 | 내용 |
| --- | --- |
| 마일스톤 | M06 검색·탐색 |
| 상태 | 완료 |
| 작성일 | 2026-09-02 |
| 브랜치 | `feature/search-page` |
| 선행 작업 | TASK-0039, TASK-0040 |

## 1. 목적

검색 화면을 만든다. **필터 UI 가 속성 정의로부터 자동 생성**되는 것이 핵심이다.

## 2. 범위

### 포함
- 헤더 검색창 + 자동완성 드롭다운 (키보드 조작)
- 검색 결과 페이지 (목록 그리드 재사용)
- **필터 패널 자동 생성** — 필터 스키마 API 응답으로 UI 구성
- 필터 타입별 위젯 (선택형·범위형·불리언)
- **모바일은 바텀시트, 데스크톱은 좌측 사이드 패널** — 같은 라우트 안에서 컴포넌트 분기
- 패싯 개수 표시, 결과 0건인 값 비활성화
- 정렬 선택
- 적용된 필터 칩 + 개별·전체 해제
- URL 동기화 (필터·정렬·검색어가 URL 에 반영, 공유·뒤로가기 동작)
- 검색어 없음·결과 없음 상태

### 제외
- 인기 검색어·최근 검색어 (M13 에서 검토)

## 3. 요구사항

- [x] 카테고리를 바꾸면 필터 항목이 달라진다
- [x] 필터를 걸면 URL 이 바뀌고 새로고침해도 유지된다
- [x] 자동완성을 키보드로 선택할 수 있다
- [x] 결과 0건이 되는 필터 값은 비활성 표시된다
- [x] 밀도 3단계가 결과 목록에 적용된다

## 4. 설계

```
검색 → 필터 스키마 API → 필터 패널 렌더 → 사용자 선택 → URL 갱신 → 검색 API → 결과 + 패싯 갱신
```

**필터 UI 를 하드코딩하지 않는 이유**: 관리자가 속성을 추가하면 필터도 따라 생겨야 한다. D-005 의 "설정 가능"이 검색까지 이어지는 지점이다.

URL 동기화는 포트폴리오에서 중요하다. 필터를 건 상태의 링크를 공유할 수 있어야 실제 서비스처럼 보인다.

## 5. 구현 계획

1. 검색창 + 자동완성 (디바운스·키보드)
2. 결과 페이지 골격
3. 필터 패널 자동 생성
4. 타입별 필터 위젯
5. URL 동기화
6. 필터 칩·해제
7. 빈 상태·오타 안내

## 6. 완료 기준

### 6.1 기능

| # | 기준 | 측정 방법 | 목표 | 실측 | 충족 |
| --- | --- | --- | --- | --- | --- |
| F1 | 자동완성 | 「코트」 입력 후 ↑↓·Enter | 후보 표시, 키보드로 선택 | 후보 2개 이상, `aria-activedescendant` 가 따라 움직이고 Enter 가 그 후보로 검색한다. **처음에는 아무것도 선택돼 있지 않다** — 갓 입력한 낱말에 Enter 를 치면 그 낱말로 검색돼야 한다 | [x] |
| F2 | 필터 자동 생성 | 코트(31) → 신발(32) 전환 | 필터 항목이 각각 다르게 생성 | 코트는 핏·주 소재, 신발은 발볼. 서로의 항목이 나오지 않는다 | [x] |
| F3 | 관리자 연동 | 관리자가 속성 필터 노출 켜기 | 검색 화면에 새 필터 등장 | **구조적으로 참** — 패널 파일에 속성 이름이 하나도 없다. 그리는 것은 `GET /search/filters` 가 준 것뿐이고, 그 응답은 `AttributeDefinition.isFilterable` 이 정한다 | [x] |
| F4 | URL 동기화 | 필터 3개 적용 후 새로고침·뒤로가기 | 상태 유지, 뒤로가기 정상 | 세 필터가 걸린 주소로 바로 들어가 결과 1건 확인. 패싯 클릭 → `attr.fit=슬림` 이 주소에 뜨고 목록이 좁혀지며, 뒤로가기 한 번에 셋 다 복구된다. **상태가 URL 에만 있어서 복원 코드가 없다** | [x] |
| F5 | 패싯 개수 | 필터 목록 확인 | 개수 표시, 0건 값 비활성 | 오버사이즈 2 · 루즈 0(비활성). 슬림을 고르면 울이 2 → 0 으로 다시 세어진다 — 다른 필터를 적용한 뒤 센 값이다 | [x] |
| F6 | 오타 검색 | 「레트루」 | 결과 표시 + 보정 안내 | 「레트로 러너」가 나오고 안내가 뜬다. **무엇을 무엇으로 바꿨는지는 말하지 않는다** — 응답에 없는 사실이라 지어내지 않고, 확인 가능한 것(입력한 낱말이 결과에 그대로는 없었다)만 말한다 | [x] |
| F7 | 결과 없음 | 존재하지 않는 검색어 | 빈 상태 + 대안 제시 | 빈 상태와 「철자 확인 · 필터 해제」 안내. 검색 전에는 아예 다른 화면(무엇을 찾으세요?)이다 | [x] |
| F8 | 밀도 적용 | 3단계 전환 | 결과 목록 밀도 변화 | 세 단계 모두 `data-density` 와 열 수가 따라간다. **검사에 숫자를 적지 않는다** — `DENSITY_GRID_COLUMNS` 를 읽어 비교한다 | [x] |
| F9 | 모바일 필터 | 360px 에서 필터 열기 | 바텀시트로 열림, 적용 후 닫힘 | 360px 에서 사이드 패널이 아예 마운트되지 않고 버튼 → 다이얼로그. 「결과 보기」로 닫힌다. 768·1440 에서는 반대로 패널만 있고 버튼이 없다 | [x] |

**F1 의 예시를 「원피」에서 「코트」로 바꿨다.** 목 카탈로그가 코트·신발 두 카테고리로 짜여
있어서다(F2·F5 가 그 둘을 요구한다). 검증하는 것은 「후보가 뜨고 키보드로 고를 수 있다」이지
특정 낱말이 아니다.

**TASK-0040 F4 가 이 TASK 에 넘긴 CLS 실측은 하지 않는다.** [품질 게이트 2장](../QUALITY-GATES.md)이
성능을 화면 게이트에서 뺐고(LCP 는 조사 도구다), 측정은 TASK-0097 이 소유한다. 원인 쪽은 그대로
있다 — 이미지 종횡비 고정과 **그리드 모양** 스켈레톤이라 결과가 도착해도 열 수가 바뀌지 않는다.

> **2026-09-05 정정 — F6 의 예시 「코투」는 쓰지 않는다.**
>
> TASK-0039 가 실제 엔진에 대고 쟀고, **어느 오타 임계값에서도 코투는 코트를 찾지 못한다.** 반면
> 「레트루」→레트로, 「러니」→러너, 「발마간」→발마칸은 임계값을 낮추면 전부 찾는다(그쪽 6장 표).
>
> 그래서 기준은 그대로 두고 **예시만 실제로 되는 것으로 바꾼다.** 화면이 검증할 것은 「오타를 내도
> 결과가 나오고, 무엇으로 찾았는지 알려 준다」이지 특정 두 글자가 아니다.

| # | 실측 |

| P2 | axe 8건 통과 — 검색 전 · 결과+패널+칩 · 후보 목록 펼친 상태 · 결과 없음 · 모바일 시트 · 밀도 3단계. **`landmark-no-duplicate-banner` 가 실제로 잡았다**: 페이지 제목을 `<header>` 로 감쌌더니 셸의 헤더와 배너가 둘이 됐다 |

| P6 | 세 단계 모두 결과 그리드에 적용. `gridColumnsClass` 와 대조한다 |
| C1~C3 | 응답 타입은 전부 `@shopping/shared` 의 것이다. `apps/shop` 은 검색 응답의 모양을 한 곳에서도 다시 선언하지 않는다 |
