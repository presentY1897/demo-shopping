## 1. 목적

상품 상세부터 결제까지 안내 금액과 버튼 동작이 실제 구매 흐름과 일치하게 한다.

## 2. 범위

### 포함

- 실제 배송비 정책 안내와 바로 구매 동작
- 카드 조회·장바구니 변경 실패 피드백
- 모바일 최종 금액/결제 버튼 및 밀도 안내 배치

- 장바구니·주문서·주문 상세 썸네일의 URL 전달과 로딩 실패 처리

### 제외

- 완료 화면과 주소록 오류 처리는 TASK-0126/0128 결과를 재사용한다. 새로운 브랜드 디자인은 추가하지 않는다.

## 3. 요구사항

[검토 보고서](../../reviews/2026-09-10-storefront-checkout-review.md)의 해당 발견을 해결하며, 실측 사실과 코드상 위험을 구분한다. 아래 완료 기준의 시나리오를 구현 전 회귀 검증으로 구체화한다.

기존 구매자/판매자 권한·데모 격리·금액 스냅샷·재고/원장 정합성을 유지한다. 변경 계약은 `packages/shared`를 기준으로 API·화면·대역에 함께 반영한다.

## 4. 설계

1. 상세 배송 안내는 판매자 정책을 공유 계약으로 읽는다. 무료배송 조건과 기본 배송비를 설명하고 근거 없는 도착일은 표시하지 않는다. 다중 판매자/조건부 무료배송 계산은 기존 금액 엔진을 사용한다.
2. 바로 구매는 선택 옵션·수량을 실제 주문서 생성으로 연결한다. 기존 장바구니의 미선택 항목은 포함하지 않는다. 현재 준비 중 문구를 제거하고 선택 누락/재고 부족은 해당 컨트롤 가까이에 표시한다.
3. 카드 조회 중·실패·빈 상태를 분리한다. 장바구니 변경 중인 항목과 실패 원인을 표시하고 재시도 가능하게 한다. 서버 확정 전 금액을 확정값처럼 표시하지 않는다.
4. 모바일 하단에 최종 결제금액과 공통 상태 검증을 사용하는 버튼을 배치한다. 본문 여백/키보드/오류 초점으로 가림을 방지한다. 밀도 안내는 주문/결제 화면을 덮지 않게 노출 범위를 제한한다.

5. 썸네일 깨짐 제보의 상품/단계를 특정해 실제 API thumbnailUrl과 이미지 요청 상태·콘텐츠 형식·브라우저 디코딩을 대조한다. null/빈 URL/404/403/손상 이미지의 대체 표시를 제공한다. 결제 전 주문서는 현재 이미지 렌더링이 없으므로 스냅샷 대표 이미지를 표시한다. 과거 주문의 스냅샷 URL이 깨진 경우 현재 상품 이미지로 조용히 덮어쓰지 않고 대체 표시한다. 경로 원인이 확인되면 API 또는 데이터 수정 범위를 먼저 문서에 확정한다. 이미지 용량/변환 최적화는 TASK-0130이 담당한다.

### 구현 상세

바로 구매는 POST /checkouts에 items(variantId, quantity)를 전달한다. itemIds와 정확히 하나만 허용하고 동일 옵션 중복을 거절한다. 장바구니를 변경하지 않으며 재고 예약·가격 계산은 기존 경로를 공유한다. 직접 구매 예약에는 장바구니 정리용 원본 ID를 기록하지 않는다.

### 구현 및 중간 검증

- 실제 판매자 배송 정책을 상세 응답에 추가하고 근거 없는 도착일을 제거했다.
- 직접 구매는 선택 항목만 예약하며 장바구니를 변경하지 않는다. 실 DB 주문서 검사 16개 통과.
- 카드 조회 실패/빈 목록, 장바구니 변경 실패/재시도를 분리했다. 상품·장바구니·주문서 화면 검사 75개 및 결제/주문서 검사 40개 통과.
- 장바구니·주문서·주문 상세는 스냅샷 썸네일을 표시하고 없는 URL/로딩 실패에 대체 표시를 제공한다. 제보 상품의 실제 실패 URL은 미확인 상태다.
- 모바일 CTA는 기존 결제 버튼 하나를 하단에 배치한다. 전체 게이트·브라우저 치수 검사는 통합 단계에 남아 있다.

### 통합 검증 진행

2026-09-10 통합 브랜치 `feature/checkout-review-integration`에서 전체 타입·린트·빌드를 통과했다. 전체 테스트 재확인과 CI가 남아 있어 완료 상태로 변경하지 않았다. 공통 결과는 [구매 흐름 검증 기록](../../reviews/2026-09-10-checkout-latency-measurements.md)을 참조한다.
