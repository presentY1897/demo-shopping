## 1. 목적

운영 두 상품 요청에서 주문서 생성4,962ms·주문 생성5,618ms가 측정됐고 브라우저는 해당 단계에서 응답을 받지 못했다. 반복 카탈로그 조회와 항목별 쓰기를 줄여 구매를 시작할 수 있게 한다.

## 2. 범위

API의 장바구니/주문서 상품 projection, 주문서 예약, 판매자별 주문 생성. API 계약·가격·소유권·스냅샷·원장·예약 TTL·transaction/브라우저 제한은 유지한다. 전역 Prisma join 전략이나 인프라 설정은 바꾸지 않는다.

## 3. 요구사항

현재 권한·상품 활성/구매 상한·쿠폰/요율·대표 이미지 순서·주문서 멱등성 유지. 모든 항목 성공 또는 전체 롤백. 재시도 중 추가 결제 금지.

## 4. 설계

1. 카탈로그 projection을 대상 경로에서만 parameterized SQL의 단일 조인으로 읽는다. 상품/옵션/첫 이미지/판매자/카테고리의 기존 필드와 순서를 보존하고 JSON 날짜는 명시 변환한다. 장바구니 소유자와 항목 id 조건을 SQL에 둔다.
2. 예약은 variant를 id 순으로 잠그고 수량별 조건부 UPDATE와 createManyAndReturn으로 일괄 기록한다. 원본 장바구니 id/시각을 예약 생성 시 함께 저장한다.
3. 주문서 open은 방금 읽은 상품과 생성된 예약으로 응답을 만들고 불필요한 전체 재조회를 피한다. 이후 read는 실제 최신 카탈로그를 읽는다.
4. 판매자 주문/항목/초기 상태 이력을 각각 일괄 기록한다. 주문서 유일성과 요율/금액 스냅샷, 쿠폰 소진 transaction 경계는 그대로다.

## 5. 구현 계획

문서 → 기존 projection/권한 비교 검사 → 읽기·쓰기 왕복 축소 → 실 PostgreSQL 지연/대량/동시성 회귀 → 전체 게이트/PR/배포 → 모바일 두 상품 구매.
