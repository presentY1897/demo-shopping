## 1. 목적

데모 셀러 발급 시 생성되는 초기 상품을 구매자가 검색·브랜드관에서 발견하고 구매할 수 있게 한다. 상품을 직접 수정해야 검색에 나타나는 누락을 해소한다.

## 2. 범위

데모 카탈로그 복제 트랜잭션의 검색 outbox 등록, 신규 계정의 검색 수렴 및 구매 흐름 검증, 유효한 기존 데모 상품의 누락 색인 복구를 포함한다. 데모 격리·만료·가격·재고·결제 규칙, 공용 카탈로그 정책은 유지한다. 이번 작업에서 썸네일 소유권이나 이미지를 변경하지 않는다.

## 3. 조사 근거와 요구사항

- 사용자 제보: 데모 셀러 상품이 구매자 화면에 보이지 않는다.
- 운영 읽기 전용 표본: 최근 유효 데모 셀러의 상품12개는 ACTIVE, 각 재고11~21개이며 판매자 ID로 조회한 공개 검색은 total=0/items=0이다. 표본 상품의 공개 상세 API는 HTTP200이다. 검색 대기 이벤트도 표본12개 모두0건이었다. 계정·상품 식별자는 비공개 조사 기록에 보존한다.
- `apps/api/src/demo/demo-catalog-clone.ts`의 `cloneOne`은 상품·옵션·재고·이미지를 생성하지만 검색 outbox를 등록하지 않는다. `demo-seed.service.ts`의 호출 경로에도 등록이 없다.
- 일반 상품 변경은 `ProductService`가 `SearchOutboxService`로 검색 갱신을 등록한다. 데모 정리는 검색 REMOVE를 등록한다. 검색 소스 자체에 데모 셀러를 일괄 제외하는 필터는 없다.
- 구매자 검색 누락을 확인한 것이며 결제 단계 장애까지 재현한 것은 아니다. 수정 후 구매 흐름은 별도 검증한다.

### 관리자 및 다른 데모 경로 추가 조사

- 관리자 상품 목록/이름 검색은 `GET /products`→`ProductService.list`의 PostgreSQL 직접 조회이며 Meilisearch를 사용하지 않는다. 관리자 판매자/주문 목록도 `AdminSellerService.list`/`AdminCatalogService.searchOrders`의 SQL 조회다. 데모 관리자는 읽기 any, 쓰기 demo로 제한된다. 따라서 이번 색인 누락이 관리자 목록 누락을 직접 일으키는 구조는 아니다. 운영 관리자 세션으로 화면을 재현한 결과는 아직 없다.
- 관리자 상품 숨김/복원은 상품 상태 변경과 같은 트랜잭션에서 각각 REMOVE/UPSERT를 등록한다. 데모 만료 정리도 REMOVE를 등록한다. 이 경로들은 코드상 신규 데모 상품 복제의 누락과 다르며 회귀 검증 대상에 포함한다.
- 별도 미구현: TASK0024의 후속 초기 데이터 계획과 달리 현재 `DemoSeedService.seeders`의 관리자 배열은 승인 대기 입점 신청2건만 생성한다. 개입 대기 클레임/정산 예제는 없다. 판매자 배열도 스토어/복제 상품만 생성하고 계획된 주문/정산 예제는 없다. 이는 검색 누락이 아니라 초기 데이터 생성 누락이며, TASK0139의 검색 수정으로 완료 처리하지 않는다. 후속 TASK로 분리할 범위다.

## 4. 설계

복제 상품과 같은 DB 트랜잭션에서 상품별 UPSERT 이벤트를1개 등록한다. 기존 outbox 계약과 주입된 시각을 사용한다. 검색엔진 요청은 트랜잭션 밖의 기존 소비자가 처리하므로 검색 장애가 데모 발급을 실패시키지 않는다. 복제 실패/롤백 시 이벤트도 남지 않는다. 새 스키마나 공개 API 변경은 필요하지 않다.

기존 복구는 미만료·미삭제 데모 셀러의 미삭제 ACTIVE 상품을 읽기 전용으로 열거하고, 판매자별 공개 검색 결과와 대조한다. 누락만 제한된 배치로 UPSERT 등록한다. 재실행은 현재 검색/대기 상태를 다시 검사한다. 이미 만료·중지된 상품을 강제로 활성화하지 않는다. 운영에서 원본 상품 데이터나 재고·주문은 직접 수정하지 않는다.

## 5. 구현 계획

1. 승인 후 데모 초기 상품의 검색 누락 회귀 검사를 추가한다.
2. 복제 트랜잭션과 outbox 연결을 구현하고 롤백·시각·만료 경로를 검사한다.
3. 실제 검색엔진을 포함한 API 통합 검사로 발급→검색→상세→구매자 장바구니→주문·가상 결제를 검증한다.
4. 전체 CI 통과 후 배포하고 기존 누락을 dry-run→제한된 배치로 복구한다.
5. 운영 노출 및 신규 데모 계정 재현 결과와 TASK 인덱스를 갱신한다.

### 구현 및 로컬 검증 (2026-09-12)

복제 결과 ID를 모아 같은 트랜잭션에서 UPSERT를 일괄 등록했다. 옵션이 없는 상품도 등록하며, 중간 실패 시 상품과 이벤트가 함께 롤백된다. 실제 PostgreSQL과 Meilisearch 통합 검사에서 신규 데모 상품12개 검색 수렴, 별도 구매자 장바구니→주문→가상 카드 결제(PAID)→장바구니 비움, 관리자 상품 목록→숨김→검색 제외→복원→재노출을 확인했다.

로컬 전체 타입 검사·린트·빌드 성공. 전체 테스트9,231개 통과, 기존 skip3개(shared103 / UI961 / API4,389 / mocks472 / admin1,164 / seller867 / shop1,275). API 변경 후 타입 검사와 해당 파일 린트를 다시 확인했다. 운영 배포·누락 복구 및 정확한 PR head의 CI 결과는 배포 후 추가한다. 완료 기준은 운영 검증까지 남겨 둔다.
