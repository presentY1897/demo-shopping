## 1. 목적

깨어 있는 서버의 상품을 즉시 요청하고 작은 카드에 대용량 원본 이미지를 내려보내지 않는다.

## 2. 범위

### 포함

- 홈 health 대기와 상품 조회 분리 및 수면 복구 유지
- 상품 카드용 반응형 이미지 크기·형식·우선순위
- 동일 조건 전후 네트워크/화면 표시 측정

### 제외

- 쓰기 API 병목 분석은 TASK-0131이다. 원본 이미지 삭제나 무조건적인 운영 이미지 일괄 교체는 수행하지 않는다.

## 3. 요구사항

[검토 보고서](../../reviews/2026-09-10-storefront-checkout-review.md)의 해당 발견을 해결하며, 실측 사실과 코드상 위험을 구분한다. 아래 완료 기준의 시나리오를 구현 전 회귀 검증으로 구체화한다.

기존 구매자/판매자 권한·데모 격리·금액 스냅샷·재고/원장 정합성을 유지한다. 변경 계약은 `packages/shared`를 기준으로 API·화면·대역에 함께 반영한다.

## 4. 설계

1. 정상 상품 조회와 health를 병행한다. 검색 미준비/실패는 재시도 가능한 상태로 남기고 정상 빈 목록과 구분한다. TASK-0123의 readiness gate와 관련 D-269를 갱신한다.
2. 현재 CDN/이미지 변환 경로를 확인한 뒤 파생 이미지 또는 앱 이미지 최적화 중 지원되는 방식을 선택한다. srcset/sizes와 최신 형식을 제공하고 fallback을 둔다. 원본을 보존한다.
3. 첫 화면 이미지 우선순위를 지정하고 나머지는 lazy loading한다. 데스크톱·모바일 DPR에 맞는 해상도를 제공한다. 상품 카드의 의미 있는 이미지 대체 텍스트/비율은 유지한다.
4. 기준 상품 3개와 360px DPR 2 조건을 고정해 파일 크기와 렌더링을 비교한다. 네트워크/캐시/브라우저 조건을 보고서에 기록한다.

### 구현 상세

Next 이미지 최적화의 기존 renderImage 슬롯을 사용한다. CDN 호스트의 products 경로만 변환을 허용하며 WebP·반응형 sizes를 사용한다. 외부 과거 URL은 원래 경로를 사용하고 로딩 실패는 카드의 기존 대체 표시로 처리한다. 홈 섹션은 health와 동시에 시작하고 첫 조회가 실패한 경우 health 복구가 재조회를 유발한다. 성공한 상품 목록은 health 재검사로 지우지 않는다.

### 중간 실측

동일 CDN 상품 3개 원본 6,013,377 bytes → 750px WebP 75,928 bytes (98.74% 감소). 각 응답 400KB 미만, HTTP 200. Chromium 360/768/1440px DPR 2에서 이미지 디코딩 성공 및 가로 넘침 없음. 실제 360px 표준 밀도에서는 384px 파생 이미지가 선택된다. 로컬 변환 서버의 최초 요청 시간은 734~1954ms로, 캐시가 찬 요청과 분리해 기록했다. 홈 관련 검사 21개 통과. 전체 게이트와 CI는 통합 단계에 남아 있다.

### 통합 검증 진행

2026-09-10 통합 브랜치 `feature/checkout-review-integration`에서 전체 타입·린트·빌드를 통과했다. 전체 테스트 재확인과 CI가 남아 있어 완료 상태로 변경하지 않았다. 공통 결과는 [구매 흐름 검증 기록](../../reviews/2026-09-10-checkout-latency-measurements.md)을 참조한다.
