## 1. 목적

구매한 상품은 장바구니에서 정리하고 미구매 상품과 다른 탭에서 추가한 상품은 보존한다.

## 2. 범위

### 포함

- 주문서 원본 장바구니 항목·수량 추적
- 서버 결제 완료 후처리의 한 번만 정리
- 장바구니 목록·헤더 건수 갱신

### 제외

- 결제 취소/환불 때 장바구니로 자동 복원하는 기능은 추가하지 않는다.

## 3. 요구사항

[검토 보고서](../../reviews/2026-09-10-storefront-checkout-review.md)의 해당 발견을 해결하며, 실측 사실과 코드상 위험을 구분한다. 아래 완료 기준의 시나리오를 구현 전 회귀 검증으로 구체화한다.

기존 구매자/판매자 권한·데모 격리·금액 스냅샷·재고/원장 정합성을 유지한다. 변경 계약은 `packages/shared`를 기준으로 API·화면·대역에 함께 반영한다.

## 4. 설계

1. 주문서 생성 시 원본 CartItem ID·구매 수량·수정 버전을 스냅샷으로 남긴다. 예약 ID를 CartItem ID로 취급하지 않는다. 장바구니를 거치지 않는 구매는 정리 대상이 없다.
2. 정리 기준은 서버 결제 확정 및 주문 완료다. markPaid의 정상/대사/재처리 경로가 같은 정리 루틴을 사용하고 완료 표식과 변경을 원자적으로 기록한다. 기존 주문 완료의 조기 반환 때문에 정리를 건너뛰지 않게 한다.
3. 같은 항목이 그대로라면 구매한 수량만 제거한다. 삭제 후 재담은 새 ID는 유지한다. 동시 수정은 항목 버전과 잠금으로 판정한다. 증가/감소를 구별할 이력이 없으면 변경된 행은 보수적으로 보존한다. 추가분을 정확히 분리해야 하는 경우 수량 변경 이력을 계약에 포함하고 검증한다.
4. 기존 주문에는 원본 매핑이 없을 수 있으므로 variantId로 추정해 현재 장바구니를 삭제하지 않는다. 스냅샷 없는 과거 주문의 적용 범위를 명시한다.
5. 클라이언트는 확정 결과 후 장바구니와 배지 데이터를 무효화/재조회한다. 화면에서만 삭제하거나 장바구니 전체를 비우지 않는다.

### 소유 경로와 경계

- apps/api/src/orders/ · apps/api/src/cart/ · DB 스냅샷/정리 표식
- packages/shared/src/api/ · apps/shop/src/lib/cart/ · 결제 완료 연결

1. 선행 TASK와 최신 main을 확인하고 예정 브랜치/worktree를 별도로 만든 뒤 `pnpm install --frozen-lockfile`을 수행한다.
2. 기존 재현과 계약을 확인하고 변경 설계를 문서에 먼저 확정한다. 상태/스키마/정책 변경은 결정 문서와 해당 TASK에 반영한다.
3. 아래 시나리오를 검증하고 계약→서버→화면 순으로 필요한 변경을 적용한다.

### 구현 정책 확정

예약 행에 sourceCartItemId와 sourceCartUpdatedAt을 저장하고 예약 수량을 구매 수량으로 사용한다. 결제 확정은 Order.cartCleanedAt 표식과 함께 현재 항목 ID·수량·수정시각이 스냅샷과 같은 경우에만 제거한다. 수정된 행과 삭제 후 재담기는 보존한다. 과거 예약에 원본 매핑이 없으면 추정 삭제하지 않는다. 다른 탭에서 증가한 동일 행은 구매분까지 포함해 보수적으로 보존하는 정책이다.
