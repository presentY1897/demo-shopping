## 1. 목적

배송지를 추가해도 주문서를 유지하고 입력한 배송 요청사항이 실제 주문과 판매자에게 전달되게 한다.

## 2. 범위

### 포함

- 주문서 내 배송지 추가/수정 및 보조 화면 왕복
- TTL 내 주문서·쿠폰·입력 복원
- 배송 요청사항 공유 계약·저장·역할별 조회

### 제외

- 결제 생성 후 확정된 주문의 임의 배송지 변경 기능은 포함하지 않는다.

## 3. 요구사항

[검토 보고서](../../reviews/2026-09-10-storefront-checkout-review.md)의 해당 발견을 해결하며, 실측 사실과 코드상 위험을 구분한다. 아래 완료 기준의 시나리오를 구현 전 회귀 검증으로 구체화한다.

기존 구매자/판매자 권한·데모 격리·금액 스냅샷·재고/원장 정합성을 유지한다. 변경 계약은 `packages/shared`를 기준으로 API·화면·대역에 함께 반영한다.

## 4. 설계

1. 주문서 안의 배송지 편집을 우선 사용한다. 주소록으로 이동하는 경우 복귀 경로와 상태를 유지한다. 컴포넌트 해제/pagehide만으로 예약을 취소하지 않고 명시적 취소와 서버 TTL로 해제한다. 기존 이탈 관련 결정/테스트를 함께 갱신한다.
2. 배송 요청사항은 100자 이내 optional 값으로 공유 스키마→주문 스냅샷→구매자·판매자 주문 상세에 연결한다. 과거 주문의 null은 빈 안내로 처리한다.
3. 배송지·메모 초안은 주문서 단위로 복원한다. 새로고침 보존이 필요한 개인정보는 인증된 서버 초안 저장을 우선하고 로컬 저장소에 주소/메모를 무분별하게 남기지 않는다. 결제 생성 후 변경 제한은 TASK-0126과 일치시킨다.
4. 주소록 로딩·실패·실제 빈 상태를 분리하고 실패에는 재조회를 제공한다. 소유자/데모 격리와 만료 후 정리 규칙을 유지한다.

### 소유 경로와 경계

- packages/shared/src/api/orders.ts · API 주문/배송지 경계 · DB 스냅샷

### 구현 계약 확정

예약 행의 checkoutDraft JSON으로 주소 ID·배송 요청·쿠폰 선택을 인증된 서버에 저장한다. GET/PATCH /checkouts/:id/draft는 유효 예약의 소유자를 확인한다. 클라이언트 저장은 순차 요청으로 처리하고 주소록 이동 전에 flush한다. pagehide에서는 마지막 초안을 keepalive로 저장하되 예약을 해제하지 않는다. 예약은 명시 취소와 TTL로 종료한다. 배송 메모는 주문 스냅샷의 deliveryNote로 저장한다.

### 통합 검증 결과

2026-09-10 통합 코드 `d945f04`에서 GitHub CI typecheck·lint·build·test 네 게이트, E2E, Lighthouse가 모두 COMPLETED/SUCCESS다. 기능 기준은 실 PostgreSQL 회귀와 Chromium 대역 검사 및 실제 스택 E2E를 조합해 검증했다. 공통 결과는 [구매 흐름 검증 기록](../../reviews/2026-09-10-checkout-latency-measurements.md)을 참조한다.

런타임 환경변수 추가는 없다. 상태/계약 변경은 설계 및 D-270~272에 반영했으며 인덱스 두 곳을 갱신했다.

### 운영 재진입 인증 경합 보완 계획

PR #138 운영 검증에서 주문서를 새 문서로 열면 `/checkouts/:id`와 `/coupons`가 인증 부팅 갱신보다 먼저 실행돼401을 받는 것을 확인했다. 장바구니·주소록·배송 초안은 인증 checking이 끝날 때까지 기다리지만 useCheckout의 두 조회 효과에는 같은 조건이 없다. 기존 F2의 TTL 내 새로고침 복구 범위에서 `feature/checkout-session-bootstrap` worktree로 후속 수정한다.

인증 확인이 끝난 후 주문서와 쿠폰 조회를 시작한다. 인증 실패를 무한 로딩으로 만들지 않고 기존 오류 처리를 유지하며, 확인 중 화면을 떠나면 나중에 조회하지 않는다. 지연된 인증 응답을 제어하는 회귀 검사로 부팅 전 조회0건, 부팅 후 두 조회 각1회 및 언마운트 취소를 확인한다. 상태·금액·예약·세션 계약과 전역 인증 클라이언트는 변경하지 않는다.

지연된 인증 부팅 회귀3개는 수정 전 모두 실패하고 수정 후 통과했다. 주문서·쿠폰·결제·토스·접근성 관련95개 검사 통과. 키보드 구매 E2E는 같은 checkout URL에서 문서를 새로고침한 뒤 구매를 끝내도록 보강했다. 최종 통합 게이트와 실제 운영 재진입 결과는 후속 PR 본문에 기록한다.
