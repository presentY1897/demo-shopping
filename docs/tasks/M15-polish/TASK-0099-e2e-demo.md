## 1. 목적

핵심 흐름을 E2E 로 고정하고, **방문자가 5분 안에 이 서비스를 이해하는 데모 시나리오**를 만든다.

## 2. 범위

### 포함
- **Playwright** 도입 (D-057)
- 핵심 시나리오 자동화
  1. 데모 발급 → 검색 → 상세 → 장바구니 → 주문 → 가상카드 결제 → 주문 확인
  2. 판매자 데모 → 상품 등록 → 주문 확인 → 발송 처리
  3. 부분 취소 → 환불 확인 (카드 잔액·재고 복원)
  4. 밀도 3단계 전환
- CI 에 E2E 연결 — **모든 PR 에서 실행** (D-057)
- **가이드 데모 시나리오** — 방문자용 안내 (3역할 동시 체험 동선)
- 데모 안내 페이지 (`/guide` 또는 첫 방문 안내 확장)

### 제외
- 전 화면 E2E 커버리지

## 3. 요구사항

- [ ] 핵심 4개 시나리오가 자동으로 검증된다
- [ ] CI 에서 실행되고 실패 시 머지가 차단된다
- [ ] 방문자가 안내를 따라 3역할을 체험할 수 있다
- [ ] 안내가 실제 동작과 어긋나지 않는다

## 4. 설계

**가이드 시나리오**가 이 TASK 의 진짜 산출물이다. 기능이 아무리 많아도 방문자가 어디서 뭘 봐야 할지 모르면 전달되지 않는다.

```
① 구매자 데모 발급 → 상품 검색 → 밀도 3단계 전환해보기 → 주문
② (새 탭) 판매자 데모 발급 → 방금 들어온 주문 확인 → 발송 처리
③ (구매자 탭) 배송 상태 변화 확인 → 부분 취소 → 카드 잔액 복구 확인
④ (새 탭) 관리자 데모 → 정산·통계 확인
```

세 앱의 세션이 독립이라 **탭 3개로 동시에 열 수 있다**(D-028). 이 구조가 데모 동선의 핵심이다.

E2E 도구는 **Playwright** 다. Cypress 대비 병렬 실행·다중 브라우저·트레이스 뷰어가 낫고 사실상 표준이다.

**시나리오는 4개로 유지한다.** 늘릴수록 깨지기 쉽고 유지비가 커진다. 커버 못 하는 영역은 단위·통합 테스트가 맡는다.
