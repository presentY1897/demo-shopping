## 1. 목적

동일 주문 재시도나 동시 승인에서도 카드 사용액이 한 번만 반영되도록 서버에서 보장한다.

## 2. 범위

### 포함

- 주문 단위 결제 생성의 원자성과 재시도 계약
- 동일 결제 승인과 가상 카드 CHARGE의 멱등성
- 생성 응답 유실 후 기존 결제를 찾는 구매자 복구 계약

### 제외

- 화면 결과 복구는 TASK-0126, 장바구니 정리는 TASK-0127에서 수행한다.

## 3. 요구사항

[검토 보고서](../../reviews/2026-09-10-storefront-checkout-review.md)의 해당 발견을 해결하며, 실측 사실과 코드상 위험을 구분한다. 아래 완료 기준의 시나리오를 구현 전 회귀 검증으로 구체화한다.

기존 구매자/판매자 권한·데모 격리·금액 스냅샷·재고/원장 정합성을 유지한다. 변경 계약은 `packages/shared`를 기준으로 API·화면·대역에 함께 반영한다.

## 4. 설계

1. 먼저 실 PostgreSQL 통합 테스트에서 완료 주문 재결제와 승인 직전 동시 요청을 재현한다. 운영에서 중복 차감을 실험하지 않는다.
2. 기존 결제 확인과 생성은 주문 잠금/원자적 제약으로 묶는다. READY·AUTHORIZED·UNRESOLVED는 진행 중으로 취급하고 기존 시도를 반환하거나 일관된 도메인 응답으로 연결한다. PAID 이후 새 결제는 금지한다. FAILED 이후 정상 재시도는 허용한다. CANCELED·PARTIAL_CANCELED는 주문의 재결제 가능 여부를 별도 판정하고 자동 재결제를 허용하지 않는다.
3. 승인 작업의 실행 소유권을 원자적으로 확보하되 외부 provider 호출 동안 긴 DB 트랜잭션을 유지하지 않는다. 도중 프로세스 종료는 기존 대사/straggler 처리와 함께 복구한다.
4. 가상 카드 CHARGE는 동일 결제 참조에 대해 한 번만 적용한다. 카드/금액이 다른 동일 키는 거부한다. CHARGE에 한정한 유일 제약과 기존 데이터 충돌 사전 조회를 설계하고, 부분 환불 원장의 정상 반복은 유지한다. 기존 중복 원장을 임의 삭제하지 않는다.
5. GET /payments/:id를 재사용한다. ID를 받지 못한 생성 응답 유실에는 주문 단위 조회 또는 멱등 생성 응답을 공유 스키마로 정의한다. 소유권·앱/데모 격리는 유지한다.

### 구현 계약 확정

주문 행 잠금으로 결제 생성을 직렬화한다. 같은 수단의 READY와 기존 AUTHORIZED/PAID는 기존 결제를 반환하며, UNRESOLVED/다른 진행 중 수단/취소 후 재결제는 충돌 응답이다. 승인 실행권은 Payment.authorizationStartedAt의 원자적 갱신으로 잡고, 응답 유실 또는 프로세스 종료로 오래 남은 READY는 대사에서 UNRESOLVED로 전환 후 provider 결과를 확인한다. 가상 카드 CHARGE refId 유일 제약으로 원장 중복을 별도 방어한다. 주문 소유자를 검증하는 최근 결제 조회를 추가한다.

### 현재 검증

실 PostgreSQL에서 TASK-0125 신규 4개 검사 통과. 기존 결제/토스/대사 60개 검사와 가상 카드/straggler 44개 통과(실행별 중복 포함). API 타입 검사 통과. 전체 게이트 및 최종 PR 검증은 통합 단계에서 수행하며 완료 상태로 표시하지 않는다.
