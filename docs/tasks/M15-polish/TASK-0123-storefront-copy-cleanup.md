## 1. 목적

구매자 메인에서 API 운영 정보와 반복되는 기능 설명을 덜어 상품 탐색에 집중하게 한다.
사용자 요청: 메인에 API 연결 상태를 보여줄 필요가 없고, 쓸모없는 설명을 정리한다.

## 2. 범위

### 포함

- 구매자 홈의 API 상세 상태와 임시 안내, 해당 패널 전용 여백 제거.
- 히어로·데모 초대·공통 푸터의 반복 설명 정리.
- 지연·실패 시 필요한 안내와 재시도 동작 유지.
- 관련 메시지·테스트·화면 설계 문서 갱신.

### 제외

- 판매자·관리자 콘솔, 상품 상세·주문·결제 화면의 설명 일괄 변경.
- API 헬스 엔드포인트, 서버 재시도 정책, 데이터 모델 변경.
- 밀도 토글 기능이나 데모 이용 경로 삭제.

## 3. 요구사항

- [x] 정상 상태의 홈에 API 연결 상태·엔드포인트·가동 시간·버전·검색 준비 완료 표를 표시하지 않는다.
- [x] “상품 데이터가 붙기 전까지…” 안내와 패널의 `min-h-64` 예약 공간을 제거한다.
- [x] 히어로의 밀도 사용법과 푸터의 중복 밀도 설명을 제거한다.
- [x] 데모 안내는 한 문장으로 줄이고 계정 시작·닫기 동작을 유지한다.
- [x] 데모 사이트라는 사실과 가상 상품 안내, `/guide` 링크를 유지한다.
- [x] 지연·실패 시에는 짧은 사용자 안내와 복구 수단을 제공한다.
- [x] 홈의 동기 렌더·정적 프리렌더와 상품 섹션의 클라이언트 조회를 유지한다.

## 4. 설계

### 화면 변경안

| 위치 | 현재 | 변경안 |
| --- | --- | --- |
| 홈 하단 | API 상태 표·검색 준비 상태·임시 설명·예약 여백 | 정상 시 표시 없음. 지연·실패 시에만 간결한 안내 |
| 히어로 | “고르는 방식을 고를 수 있는 가게” + 밀도 사용법 | “취향에 맞는 상품을 만나보세요” 제목만 표시 |
| 데모 초대 | 제목과 긴 소개 | 제목 “데모로 쇼핑해 보세요”, 본문 “데모 계정으로 주문까지 체험할 수 있어요.” |
| 푸터 | 데모 소개 + 밀도 설명 두 열 | “가상 브랜드와 상품으로 구성된 데모 사이트로, 실제 판매는 이루어지지 않습니다.”와 가이드·저작권 |

`ApiWakeGate`는 상태 표를 그리는 책임을 제거하되 `useApiWake`의 프리워밍·재시도는 유지한다.
정상·검색 준비 완료 시 `null`, 지연 시 “상품을 준비하고 있어요. 잠시만 기다려 주세요.”,
실패 시 “상품을 불러오지 못했어요.”와 “다시 시도”를 표시한다.
경과 시간·시도 횟수·무료 플랜·검색 색인 같은 기술 설명은 구매자 홈에서 노출하지 않는다.
검색 준비가 늦는 상태도 짧은 준비 안내로 표현하고 기존 재확인 동작을 유지한다.

홈의 게이트가 React context로 검색 준비 여부를 전달한다. 상품 섹션은 준비 완료 후 조회하며, 수동 재시도 후에도 다시 조회한다. 홈 밖의 상품 섹션은 기존대로 즉시 조회한다. 상품 조회 자체 실패에는 섹션 안의 짧은 오류 안내와 재시도 버튼을 제공한다.

상품 조회 실패는 `error` 상태로 구별하며 섹션의 재시도 버튼으로 해당 목록을 다시 조회한다. 빈 목록은 성공 응답의 상품이 0개일 때만 표시한다.

데이터 모델·API 계약·권한 변경은 없다. 메시지는 `apps/shop/src/messages/`에서 관리한다.
구현 소유 경로는 구매자 홈·게이트·홈 구성 요소·푸터·상품 섹션 복구 연결과 해당 테스트다.

### 기존 문서와의 관계

TASK-0101의 동기 렌더 F4와 프리워밍·재시도 정책은 유지한다.
기술 상세 표시 요구는 이 TASK 승인 후 구매자 홈에 한해 대체한다.
구현 전에 `docs/design/pages.md`의 홈 패널 설명과 영향받는 TASK-0101·0044의 표시 요구를 갱신한다.
결정 변경이 필요한 항목은 세션 기록과 `DECISIONS.md`에 반영한다.
