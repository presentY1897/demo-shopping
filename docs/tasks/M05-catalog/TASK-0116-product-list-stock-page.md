> **분할 유래** — TASK-0035(판매자 상품 목록 · 재고 관리)의 화면 절반이다. D-208 에 따라 화면과 API 를
> 나눴고, API 는 TASK-0115 가 맡는다.

## 1. 목적

`apps/seller` 에서 판매자가 자기 상품을 관리하는 화면을 만든다. **재고를 절대값이 아니라 조정량으로
입력하게 하는 UI** 가 이 화면의 핵심이며, 그것이 원장을 우회하지 않는 유일한 방법이다.

## 2. 범위

### 포함
- `/products` — 상품 목록. 상태 · 카테고리 · 재고 필터, 이름 검색, 커서 페이지네이션
- **품절 · 품절 임박 배지** — 기준은 `LOW_STOCK_THRESHOLD` 상수를 읽는다
- **일괄 선택 → 상태 변경**(판매중지 · 재개), 선택 개수 표시
- `/products/[id]/stock` — Variant 별 재고 관리
- **재고 인라인 조정 UI** — 조정량(`+5` · `-2`) 입력 + 사유. **절대값 입력란을 두지 않는다**
- 조정 결과(변동 후 재고)를 즉시 표시하고 **변동 이력**을 함께 보여준다
- **상품 복제** — 확인 후 실행, 결과(`DRAFT`)로 이동
- `sellerProductListResponseSchema` · `stockAdjustResponseSchema` 로 **모킹 데이터를 만들고 `parse` 로 검증**

### 제외 (이번에 하지 않는 것)
- **목록 · 조정 API** → TASK-0115
- **재고 원장 자체** → TASK-0036
- **상품 등록 · 수정 화면** → TASK-0114
- 주문 관리 화면 → M09(TASK-0060)
- 실제 API 호출 테스트 — 백엔드는 모킹한다

## 3. 요구사항

### 기능 요구사항
- [ ] 자기 상품 목록이 상태 · 재고와 함께 보인다
- [ ] 상태 · 카테고리 · 재고로 걸러내고 이름으로 검색할 수 있다
- [ ] 품절 · 품절 임박이 배지로 구분된다
- [ ] 여러 상품을 선택해 한 번에 판매중지 · 재개할 수 있다
- [ ] 재고를 조정량으로 입력하면 변동 후 재고가 즉시 보인다
- [ ] 조정 이력이 같은 화면에서 보인다
- [ ] 상품을 복제할 수 있고 결과가 `DRAFT` 임을 안내받는다
- [ ] 100건에서 페이지를 넘겨도 중복 · 누락이 없다

### 비기능 요구사항
- 콘솔 화면 — 밀도 토글 없음(2단계 고정), 데스크톱 우선
- 표는 좁은 화면에서 가로 스크롤 + 첫 열 고정 (TASK-0016)

## 4. 설계

### 화면 / 컴포넌트

```
apps/seller/app/products/page.tsx           목록 + 필터 + 일괄 액션
apps/seller/app/products/[id]/stock/page.tsx Variant 재고 + 이력
        ├ ProductFilters                    상태 · 카테고리 · 재고 · 검색
        ├ ProductTable                      선택 체크박스 + 배지 (TASK-0016 Table)
        ├ StockAdjustCell                   조정량 입력 + 사유 + 적용
        └ StockLedgerList                   변동 이력
```

`docs/design/pages.md` 2장의 `/products`(상태·재고 필터)와 `/products/[id]/stock`(Variant 별 재고,
변동 이력)이 그대로 이번 범위다.

### 조정량 UI

```
[블랙 / M]  현재 12   [ +5 ] [사유: 입고 ▾] [적용]   →  결과 17
```

**절대값 입력란을 만들지 않는 것이 이 화면의 설계 결정이다.** 입력란을 두면 판매자가 "17"을 적고, 그
사이에 1개가 팔리면 재고가 조용히 틀어진다. TASK-0115 의 API 도 조정량만 받는다.

입력값은 `stockAdjustRequestSchema` 로 검증한다 — 0 은 거부하고, 결과 재고가 음수가 되는 값은 서버가
400 으로 돌려준다(그 판정은 실제 재고를 아는 서버만 할 수 있다).

### 절단면 — `packages/shared` 의 zod 스키마

TASK-0115 가 정의한 스키마를 그대로 쓰고, **모킹 응답도 같은 스키마로 만든다.**

| 스키마 | 이 화면에서의 용도 |
| --- | --- |
| `sellerProductListQuerySchema` | 필터 상태 → 질의 문자열 구성 |
| `sellerProductListItemSchema` · `sellerProductListResponseSchema` | 목록 행 · 커서. **모킹 3페이지 `parse`** |
| `variantStockSchema` | 재고 표의 행 타입 |
| `stockAdjustRequestSchema` | 조정 입력 검증 (0 거부, 정수) |
| `stockAdjustResponseSchema` | 적용 후 `balanceAfter` 표시 |
| `stockLedgerEntrySchema` | 이력 목록 |
| `productBulkStatusRequestSchema` | 일괄 상태 변경 요청 |
| `LOW_STOCK_THRESHOLD` | 품절 임박 배지 기준. **API 필터와 같은 값** |

배지 기준을 화면에 숫자로 적으면 필터와 어긋난다. 상수를 읽는다.

### 역할별 권한

`apps/seller` 진입은 TASK-0023 의 미들웨어가 판정한다. 스토어가 `ACTIVE` 가 아니면 조정 · 일괄 변경 ·
복제 버튼이 비활성이고 사유가 표시된다(목록 조회는 가능). 실제 차단은 서버의 403 이다.
