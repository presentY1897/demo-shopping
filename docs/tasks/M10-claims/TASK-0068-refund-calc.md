## 1. 목적

부분 취소·반품 시 환불액을 정확히 계산하고 결제 프로바이더로 실행한다. **`docs/design/pricing.md` 3장이 이 코드의 명세다.**

## 2. 범위

### 포함
- 환불액 계산 — 항목 저장된 안분액 기반 (재계산하지 않음)
- 배송비 환불 규칙 (전체/부분, 귀책별)
- 프로바이더 부분 취소·환불 호출 (가상 카드 / 토스)
- `Refund` 기록, 누적 취소액 갱신
- 환불 실패 시 재시도·수동 처리 경로
- 여러 번의 부분 환불 누계 검증
- 환불 완료 알림 이벤트 자리

### 제외
- 쿠폰·적립금 복구 (M11 에서 이 로직에 연결)
- 정산 차감 (M12)

## 3. 요구사항

- [ ] 환불액이 주문 시 저장된 안분액을 기반으로 계산된다
- [ ] 부분 환불을 여러 번 해도 누계가 실결제금액을 넘지 않는다
- [ ] 전량 취소 시 환불 합계가 실결제금액과 정확히 일치한다
- [ ] 배송비 규칙이 정확히 적용된다
- [ ] 환불 실패가 감지되고 재시도된다

## 4. 설계

```
환불액 = Σ(항목 상품금액 − 항목 쿠폰안분액 − 항목 적립금안분액) + 배송비 조정
```

**저장된 안분액을 쓰는 이유**: 환불 시점에 재계산하면 그 사이 쿠폰 정책이 바뀌었을 때 값이 달라진다. 주문 시점의 계산 결과가 진실이다.

| 상황 | 배송비 |
| --- | --- |
| 판매자 항목 전체 취소 | 전액 환불 |
| 부분 취소 후 무료배송 조건 미달 | 배송비 재부과 (환불액에서 차감) |
| 판매자 귀책 반품 | 배송비·반품비 판매자 부담 |
| 단순 변심 반품 | 반품 배송비 차감 |

## 5. 구현 계획

1. 환불액 계산 (TASK-0047 역산 함수 활용)
2. 배송비 조정 규칙
3. 프로바이더 환불 호출
4. `Refund` 기록·누계 갱신
5. 실패 재시도·수동 처리
6. 누계 검증 테스트
7. 전량 분할 환불 시나리오 테스트
