# TASK-0069: 재고 복원

| 항목 | 내용 |
| --- | --- |
| 마일스톤 | M10 취소·반품·환불 |
| 상태 | 승인 대기 |

| 선행 작업 | TASK-0066, TASK-0067 |

## 1. 목적

취소·반품된 수량만큼 재고를 되돌린다. 원장(TASK-0036)을 통해서만 처리한다.

## 2. 범위

### 포함
- 취소 완료 시 재고 복원 (원장 CANCEL 기록)
- 반품 검수 합격 시 재고 복원 (원장 RETURN_IN 기록)
- 검수 불합격 시 복원하지 않음
- 판매 종료·삭제된 Variant 의 복원 처리
- 복원 멱등 처리 (같은 클레임으로 두 번 복원 금지)
- 재고 복원 시 판매자 알림 이벤트 자리
- 정합성 검증

## 3. 요구사항

- [ ] 취소·반품 완료 시 재고가 정확히 복원된다
- [ ] 검수 불합격은 복원되지 않는다
- [ ] 같은 클레임으로 두 번 복원되지 않는다
- [ ] 삭제된 Variant 도 처리가 실패하지 않는다
- [ ] 복원 후 원장 합계와 재고가 일치한다

## 4. 설계

```
취소 완료  → adjustStock(type=CANCEL,    +수량, refType=CLAIM, refId=claimId)
반품 합격  → adjustStock(type=RETURN_IN, +수량, refType=CLAIM, refId=claimId)
반품 불합격 → 복원 없음
```

**멱등 처리**: `(refType, refId, variantId)` 조합으로 이미 기록된 원장이 있으면 건너뛴다. 환불 재시도나 이벤트 중복 시 재고가 부풀지 않아야 한다.

**삭제된 Variant**: 데모 판매자가 만료돼 상품이 사라졌을 수 있다(TASK-0025). 이 경우 복원을 건너뛰되 로그를 남긴다. 클레임 처리 자체는 실패하지 않아야 한다.

## 5. 구현 계획

1. 복원 서비스 (원장 경유)
2. 취소·반품 흐름에 연결
3. 멱등 처리
4. 삭제된 Variant 예외 처리
5. 알림 이벤트 자리
6. 정합성 검증 테스트
