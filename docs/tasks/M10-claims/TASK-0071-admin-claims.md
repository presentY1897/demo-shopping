# TASK-0071: 관리자 클레임 개입

| 항목 | 내용 |
| --- | --- |
| 마일스톤 | M10 취소·반품·환불 |
| 상태 | 완료 |
| 작성일 | 2026-09-02 |
| 브랜치 | `feature/admin-claims` |
| 선행 작업 | TASK-0070 |

## 1. 목적

판매자와 구매자 사이 분쟁에 관리자가 개입하는 경로를 만든다. 확정 후 하자 반품도 여기서 처리한다.

## 2. 범위

### 포함
- 전체 클레임 조회 (판매자·구매자·상태·기간 필터)
- 구매자 이의 제기 접수
- 관리자 강제 처리 — 판매자 거절을 뒤집어 승인, 귀책 재판정
- 구매확정 후 하자 반품 처리
- 처리 지연 클레임 모니터링
- 개입 이력 기록 (누가·왜)
- 데모 관리자는 **데모 계정이 만든 클레임만** 강제 처리 가능 (D-058, 스코프 `demo`)

### 제외
- 자동 분쟁 판정

## 3. 요구사항

- [x] 관리자가 모든 클레임을 조회할 수 있다
- [x] 구매자가 거절에 이의를 제기할 수 있다
- [x] 관리자가 판매자 결정을 뒤집을 수 있다
- [x] 확정 후 하자 반품을 처리할 수 있다
- [x] 데모 관리자는 **데모 계정이 만든 클레임만** 강제 처리할 수 있다
- [x] 모든 개입이 이력으로 남는다

## 4. 설계

```
판매자 거절 → 구매자 이의 제기 → 관리자 검토 → 강제 승인 / 거절 유지
CONFIRMED 주문 + 하자 신고 → 관리자만 반품 승인 가능
```

**개입 이력을 반드시 남기는 이유**: 관리자가 판매자 결정을 뒤집는 건 판매자의 돈이 나가는 일이다. 근거가 남지 않으면 분쟁이 관리자로 옮겨갈 뿐이다.

**데모 관리자 제한**(D-058): 강제 처리는 다른 사용자의 데이터와 금액을 바꾸는 작업이다. `DEMO_ADMIN` 은 스코프 `demo` 이므로 **데모 계정이 만든 클레임만** 처리할 수 있고, 실계정 클레임은 조회만 된다.

**「비활성 + 사유 툴팁」은 하지 않는다** (4.3). 응답 어디에도 「데모 계정이 만든 건인가」가 없어 줄마다 잠그는 것은 **추측**이고, 그 추측은 두 방향 중 하나로 틀린다.

데모 구매자가 반품을 신청하면 데모 관리자가 실제로 개입해볼 수 있다. 이게 없으면 관리자 데모가 조회만 되는 껍데기가 된다.

### 4.0 `CONFIRMED → RETURNED` 를 **관리자에게만** 연다 (2026-09-06 승인)

「구매확정 후 하자 반품 처리」(2장)를 하려면 화살표가 필요하다. `CONFIRMED` 는 지금 전이표의
**종착 상태**이고, TASK-0064 는 그 사실 하나로 「확정 후 반품 제한」을 구현했다.

셋 중 **관리자에게만 여는 것**을 골랐다(사용자 승인).

| 안 | 왜 아닌가 |
| --- | --- |
| 클레임만 진행하고 주문은 `CONFIRMED` 로 둔다 | 환불·재고는 돌아가는데 주문은 확정이다 — **두 표가 다른 말을 한다** |
| 정산 이후의 별도 보상 절차로 미룬다 | M12 로 밀리고, 그동안 하자 반품이 아예 불가능하다 |

**「확정은 끝」이 「확정은 구매자에게 끝」으로 약해진다.** 그 성질이 사던 것이 셋이었다 —
정산의 방아쇠(「배송완료 직후 정산하면 반품 시 회수할 방법이 없다」), 코드가 기대는 종착,
사람에게 한 약속. 앞의 둘은 관리자에게만 열어 지키고, 세 번째는 **문구를 고쳐** 지켰다
(TASK-0064 4.6).

`SELLER` 를 넣지 않는다 — 판매자가 확정된 주문을 되돌리는 것은 클레임 절차 밖이다.

**M12 로 넘어가는 것 하나**: 지급이 나간 뒤 반품이 오면 **회수**해야 한다. 지금은 정산이
없어 문제가 아니지만, 이 화살표가 그때의 근거가 된다.

### 4.2 거절을 뒤집는 방법 — **새 클레임을 관리자가 대신 낸다**

`CANCEL_REJECTED`·`RETURN_REJECTED` 에서 나가는 화살표를 **열지 않았다.** 이유 셋.

- **거절은 잡고 있던 수량을 이미 돌려준다.** 되돌리는 화살표는 「다시 잡는」 역연산을 요구하고,
  그 사이 구매자가 재신청했으면 **잡을 수 없다**
- `ClaimRefund` 의 기본키가 `claimId` 인 근거가 **「돌아오는 화살표가 없어 한 클레임은 평생 한 번만
  그 자리에 선다」**이다. 역화살표는 고리를 만들어 그 근거를 깬다
- `RETURN_REJECTED` 는 **두 자리**(신청 거절 · 검수 불합격)에서 온다. 역화살표 하나는 그 둘을
  구분하지 못해, 검수에서 떨어진 반품에 **회수 운송장이 다시 난다**

저장소가 이미 「거절된 것은 다시 신청할 수 있다」를 규칙으로 갖고 있으므로, 뒤집기는 **그
재신청의 주체가 관리자인 경우**다. 라우트 하나가 강제 처리와 확정 후 하자 반품을 함께 덮고,
원본은 거절된 채 남으며 `overturnsClaimId` 가 둘을 잇는다.

**그 덕분에 상태 기계에 새 상태도 새 화살표도 없다.**

### 4.3 「처리 불가」를 **미리 잠그지 않는다**

6.1 F5 가 「403 + UI 비활성」을, 4장이 「비활성 + 사유 툴팁」을 적었다. **둘 다 하지 않았다.**

응답 어디에도 **「데모 계정이 만든 건인가」가 없다.** 그래서 줄마다 잠그는 것은 추측이고, 그
추측은 **실계정 건을 처리 가능한 것처럼 보이거나 데모 건을 잠그는** 두 방향 중 하나로 틀린다.

대신 누르기 전에는 **계정에 대해 참인 문장**만 세우고(「전체를 보되 데모가 만든 것만 바꿉니다」),
서버가 403 을 답하면 그 답을 **이 건에 대한 문장**으로 바꾸고 버튼을 치운다. F5 가 재려는 것
— 처리 못 함 + **이유가 보임** — 을 추측 없이 채운다.

**못 누르는 이유가 넷이고 버튼 하나로는 말할 수 없다**는 것도 이 선택의 근거다: 아직 결론이
안 남 · 이미 환불됨 · 권한 없음 · 데모 제한. 넷이 서로 다른 문장이다.

### 4.4 도중에 발견한 것 — **`DELIVERED → RETURNED` 를 지나는 코드가 없었다**

반품이 완료되고 환불까지 나가도 **주문은 `DELIVERED` 로 남았다.** 아무것도 실패하지 않았다.

확정 쪽만 고쳤다면 4.0 이 거부한 「두 표가 다른 말을 한다」가 **배송완료 쪽에 그대로** 남았을
것이다. 그래서 **모든 반품**이 결론에서 몫을 닫는다.

### 4.5 하자로 뒤집을 때 **사진이 빠져 실 서버에서 400 이었다**

화면이 `photoKeys: []` 를 보냈고 서버는 하자·오배송에 사진을 필수로 요구한다. **어떤 검사도
잡지 못한 이유가 세 겹이었다** — 대역의 뒤집기 갈래에 사진 판정이 없었고, 서버 검사의 뒤집기는
취소만 뒤집었으며, **반품을 뒤집는 화면 검사 자체가 없었다.**

고치는 **순서**가 중요했다: 대역을 먼저 충실하게 만들고, 그다음 화면을 고친다. 반대로 하면
화면이 왜 고쳐졌는지 아무 검사도 증명하지 못한다. (대역만 고쳤을 때 빨개진 기존 검사가
**하나도 없었다**는 것이 세 번째 겹의 증거다.)

### 4.1 데모 관리자 조항이 2장과 3장에서 달랐다 — **2장이 맞다** (2026-09-06)

3장은 「데모 관리자는 **강제 처리를 할 수 없다**」였고 2장은 「**데모 계정이 만든 클레임만**
강제 처리 가능」이었다. **D-058 이 뒤쪽 편이다.**

> **데모끼리는 서로 처리할 수 있다.** `demo` 스코프의 목적은 실계정 보호이지 데모 간
> 격리가 아니다. 판매자 데모가 입점 신청하면 관리자 데모가 승인할 수 있다. **이게 없으면
> 관리자 콘솔이 조회만 되는 껍데기가 된다.**

같은 결정이 데모 관리자 발급 시 **「개입 대기 클레임 1건」**을 함께 만들어 준다고 적었다 —
처리할 수 없다면 그 씨앗은 아무 뜻이 없다.

**그래서 새로 만들 권한이 없다.** `claim.handle` 은 `ADMIN_OPERATOR` 에 `any` 로 있고
`DEMO_ADMIN` 은 그것을 `demo` 로 좁혀 물려받는다(`role-permissions.ts` 의 `narrowToDemo`).
이 TASK 가 할 일은 **강제 처리 라우트가 `assertResourceAccess` 를 지나게 해서 그 스코프가
실제로 물게** 하는 것이다 — 지나지 않으면 스코프는 표에만 있는 값이 된다.

읽기는 `any` 로 남는다(`erd.md` 1장 — 「시드·실계정 데이터는 조회만」). 데모 관리자는 **플랫폼
전체를 보되 데모가 만든 것만 바꾼다.**
