## 1. 목적

배송 후 반품을 구현한다. 수거·검수 단계를 포함해 실제 서비스와 같은 흐름을 만든다.

## 2. 범위

### 포함
- 구매자 반품 신청 (항목·수량·사유·사진 첨부)
- 귀책 구분 — 단순 변심 / 상품 하자 / 오배송
- 판매자 승인·거절
- 수거 처리 (가상 회수 운송장)
- 입고 검수 — 합격/불합격
- 검수 합격 시 환불 + 재고 복원
- 검수 불합격 시 반송 처리
- 귀책에 따른 반품 배송비 부담 결정
- 반품 진행 상태 조회

### 제외
- 교환 (구현하지 않음)
- 환불 계산 로직 (TASK-0068)

## 3. 요구사항

- [ ] 항목·수량을 골라 반품할 수 있다
- [ ] 하자 반품은 사진을 첨부할 수 있다
- [ ] 수거·검수 단계가 상태로 추적된다
- [ ] 검수 합격 시에만 환불된다
- [ ] 귀책에 따라 반품 배송비 부담자가 달라진다

## 4. 설계

```
반품신청 → 판매자 승인 → 수거중(가상) → 입고검수 ─합격→ 환불 + 재고 복원
                    └거절                        └불합격→ 반송
```

| 귀책 | 반품 배송비 | 원 배송비 |
| --- | --- | --- |
| 단순 변심 | 구매자 부담 (환불액에서 차감) | 환불 안 함 |
| 상품 하자 | 판매자 부담 | 환불 |
| 오배송 | 판매자 부담 | 환불 |

**검수 단계를 두는 이유**: 반품 상품이 실제로 도착하고 상태가 확인돼야 환불한다. 이게 없으면 물건을 안 보내고 환불받는 게 가능해진다. 실제 커머스가 검수를 거치는 이유이기도 하다.

**교환을 만들지 않는 이유**(D-027): 회수+재배송+재고 2회 이동+차액 정산이 엮여 상태 머신이 두 배가 된다. 반품 후 재구매로 안내한다.

## 5. 구현 계획

1. 반품 신청 API + 화면 (사진 첨부 포함)
2. 판매자 승인·거절
3. 수거 처리 (가상 회수 운송장)
4. 검수 처리 (합격·불합격)
5. 귀책별 배송비 계산
6. 환불·재고 복원 연동
7. 반송 처리
8. 상태 조회 화면
