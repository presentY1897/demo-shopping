## 1. 목적

쿠폰 정책과 발급 데이터를 만든다. **부담 주체(플랫폼/판매자)를 스키마에 못박는다.**

## 2. 범위

### 포함
- `Coupon` — 발행 주체, 이름, 할인 유형(정액/정률), 값, 최대 할인액, 최소 주문금액, 적용 범위(전체/카테고리/상품/판매자), 유효기간, 발급 수량 제한
- `UserCoupon` — 발급된 쿠폰, 상태(발급/사용/만료), 사용 주문
- 발행 API (관리자·판매자 권한 분기)
- 발급 API (사용자에게 지급, 중복 발급 제한)
- 만료 처리 배치
- 발급 수량 소진 처리
- 쿠폰 코드 방식 지원 (코드 입력으로 발급)

### 제외
- 화면 (TASK-0073, 0074)
- 적용·검증 (TASK-0075)

## 3. 요구사항

- [ ] 플랫폼 쿠폰과 판매자 쿠폰이 구분되어 저장된다
- [ ] 판매자는 자기 상품에만 적용되는 쿠폰만 발행할 수 있다
- [ ] 발급 수량이 소진되면 더 발급되지 않는다
- [ ] 같은 쿠폰을 중복 발급받을 수 없다
- [ ] 만료된 쿠폰이 자동으로 상태 전환된다

## 4. 설계

| 필드 | 설명 |
| --- | --- |
| `issuerType` | PLATFORM / SELLER — **정산의 근거** |
| `sellerId` | 판매자 쿠폰일 때만 |
| `discountType` | FIXED(정액) / PERCENT(정률) |
| `maxDiscountAmount` | 정률일 때 상한 |
| `minOrderAmount` | 최소 주문금액 |
| `scopeType` / `scopeIds` | ALL / CATEGORY / PRODUCT / SELLER |

**판매자 쿠폰의 범위를 자기 상품으로 강제**한다. 판매자가 전체 쿠폰을 발행하면 다른 판매자 매출에 자기 부담이 들어간다.

## 5. 구현 계획

1. 스키마·인덱스·마이그레이션
2. 발행 API (권한별 검증)
3. 발급 API (수량·중복 제한)
4. 쿠폰 코드 발급
5. 만료 배치
6. 단위 테스트
