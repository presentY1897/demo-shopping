## 1. 목적

적립금을 원장으로 관리한다. **구매확정 시 지급**하고 주문 시 사용한다. (D-029)

## 2. 범위

### 포함
- `PointAccount` / `PointTransaction` — 적립·사용·복구·만료·조정, `balanceAfter`
- 구매확정 이벤트 수신 → 적립 (M09 TASK-0064 연동)
- 주문 시 사용 (계산 엔진 `discounts` 에 전달)
- 적립률 설정 (관리자)
- 유효기간·만료 배치
- 잔액 조회, 사용 가능 상한 규칙
- 음수 잔액 방지
- 동시성 제어

### 제외
- 화면 (TASK-0077)
- 환불 시 복구 (TASK-0078)

## 3. 요구사항

- [ ] 구매확정 시 적립금이 지급된다
- [ ] 배송완료만으로는 지급되지 않는다
- [ ] 주문에 적립금을 사용할 수 있다
- [ ] 잔액보다 많이 사용할 수 없다
- [ ] 원장 합계와 잔액이 항상 일치한다

## 4. 설계

```
구매확정 → earn(userId, 실결제금액 × 적립률, refType='ORDER', refId)
주문     → use(userId, amount, refType='ORDER', refId)
```

**구매확정 시 지급하는 이유**: 배송완료 직후 주면 반품 시 이미 쓴 적립금을 회수할 수 없다. 확정은 "문제없음"의 표시다.

**적립금은 플랫폼 부담**이다. 판매자 정산에서 차감하지 않는다.

사용 상한: 주문 금액의 일정 비율(예: 전액 가능하되 최소 결제금액 100원 이상). 규칙은 설정값으로 둔다.

## 5. 구현 계획

1. 스키마·인덱스·마이그레이션
2. 원장 서비스 (적립·사용·복구, 트랜잭션·멱등)
3. 구매확정 이벤트 연동
4. 계산 엔진 연결
5. 적립률·상한 설정
6. 만료 배치
7. 동시성·정합성 테스트
