## 1. 목적

관리자가 정산서를 검토하고 승인·지급 처리하는 화면을 만든다. 실제 이체는 없고 상태만 바뀐다.

## 2. 범위

### 포함
- 정산서 목록 (회차·판매자·상태 필터)
- 정산서 상세 (항목별 내역, 계산 근거)
- 승인 / 보류 / 지급완료 처리
- 보류 사유 입력 (분쟁·이상 건)
- 일괄 승인
- 정산 총액 요약 (회차별 지급 예정 총액)
- 정산서 내보내기 (CSV)
- 데모 관리자는 지급 확정 불가 (Q-11)

### 제외
- 실제 이체·은행 연동

## 3. 요구사항

- [ ] 정산서 항목별 계산 근거를 볼 수 있다
- [ ] 승인 후 지급완료로 전환할 수 있다
- [ ] 보류 시 사유를 입력해야 한다
- [ ] 지급완료된 정산서는 수정할 수 없다
- [ ] 데모 관리자는 지급 확정을 할 수 없다

## 4. 설계

정산서 상세에 **계산 근거를 항목별로 펼쳐 보여준다.**

```
판매액          1,890,000
− 수수료 (10%)   -189,000
− 판매자 쿠폰     -30,000
− 반품 차감      -120,000
────────────────────────
지급액          1,551,000
```

각 줄을 클릭하면 해당하는 주문 목록으로 내려갈 수 있게 한다. 판매자가 이의를 제기했을 때 근거를 즉시 확인할 수 있어야 한다.

**지급완료 후 수정 불가**: 돈이 나간 것으로 간주되므로 잠근다. 오류가 있으면 다음 회차에서 조정한다.

## 5. 구현 계획

1. 목록 화면
2. 상세 화면 + 계산 근거 펼침
3. 승인·보류·지급 처리
4. 일괄 승인
5. 총액 요약
6. CSV 내보내기
7. 데모 제한
