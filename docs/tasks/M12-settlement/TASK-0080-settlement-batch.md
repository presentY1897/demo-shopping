# TASK-0080: 정산서 생성 배치

## 1. 목적

구매확정된 주문을 주간 단위로 집계해 정산서를 만든다. **이 프로젝트 도메인 설계의 최종 수렴점**이다.

## 2. 범위

### 포함
- `Settlement` / `SettlementItem` 스키마
- 주간 정산서 생성 배치 (구매확정 건 집계)
- 정산 금액 계산 — 판매액, 수수료, 판매자 부담 쿠폰, 반품 차감
- **플랫폼 쿠폰·적립금은 차감하지 않음** 검증
- 정산 기간 이후 발생한 반품의 차감 처리 (다음 회차 조정)
- 중복 집계 방지 (같은 SellerOrder 가 두 정산서에 들어가지 않음)
- 정산서 재생성 (승인 전에만)
- 배치 실행 이력·헬스체크

### 제외
- 승인·지급 화면 (TASK-0081)
- 판매자 화면 (TASK-0082)

## 3. 요구사항

- [ ] 구매확정된 건만 집계된다
- [ ] 판매자 쿠폰만 차감되고 플랫폼 쿠폰·적립금은 차감되지 않는다
- [ ] 같은 주문이 두 번 정산되지 않는다
- [ ] 정산 후 발생한 반품이 다음 회차에서 조정된다
- [ ] 금액이 `pricing.md` 5장과 정확히 일치한다

## 4. 설계

```
매주 월요일:
  ① 지난주 구매확정된 SellerOrder 조회 (아직 정산되지 않은 것)
  ② 건별 정산액 계산
       판매액 − (판매액 × 요율) − 판매자쿠폰안분액
  ③ 이전 회차 이후 발생한 반품 차감분 반영
  ④ Settlement + SettlementItem 생성 (상태 PENDING)
```

**차감 조정이 필요한 이유**: 구매확정 후 관리자 개입으로 반품될 수 있다(TASK-0071). 이미 정산된 건이면 다음 회차에서 차감한다. 지급 전이면 해당 정산서에서 제외한다.

**플랫폼 부담을 차감하지 않는 것이 이 계산의 핵심**이다. 판매자는 정가 기준으로 정산받고, 플랫폼 쿠폰·적립금 비용은 플랫폼이 진다. (D-029)

## 5. 구현 계획

1. 스키마·인덱스·마이그레이션
2. 집계 쿼리 (미정산 확정 건)
3. 정산액 계산 (부담 주체 구분)
4. 반품 차감 조정
5. 중복 방지 (정산 여부 표시)
6. 배치 스케줄러 + 수동 실행
7. 검증 테스트 (합계 대조)
