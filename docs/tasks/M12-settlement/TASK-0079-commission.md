## 1. 목적

수수료율을 데이터로 관리한다. 카테고리 기본율과 판매자 개별율을 두고, **판매자 개별율이 우선**한다.

## 2. 범위

### 포함
- `CommissionRate` — 카테고리 / 판매자 / 우선순위 / 요율 / 적용 기간
- 요율 결정 로직 (판매자 개별율 > 카테고리 기본율 > 전역 기본율)
- 관리자 수수료 설정 화면 (카테고리별·판매자별)
- 요율 변경 이력
- **적용 시점 규칙** — 주문 시점의 요율을 사용
- 요율 시뮬레이션 (변경 시 영향 금액 미리보기)

### 제외
- 정산 계산 (TASK-0080)

## 3. 요구사항

- [ ] 카테고리별로 다른 요율을 설정할 수 있다
- [ ] 특정 판매자에게 개별 요율을 줄 수 있다
- [ ] 판매자 개별율이 카테고리 기본율보다 우선한다
- [ ] 요율을 바꿔도 과거 주문의 정산 금액이 변하지 않는다
- [ ] 요율 변경 이력이 남는다

## 4. 설계

```
적용 요율 = 판매자 개별율 ?? 카테고리 요율 ?? 전역 기본율
```

**주문 시점 요율을 사용하는 이유**: 정산은 나중에 계산되지만 계약은 판매 시점에 성립한다. 요율을 올린 뒤 과거 판매분까지 소급하면 판매자와 분쟁이 된다. `SellerOrder` 에 적용 요율을 함께 저장한다.

## 5. 구현 계획

1. 스키마·마이그레이션
2. 요율 결정 로직
3. 주문 생성 시 요율 스냅샷 저장
4. 관리자 설정 화면
5. 변경 이력
6. 시뮬레이션
