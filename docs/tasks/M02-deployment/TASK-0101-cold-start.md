## 1. 목적

무료·저가 플랜의 백엔드는 무활동 시 잠든다. **첫 방문자가 30초 넘게 빈 화면을 보는 상황**을 막는다. 데모 URL 을 채용 담당자에게 보내는 프로젝트라 첫인상이 여기서 결정된다.

## 2. 범위

### 포함
- 프론트 진입 시 백그라운드 **프리워밍** — 페이지 렌더와 동시에 `/health` 호출로 API 를 깨움
- API 응답이 지연될 때의 UX — 스켈레톤 + "서버를 준비하는 중입니다" 안내 (3초 이후 노출)
- 타임아웃·재시도 정책 (지수 백오프, 최대 3회)
- 깨어남 감지 후 자동 재요청
- 외부 cron 핑 (선택) — 데모 공개 기간에만 사용
- 콜드 스타트 소요 시간 측정·기록
- 플랫폼별 sleep 정책 문서화

### 제외
- 유료 플랜 전환 (비용 결정은 별도)

## 3. 요구사항

- [ ] 서버가 자고 있어도 화면이 깨지지 않는다
- [ ] 3초 이상 걸리면 이유를 알려주는 안내가 뜬다
- [ ] 서버가 깨어나면 자동으로 다시 요청한다
- [ ] 프리워밍이 페이지 렌더를 막지 않는다
- [ ] 콜드 스타트 소요 시간을 측정할 수 있다

## 4. 설계

```
페이지 진입 → (병렬) 렌더 시작 + /health 프리워밍
              ↓
       0~3초: 평소 스켈레톤
       3초~ : "서버를 준비하는 중입니다. 잠시만 기다려주세요" + 진행 표시
       응답  : 자동 재요청 → 정상 렌더
       실패  : 재시도 버튼 + 상태 안내
```

**프리워밍은 렌더를 막지 않는다.** `await` 로 기다리면 오히려 첫 화면이 늦어진다. 정적 부분은 즉시 그리고 데이터 영역만 대기 상태로 둔다.

| 플랫폼 | sleep 정책 | 콜드 스타트 |
| --- | --- | --- |
| Render 무료 | 15분 무활동 시 sleep | 30초~1분 |
| Railway | sleep 없음 (크레딧 소진 시 중단) | 해당 없음 |

플랫폼 선택(TASK-0009)에 따라 이 TASK 의 비중이 달라진다. Render 라면 필수, Railway 라면 배포·재시작 순간에만 해당한다.

**외부 cron 핑**은 sleep 을 회피하는 흔한 방법이지만 무료 플랜의 취지에 어긋난다. 포트폴리오 공개 기간에만 쓰고, 사용 여부를 README 에 밝힌다.

## 5. 구현 계획

1. 플랫폼 sleep 정책 확인·측정
2. 프리워밍 훅 (진입 시 비차단 호출)
3. 지연 안내 UI (3초 임계)
4. 재시도·백오프
5. 깨어남 감지 후 자동 재요청
6. 콜드 스타트 시간 측정·기록
7. cron 핑 검토·적용
