## 1. 목적

`main` 머지 → 자동 배포를 연결하고, 환경별 변수 관리 규칙을 정한다. 배포가 수동 작업으로 남지 않게 한다.

## 2. 범위

### 포함
- `main` 머지 시 API·웹 3개 자동 배포
- PR 프리뷰 배포 (웹 3개), 프리뷰 전용 환경변수
- CI 통과를 배포 전제 조건으로 연결
- 환경변수 관리 규칙 문서화 (로컬 / 프리뷰 / 운영)
- 배포 실패 시 롤백 절차
- 배포 후 스모크 테스트 (헬스체크 + 각 앱 루트 200)
- **실패 알림** — CI 실패·배포 실패·스모크 테스트 실패를 즉시 인지할 수 있는 경로

### 제외
- 스테이징 환경 별도 구성 (프리뷰로 갈음)
- 무중단 배포·블루그린

## 3. 요구사항

- [ ] `main` 머지 후 사람 개입 없이 배포가 끝난다
- [ ] CI 실패 시 배포되지 않는다
- [ ] PR 마다 프리뷰 URL 이 생성된다
- [ ] 프리뷰는 운영 DB 를 건드리지 않는다
- [ ] 배포 후 스모크 테스트가 자동 실행된다
- [ ] CI·배포·스모크 테스트가 실패하면 **1분 내 알림을 받는다**

## 4. 설계

```
PR 생성 → CI (typecheck·lint·build·test) → 프리뷰 배포 (웹 3개, 프리뷰 API 연결)
main 머지 → CI → API 배포 (migrate deploy) → 웹 3개 배포 → 스모크 테스트
```

### 실패 알림

| 경로 | 특징 |
| --- | --- |
| **Discord webhook** (채택) | 무료, 설정 5분, 모바일 푸시 즉시. 실패 로그 링크를 함께 보냄 |
| GitHub 기본 이메일 | 이미 켜져 있으나 메일함에 묻힌다 |
| GitHub 모바일 앱 | 푸시는 오지만 알림 세분화가 어렵다 |

Discord webhook 을 GitHub Actions 실패 시에만 호출한다. 성공까지 알리면 알림 피로로 결국 무시하게 된다.

| 환경 | API | DB | 용도 |
| --- | --- | --- | --- |
| local | localhost:4000 | docker | 개발 |
| preview | 프리뷰 API | **프리뷰 전용 DB** | PR 검증 |
| production | `api.<도메인>` | 운영 DB | 운영 |

**프리뷰가 운영 DB 를 쓰면 안 된다.** 마이그레이션 실험이 운영 데이터를 깨뜨린다.

## 5. 구현 계획

1. Vercel Git 연동 및 프리뷰 환경변수 분리
2. 백엔드 자동 배포 트리거 연결
3. CI → 배포 순서 강제
4. 프리뷰 전용 DB 준비
5. 스모크 테스트 워크플로 작성
6. 롤백 절차 문서화 및 1회 실습
