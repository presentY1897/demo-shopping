## 1. 목적

API, PostgreSQL, Meilisearch 를 배포 환경에 올리고 서로 연결한다. 로컬 docker-compose 와 동일한 구성을 클라우드에서 재현한다.

## 2. 범위

### 포함
- Railway(또는 Render) 프로젝트 생성, 서비스 3개 구성
- 모노레포에서 `apps/api` 만 빌드하도록 설정
- 서비스 간 내부 네트워킹 (API → DB, API → Meilisearch)
- 배포 환경 변수 등록
- 마이그레이션 실행 전략 (`migrate deploy`)
- `api.<도메인>` 연결
- 배포 환경 헬스체크 확인

### 제외
- 자동 배포 트리거 (TASK-0012)
- 로그·모니터링 (TASK-0013)
- 백업 정책

## 3. 요구사항

- [ ] `https://api.<도메인>/api/v1/health` 가 `db: ok`, `search: ok` 를 반환한다
- [ ] Meilisearch 가 마스터 키로 보호되고 외부에서 직접 접근되지 않는다
- [ ] 마이그레이션이 배포 시 자동 적용된다
- [ ] DB 커넥션 풀 크기가 플랜 제한에 맞게 설정된다

## 4. 설계

| 서비스 | 플랫폼 | 노출 |
| --- | --- | --- |
| api | Railway | `api.<도메인>` (public) |
| postgres | Railway | **내부 전용** |
| meilisearch | Railway | **내부 전용** (볼륨 필요) |

```
빌드: pnpm install --frozen-lockfile && pnpm --filter @shopping/api build
시작: pnpm --filter @shopping/api prisma migrate deploy && node dist/main.js
```

DB 와 검색엔진은 외부에 노출하지 않는다. 관리가 필요하면 플랫폼 콘솔이나 터널을 쓴다.

## 5. 구현 계획

1. 플랫폼 프로젝트 생성, 모노레포 빌드 설정
2. PostgreSQL 서비스 추가, 커넥션 문자열 확보
3. Meilisearch 서비스 추가 (이미지 + 볼륨 + 마스터 키)
4. API 서비스 환경변수 등록
5. 마이그레이션 실행 전략 적용
6. `api.<도메인>` 도메인 연결
7. 헬스체크 검증
