## 1. 목적

소유자가 Render 대시보드에서 서비스를 유료로 올렸는데 **무료로 되돌아가 있었다.** `render.yaml` 이 두 서비스를
`plan: free` 로 적고 있고, 이 저장소의 Render 는 Blueprint 가 기준이라 **sync 가 대시보드의 값을 파일의 값으로
덮는다.** 2026-09-17 의 PR #154 가 `render.yaml` 의 주석 두 줄을 고쳤고, 그 push 가 자동 sync 를 일으킨 것으로
보인다 — 45분 뒤부터 검색 엔진이 잠들고 인덱스를 잃기 시작했다(TASK-0143 의 출발점).

끝나면 — 유료 플랜이 **파일에 적혀 있어** 되돌아가지 않고, 검색 엔진은 잠들지 않으며 재기동해도 인덱스가 남는다.

## 2. 범위

### 포함

- `render.yaml`: `shopping-api` · `shopping-search` 를 `plan: starter` 로, `shopping-search` 에 1GB 디스크(`/meili_data`)
- 무료 플랜을 **현재 상태**로 적고 있는 문서의 정정 — `DECISIONS.md` 10장, `docs/development.md` 배포 절,
  `OWNER-CHECKLIST.md`, `pages.md`, `performance.md`, 루트 `README.md`
- 「`render.yaml` 을 건드리면 sync 가 대시보드의 수동 변경을 덮는다」를 함정으로 기록
- 결정 D-283

### 제외 (이번에 하지 않는 것)

- 콜드 스타트 대응(TASK-0101 · 0118)과 검색 대기(TASK-0143)의 **코드는 그대로 둔다.** 유료 인스턴스도 배포 ·
  재기동 때는 잠깐 닿지 않고, 그 코드는 그 구간에서 같은 일을 한다. 예산 · 문구를 유료에 맞춰 줄이는 것은 별도 판단이다
- `preDeployCommand` 로 마이그레이션 옮기기 — 유료에서 가능해졌지만 배포 절차를 바꾸는 별도 작업이다
- 검색 엔진을 Private Service 로 바꾸기 — 주소 · 환경변수 · 헬스 경로가 함께 바뀐다
- TASK-0143 의 500 → 503(A), TASK-0144 의 목록 폴백 — 이 전환의 결과를 보고 다시 판단한다

## 4. 설계

### 4.1 `render.yaml`

```yaml
  - type: web
    name: shopping-api
    plan: starter          # free → starter

  - type: web
    name: shopping-search
    plan: starter          # free → starter
    disk:
      name: meili-data
      mountPath: /meili_data
      sizeGB: 1
```

- **`starter`** 는 Render 공식 스키마(`render.com/schema/render.yaml.json`)의 `serverPlan` 에 있다. 같은 사양의 새
  표기는 `0.5c-512mb`(0.5 CPU · 512MB)이고 둘 다 유효하다. 대시보드가 Starter 로 보여 주므로 그 이름을 쓴다
- **`/meili_data`** 는 공식 Meilisearch 이미지의 작업 디렉터리다. 데이터(`data.ms`) · 덤프 · 스냅샷이 전부 그 아래에
  생기므로 환경변수를 더하지 않고 마운트 위치만 맞춘다
- 1GB — 인덱스는 상품 866개에 수 MB 다. 디스크는 늘릴 수만 있고 줄일 수 없으므로 작게 시작한다

### 4.2 디스크가 바꾸는 것

| | 지금까지 | 디스크를 붙인 뒤 |
| --- | --- | --- |
| 엔진 재기동 | 인덱스가 비고 자동 재색인(수십 초, 그동안 `search: degraded`) | 인덱스가 남는다. `ensurePopulated()` 는 「비어 있지 않다」를 보고 아무것도 하지 않는다 |
| 엔진 배포 | 무중단 | **디스크가 붙은 서비스는 무중단 배포가 안 된다** — 새 인스턴스가 디스크를 넘겨받는 동안 잠깐 닿지 않는다. 이미지 버전이 고정돼 있어 배포는 드물다 |
| 이미지 버전 올리기 | 그냥 올린다 | **옛 버전이 쓴 `data.ms` 를 새 버전이 못 읽을 수 있다.** 인덱스는 PostgreSQL 의 사본이므로 옮기지 않고 버린다 — Shell 에서 `data.ms` 를 지우고 Restart 하거나, `MEILI_DB_PATH` 를 버전별 경로로 준다(후자는 아직 해 보지 않았다). `disk.name` 을 바꾸는 것은 새 디스크가 아니라 이름 변경이라 소용없다. `development.md` 배포 절에 적는다 |
| 문서 모양(`DOCUMENT_VERSION`) 변경 | 재기동이 곧 재색인 | 이미 `ensureCurrentShape()` 가 모양이 다르면 다시 짓는다 — 디스크와 무관하게 동작한다 |

### 4.3 Blueprint 와 대시보드

`render.yaml` 머리말이 이미 「sync 할 때 대시보드에서 바꾼 값을 이 파일 값으로 덮는다」고 적고 있다. 빠져 있던 것은
**언제 sync 가 도는가**다: 연결된 브랜치에 `render.yaml` 변경이 push 되면 **자동으로** 돈다. 주석만 고쳐도 그렇다.
그래서 —

- 대시보드에서 플랜 · 환경변수(`sync: false` 가 아닌 것)를 손으로 바꾸지 않는다. 바꿨다면 같은 날 파일에 옮긴다
- `render.yaml` 을 고치는 PR 은 **주석만 고치더라도** 「sync 가 돈다」를 PR 본문에 적는다
