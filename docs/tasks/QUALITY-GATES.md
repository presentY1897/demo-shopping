# 공통 품질 게이트

모든 TASK 에 적용된다. 각 TASK 문서의 `6.2 품질 게이트` 는 이 문서를 참조하고 **예외만** 명시한다.

## 1. 코드 게이트 (전 TASK 필수)

| # | 기준 | 측정 방법 | 목표 |
| --- | --- | --- | --- |
| Q1 | 타입 검사 | `pnpm typecheck` | error 0 |
| Q2 | 린트 | `pnpm lint` | error 0, warning 0 |
| Q3 | 빌드 | `pnpm build` | 전 앱 성공 |
| Q4 | 테스트 | `pnpm test` | 전부 통과 |
| Q5 | 신규·변경 코드 커버리지 | 커버리지 리포트 | **80% 이상** (M05 부터 적용, 그 전은 면제) |
| Q6 | CI | PR 에서 GitHub Actions | 전 job green |
| Q7 | 커밋 규칙 | commitlint | Conventional Commits 위반 0 |

## 2. 화면 게이트 (사용자 대상 화면이 있는 TASK)

| # | 기준 | 측정 방법 | 목표 |
| --- | --- | --- | --- |
| P1 | LCP | Lighthouse 모바일 | 2.5s 이하 |
| P2 | 접근성 | Lighthouse Accessibility | 90점 이상 |
| P3 | 반응형 | 360 / 768 / 1440px | 레이아웃 깨짐 0건 |
| P4 | 키보드 조작 | Tab 순회 | 모든 인터랙티브 요소 도달·조작 가능 |
| P5 | 상태 표현 | 로딩 / 빈 상태 / 에러 | 세 상태 모두 구현 |
| P6 | 밀도 3단계 | `apps/shop` 화면에서 단계 전환 | 3단계 모두 레이아웃 정상 |

## 3. API 게이트 (엔드포인트를 추가하는 TASK)

| # | 기준 | 측정 방법 | 목표 |
| --- | --- | --- | --- |
| A1 | 응답 시간 | 로컬 부하 측정 p95 | 300ms 이하 |
| A2 | 입력 검증 | 잘못된 입력 요청 | 400 + 통일된 에러 포맷 |
| A3 | 권한 | 권한 없는 역할로 호출 | 403 |
| A4 | 인증 | 토큰 없이 호출 | 401 |
| A5 | N+1 쿼리 | 쿼리 로그 확인 | 목록 조회 시 N+1 없음 |

## 4. 데이터 게이트 (스키마를 변경하는 TASK)

| # | 기준 | 측정 방법 | 목표 |
| --- | --- | --- | --- |
| S1 | 마이그레이션 | 새 DB 에 `migrate deploy` | 성공 |
| S2 | 롤백 가능성 | 마이그레이션 검토 | 데이터 손실 없는 변경이거나, 손실 시 문서에 명시 |
| S3 | 인덱스 | 조회 조건에 인덱스 존재 | 목록·검색 조건 전부 |
| S4 | 금액 컬럼 | 타입 확인 | 정수(원 단위), 부동소수 없음 |

## 5. 문서 게이트 (전 TASK 필수)

| # | 기준 |
| --- | --- |
| D1 | TASK 상태를 `완료` 로 변경하고 `docs/tasks/README.md` + 마일스톤 `README.md` 갱신 |
| D2 | 설계가 바뀌었으면 `docs/design/` 갱신 |
| D3 | 결정이 바뀌었으면 세션 파일에 기록하고 `DECISIONS.md` 갱신 |
| D4 | 새 환경변수가 있으면 `.env.example` 갱신 |
| D5 | 새로 도입한 라이브러리 버전을 TASK 문서에 기록 |

## 예외 표기 방법

TASK 문서에서 이렇게 쓴다.

```markdown
### 6.2 품질 게이트
[공통 품질 게이트](../QUALITY-GATES.md) 적용. 예외:
- **Q5 면제** — 스캐폴딩이라 의미 있는 테스트 대상이 없음
- **2장 화면 게이트 해당 없음** — 사용자 대상 화면 없음
```
