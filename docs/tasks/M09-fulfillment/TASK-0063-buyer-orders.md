## 1. 목적

구매자 주문 내역을 만든다. **판매자별 묶음이 사용자에게 어떻게 보이는지**가 이 화면에서 결정된다.

## 2. 범위

### 포함
- 주문 목록 (기간·상태 필터, 커서 페이지네이션)
- 주문 상세 — **판매자별 묶음으로 표시**, 묶음별 배송 상태와 추적
- 결제 정보 (수단·금액·할인 내역)
- 상태별 액션 (배송조회·구매확정·취소·반품 진입점)
- 주문 상태 타임라인
- 취소·반품 신청 진입점 (M10 연결)
- 리뷰 작성 진입점 (M13 연결)
- 재구매 (장바구니에 다시 담기)

### 제외
- 클레임 신청 실제 동작 (M10)
- 리뷰 작성 (M13)

## 3. 요구사항

- [ ] 한 주문에 여러 판매자가 있으면 묶음으로 나뉘어 보인다
- [ ] 묶음마다 배송 상태가 다를 수 있고 각각 표시된다
- [ ] 상태별로 가능한 액션만 노출된다
- [ ] 삭제된 상품도 주문 상세에서 정상 표시된다

## 4. 설계

```
주문번호 20260902-A3F9        결제 189,000원 (가상카드)
├ 브랜드A     배송완료   [배송조회] [구매확정] [반품신청]
│   울 코트 / 블랙 / M   1개
└ 브랜드B     상품준비중  [취소신청]
    니트 / 그레이 / L     2개
```

**묶음별로 상태와 액션이 다르다.** 이게 마켓플레이스 구조가 사용자에게 드러나는 지점이다. 하나의 주문번호 아래 서로 다른 진행 상황이 보인다.

액션 버튼은 판매자 화면과 마찬가지로 **가능 액션 API 기반**으로 렌더한다.

### 4.1 아직 없는 화면으로 가는 길은 **문장**이다

취소·반품·리뷰는 M10·M13 의 것이라 갈 곳이 없다. 셋 다 하지 않았다.

| 하지 않은 것 | 왜 |
| --- | --- |
| 없는 라우트로 가는 링크 | 404 로 보낸다. 탭 순회에 **목적지 없는 정지**가 생긴다 |
| `disabled` 버튼 | 탭으로 닿지 못하므로 **왜 못 누르는지 알 수 없다** |
| `aria-disabled` 버튼 | 닿기는 하지만 눌러도 아무 일이 없다. 사유를 툴팁에 숨기게 된다 |

남는 것은 **무엇이 언제 열리는지 말하는 한 문단**이다(`role="note"`). 이 저장소가 껍데기
라우트를 없애며 정한 규칙 그대로다(`pages.md`).

**그 날을 찾는 법도 함께 두었다.** 쓰는 자리에 TASK 번호를 주석으로 적어, 그 TASK 를 여는
사람이 `grep -rn 'TASK-0066' apps/shop` 으로 닿는다 — 전에 이것을 안 해서 화면이 생긴 뒤에도
링크가 옛 주소를 가리킨 적이 있다.

### 4.2 기본 필터가 **아무것도 좁히지 않는다**

「최근 3개월」이 기본값으로 더 쓸모 있어 보이지만, 그것은 **사람이 고르지 않은 조건**이라
빈 화면의 뜻을 거짓으로 만든다 — 3개월보다 오래된 주문만 있는 계정이 **「아직 주문한
상품이 없습니다」**를 본다. 그 문장은 틀렸고, 그 사람 눈에는 자기 주문이 사라진 것으로 보인다.

성능이 이유가 될 수도 없다. 목록은 커서 페이지네이션이라 **첫 장의 크기는 기간과 무관**하다.
좁히는 것은 사람이 고를 때만 일어나고, 그때는 빈 결과에 「조건을 지우세요」라고 말할 수 있다 —
빈 상태 둘을 가르는 기준이 바로 「사람이 좁혔는가」이므로, 기본값이 좁히면 그 기준이 무너진다.

### 4.3 상태 필터의 뜻은 「**하나라도** 그 상태인 주문」

주문 하나에 묶음이 여럿이고 상태가 서로 다르다. 「배송중」 탭을 누르는 사람이 찾는 것은
**지금 오고 있는 물건**이고, 배송완료·배송중·준비중이 섞인 주문이 바로 그 주문이다.

「전부 그 상태」로 치면 그 주문은 어느 탭에도 안 걸리고 「전체」에서만 보이는데, 하필 그
자리가 이 저장소의 2단 구조(D-023)가 사용자에게 드러나는 곳이다.

### 4.4 타임라인은 **아는 것과 모르는 것을 구분한다**

칸은 사다리(다섯)이고 시각만 이력에서 온다. 이력을 그대로 늘어놓지 않은 이유가 둘이다 —
`null → PAYMENT_PENDING` 은 사다리에 없는 줄이고, **아직 오지 않은 칸도 보여야** 한다.

이력이 그 칸을 모르면 배송의 시각으로 메우고, 그것도 없으면 **「시각 정보 없음」으로 남긴다.**
주문 접수 시각을 결제완료 칸에 놓지 않는다 — 그럴듯하지만 다른 사실이다.
