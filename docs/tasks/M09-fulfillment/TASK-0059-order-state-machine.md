## 1. 목적

`SellerOrder` 상태 전이를 코드로 구현한다. 정의되지 않은 전이가 불가능하게 만든다.

## 2. 범위

### 포함
- 상태 전이 정의 테이블 (from → to, 허용 주체, 조건)
- 전이 실행 서비스 — 검증 → 상태 변경 → 이력 기록 → 후속 처리 트리거
- `OrderStatusHistory` 기록 (이전/이후·사유·주체)
- 권한별 허용 전이 (구매자·판매자·관리자·시스템)
- 부분 취소된 항목이 있을 때의 상태 판단
- 상태 변경 시 알림 이벤트 발행 자리 (M13 연결)
- 상태별 가능 액션 조회 API (화면이 버튼을 결정하는 근거)

### 제외
- 화면 (TASK-0060, 0063)
- 클레임 상태 (M10)

## 3. 요구사항

- [x] 정의되지 않은 전이는 거부된다 — **상태를 쓰는 길이 하나뿐**이라서 성립한다 (4.1)
- [x] 권한 없는 주체의 전이는 거부된다 — 주체는 **서버가 정한다**, 요청이 주장하지 못한다
- [x] 모든 전이가 이력으로 남는다 — 주체 컬럼에 **기본값이 없다** (4.2)
- [x] 화면이 "지금 가능한 액션"을 API 로 알 수 있다 — 조건이 모자란 것도 목록에 남는다
- [x] 동시에 같은 전이가 두 번 요청돼도 한 번만 반영된다 — 이력도 한 줄이다

## 4. 설계

상태 정의는 `docs/design/state-machines.md` 1장을 따른다.

```ts
transition(sellerOrderId, to, { actor, reason })
  ① 현재 상태 조회 (행 잠금)
  ② 전이 정의 확인 — 없으면 거부
  ③ 주체 권한 확인
  ④ 조건 확인 (예: SHIPPED 는 운송장 필요)
  ⑤ 상태 변경 + 이력 기록 (한 트랜잭션)
  ⑥ 후속 이벤트 발행
```

| 전이 | 허용 주체 |
| --- | --- |
| PAID → PREPARING | 판매자, 시스템(자동) |
| PREPARING → SHIPPED | 판매자 |
| SHIPPED → DELIVERED | 시스템(시뮬레이터), 판매자 |
| DELIVERED → CONFIRMED | 구매자, 시스템(D+7) |
| * → CANCELED | 클레임 처리 결과 (M10) |

### 4.1 이미 상태를 쓰던 두 곳을 **같은 문으로** 보낸다

「정의되지 않은 전이는 불가능하다」는 **상태를 쓰는 길이 하나일 때만** 참이다. 착수
시점에 `SellerOrder.status` 를 직접 쓰는 곳이 둘 있었다 — 결제 확정(`markPaid`)과
예약 만료 스케줄러. 그 둘이 새 문을 지나지 않으면 상태 머신은 **새 코드에만 적용되는
규칙**이 된다.

문제는 둘 다 **이미 자기 트랜잭션 안**이고 PostgreSQL 에 중첩 트랜잭션이 없다는
것이다. 그래서 문을 `applyWithin(tx, …)` 로 만들어 **남의 트랜잭션을 받게** 했다.
새로 열었다면 결제 확정과 상태 전이가 다른 트랜잭션이 되어 「재고는 팔렸는데 주문은
결제 대기」가 가능해진다.

대가는 문장 수다 — 한 몫에 `UPDATE` 하나이던 것이 셋(잠금·갱신·이력)이 된다. 한
주문의 판매자 수가 데모에서 한 자리이고 만료 청소가 한 주기 200몫이라, 치를 만한
값으로 봤다.

### 4.2 주체 컬럼에 **기본값을 두지 않는다**

`OrderStatusHistory.actor` 에 `SYSTEM` 을 기본값으로 두면 편하지만, 그러면 **주체를
말하지 않은 이력이 `SYSTEM` 으로 기록된다.** 그것은 「모른다」가 아니라 **거짓**이고,
이력의 값은 분쟁에서 유일한 근거라는 점 하나에 있다. 기본값이 없으면 새 호출자는
주체를 정해야만 컴파일된다.

### 4.3 `ADMIN` 주체는 지금 `ADMIN_SUPER` 만 닿는다 (M10 으로 넘김)

표의 `ADMIN` 은 `order.write` 를 요구하는데 `ADMIN_OPERATOR` 에게는 그 권한이 없다.
지금 그것을 넓히면 `docs/design/permission-matrix.md` 가 바뀌고, **이 전이들이 실제로
열리는 자리는 클레임 처리(M10)**다 — 취소·반품은 신청이 승인된 결과이지 관리자가
임의로 누르는 것이 아니다. 그래서 권한은 M10 이 `claim.handle` 로 여는 것이 맞고,
여기서는 표에 주체만 적어 둔다.

**F8 의 검사가 자기 구멍을 적어 둔다.** 매트릭스는 기대값을 표에서 파생시키므로 **표
자체가 틀린 경우**를 못 잡는다. 그 몫을 1절이 메운다 — `docs/design/state-machines.md`
1장의 mermaid 를 실제로 파싱해 화살표 집합과 표를 **양방향** 비교한다. 기대값을 손으로
옮겨 적으면 그 사본이 세 번째 진실이 되고, 정작 「문서와 코드가 갈라졌다」를 아무도 못
잡는다. 파서가 조용히 빈 집합을 돌려주는 세 가지 길(장을 못 찾음·mermaid 를 못 찾음·
화살표 0개)은 전부 실패로 막았다.
