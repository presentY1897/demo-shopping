## 1. 목적

판매자가 자기 주문을 처리하는 화면을 만든다. 발송 처리가 여기서 이뤄진다.

## 2. 범위

### 포함
- 주문 목록 (상태 탭, 기간·검색 필터, 커서 페이지네이션)
- 주문 상세 (항목·수령인·금액·상태 이력)
- 상태별 액션 버튼 (가능 액션 API 기반)
- 발송 처리 (운송장 발급 → SHIPPED)
- 일괄 발송 처리
- 신규 주문·처리 대기 건수 뱃지
- 주문서 인쇄용 뷰
- 엑셀 내보내기
- **모바일 전용 레이아웃** — 목록은 카드 변환, 상세·발송 처리는 폰에서 완결 가능

### 제외
- 배송 추적 (TASK-0061)
- 클레임 처리 (M10)

## 3. 요구사항

- [ ] 자기 SellerOrder 만 보인다
- [ ] 상태별로 필터링된다
- [ ] 발송 처리하면 구매자 화면에 즉시 반영된다
- [ ] 여러 건을 한 번에 발송 처리할 수 있다
- [ ] 수령인 개인정보가 필요 이상 노출되지 않는다
- [ ] 360px 에서 주문 확인부터 발송 처리까지 완결할 수 있다

## 4. 설계

상태 탭: `결제완료` / `상품준비중` / `배송중` / `배송완료` / `취소·반품` / `전체`

액션 버튼은 **가능 액션 API 응답으로 렌더**한다. 화면에서 상태별 분기를 하드코딩하면 상태 머신과 어긋난다.

**개인정보**: 목록에는 이름 일부만(홍*동), 상세에서 전체를 보여준다. 데모 계정 데이터라도 습관을 들인다.

## 5. 구현 계획

1. 목록 API (필터·검색·커서)
2. 목록 화면 + 상태 탭
3. 상세 화면 + 이력
4. 액션 버튼 (가능 액션 기반)
5. 발송 처리 + 일괄 처리
6. 뱃지·인쇄·내보내기
