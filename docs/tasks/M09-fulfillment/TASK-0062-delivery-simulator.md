## 1. 목적

발송된 배송이 시간에 따라 자동으로 진행되게 한다. **데모에서 실제 배송을 기다릴 수 없으므로**, 압축된 시간으로 전 과정을 보여준다.

## 2. 범위

### 포함
- 배송 진행 스케줄러 (집화 → 간선 → 배송출발 → 배송완료)
- 데모 모드 시간 압축 (예: 단계당 2분 → 전체 8분)
- 일반 모드 시간 (단계당 수 시간)
- 배송완료 시 SellerOrder DELIVERED 전환
- 수동 진행 API — 데모에서 즉시 다음 단계로 (관리자·판매자)
- 배송 지연·분실 시나리오 재현 (선택)
- 헬스체크에 스케줄러 상태 노출

### 제외
- 실제 택배사 연동

## 3. 요구사항

- [x] 발송 후 시간이 지나면 자동으로 배송 단계가 진행된다
- [x] 데모 모드에서는 몇 분 내 배송완료까지 도달한다
- [x] 배송완료 시 주문 상태가 전환된다
- [x] 수동으로 다음 단계로 넘길 수 있다
- [x] 스케줄러 상태를 헬스체크로 알 수 있다

## 4. 설계

```
SHIPPED → (2분) 집화 → (2분) 간선상차 → (2분) 배송출발 → (2분) 배송완료 → DELIVERED
```

**시간 압축이 데모 품질을 좌우한다.** 실제 배송 시간을 쓰면 방문자가 배송완료를 볼 수 없고, 구매확정·정산·반품까지의 흐름을 전혀 시연하지 못한다. 데모 계정 수명이 24시간이므로 그 안에 전 과정이 끝나야 한다.

**수동 진행 버튼**을 함께 둔다. 시연할 때 2분도 기다리기 어렵다.

### 4.1 시간 축은 **새 환경변수 하나**다 — `FULFILLMENT_PACE`

있는 축 셋을 먼저 보고 전부 기각했다.

| 후보 | 왜 안 되나 |
| --- | --- |
| 데모 계정 판정 | 속도 하나를 정하려고 `Shipment→SellerOrder→Order→User` 를 타야 하고, 무엇보다 **한 배송의 속도가 「누가 샀는가」에 따라 갈린다** — 같은 콘솔의 두 주문이 다른 속도로 움직인다. `demo-containment.spec.ts` 가 그 플래그를 부를 수 있는 파일을 다섯으로 못 박아 둔 것도 이 검토를 강제하려는 장치이고, 검토의 답은 아니오였다 |
| `PAYMENT_SIMULATION` | 그것이 켜는 것은 **실패**(승인 지연·거절)라 기본값이 `off` 다. 매달면 「결제가 가끔 실패해야 배송이 빨라진다」가 된다 |
| `nodeEnv` | 배포된 데모가 곧 `production` 이라 방향이 반대다 |

**이름이 `DELIVERY_PACE` 가 아닌 이유**: 이 축이 배송 진행과 **구매확정**(TASK-0064) 둘 다를
지배한다. 한쪽만 가리키는 이름이면 나머지 하나는 남의 스위치를 빌려 쓰는 것처럼 보이고,
그것이 위에서 `PAYMENT_SIMULATION` 재사용을 거부한 이유와 같다.

**기본값이 `demo` 인 방향이 핵심이다.** 잘못 두었을 때 **조용한 쪽이 `realistic`** 이기
때문이다 — 배포된 데모에서 배송완료가 오지 않고 구매확정·정산·반품이 전부 닫히는데
**아무 요청도 실패하지 않는다.** 그래서 `render.yaml` 에 아무것도 넣지 않았다(기본값이
곧 배포값). `PAYMENT_SIMULATION` 과 방향이 반대인 것이 우연이 아니다.

### 4.2 수동 진행이 **이력을 거짓으로 만들지 않는다**

시연할 때 2분도 기다리기 어려워 「다음 단계로」가 필요하다. 그런데 TASK-0061 은 사건
기록에 라우트를 열지 않았다 — 주체가 `SYSTEM` 인 자리라 사람이 그 사실을 주장하면 이력이
거짓이 된다. 셋으로 풀었다.

1. **종류를 요청이 고르지 못한다** — 본문이 없고, 다음 단계는 배치와 **같은 순수 함수**가 정한다. 본문을 받는 순간 그 문이 열린다.
2. **출처가 사람이다** — `SELLER` 로 적고 추적 줄과 지점이 그렇게 말한다. 배치가 남기는 `CARRIER`/`SYSTEM` 는 사람이 누른 줄에 붙지 않는다.
3. **상태 머신을 비켜 가지 않는다** — 전이표가 `SHIPPED → DELIVERED` 를 `SYSTEM`·판매자에게만 열어 두므로 **관리자는 마지막 한 걸음에서 거절된다**(중간 단계는 민다). 시연 장치가 「누가 배송을 끝낼 수 있는가」를 조용히 넓히지 않는다.

`occurredAt` 도 갈린다 — 배치는 **때가 된 시각**(오차 누적 방지), 수동은 **지금**(누른 뒤
다음 자동 단계까지 온전히 한 단계가 남는다).

## 5. 구현 계획
