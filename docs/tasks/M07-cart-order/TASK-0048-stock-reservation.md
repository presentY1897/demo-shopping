## 1. 목적

주문서 진입 시 재고를 선점하고 결제 승인 시 확정하는 구조를 만든다. **오버셀을 구조적으로 막는다.** (D-026)

## 2. 범위

### 포함
- `StockReservation` — variant, 주문, 수량, 만료시각, 상태(HELD/CONFIRMED/RELEASED)
- 예약 생성 (조건부 갱신으로 동시성 제어)
- 예약 확정 → 재고 원장 차감 (TASK-0036 서비스 경유)
- 예약 해제 (결제 실패·이탈)
- 가용재고 계산 (`stock` − 유효 HELD 합계)
- 상품 조회에 가용재고 반영
- 예약 연장 (주문서에 오래 머무는 경우)

### 제외
- 만료 스케줄러 (TASK-0051)
- 주문 생성 (TASK-0049)

## 3. 요구사항

- [ ] 재고 1개에 두 명이 동시에 주문서 진입하면 한 명만 성공한다
- [ ] 예약된 재고는 다른 사람의 가용재고에서 빠진다
- [ ] 결제 승인 시 예약이 실제 차감으로 확정된다
- [ ] 결제 실패 시 예약이 해제된다
- [ ] 확정된 예약은 다시 확정되지 않는다 (멱등)

## 4. 설계

```
주문서 진입 → reserve(variantId, qty, orderId, ttl=15분)
              UPDATE variant SET reserved = reserved + qty
              WHERE id = ? AND stock - reserved >= qty      ← 실패하면 품절

결제 승인 → confirm(reservationId)
            원장에 SALE 기록 + stock 차감 + reserved 감소 + 상태 CONFIRMED

실패·이탈·만료 → release(reservationId)
                 reserved 감소 + 상태 RELEASED
```

`reserved` 를 Variant 에 캐시 컬럼으로 둔다. 매번 예약 테이블을 합산하면 조회가 무거워진다. 정합성은 점검 배치로 확인한다.

## 5. 구현 계획

1. 스키마·인덱스·마이그레이션
2. 예약 생성 (조건부 갱신)
3. 확정 (원장 연동, 멱등)
4. 해제
5. 가용재고 계산·조회 반영
6. 연장
7. 동시성 테스트
