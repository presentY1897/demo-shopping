## 1. 목적

주문 금액 계산과 **항목별 할인 안분**을 구현한다. `docs/design/pricing.md` 가 이 코드의 명세다.

## 2. 범위

### 포함
- 계산 순서 구현: 상품금액 → 상품할인 → (할인 목록) → 배송비 → 실결제금액
- **할인을 목록으로 받는 인터페이스** — 쿠폰·적립금이 아직 없어도 구조는 완성
- 항목별 안분 (원 단위 잔여를 최대 항목에 몰아 합계 보존)
- 판매자별 소계 계산
- 배송비 규칙 (판매자별, 무료배송 조건)
- 계산 결과 스냅샷 구조 (주문 저장용)
- 역산 함수 — 항목 일부 취소 시 환불액 계산 (M10 에서 사용)

### 제외
- 쿠폰·적립금 실제 규칙 (M11)
- 주문 저장 (TASK-0049)

## 3. 요구사항

- [ ] 안분액의 합이 전체 할인액과 1원도 어긋나지 않는다
- [ ] 판매자별 소계의 합이 전체와 일치한다
- [ ] 금액이 전부 정수로 계산된다
- [ ] 할인 목록이 비어도 정상 동작한다
- [ ] 항목 일부에 대한 환불액을 계산할 수 있다

## 4. 설계

```ts
calculateOrder({
  items: [{ variantId, unitPrice, quantity, sellerId }],
  discounts: [{ type, amount, scope: 'ORDER'|'SELLER'|'ITEM', targetId?, bearer }],
  shippingPolicies: [...]
}) => {
  totalProductAmount, totalDiscountAmount, totalShippingFee, paidAmount,
  sellerOrders: [{ sellerId, productAmount, discountAmount, shippingFee }],
  items: [{ ..., itemDiscountAmount, couponDiscountAmount, pointDiscountAmount }]
}
```

**`discounts` 를 목록으로 받는 이유**(D-036): 지금은 빈 배열이지만 M11 에서 쿠폰·적립금이 이 목록에 들어온다. 계산기를 다시 만들지 않는다.

안분 규칙과 잔여 처리는 `docs/design/pricing.md` 2장을 그대로 따른다.

## 5. 구현 계획

1. 계산 입출력 타입 정의 (`packages/shared`)
2. 상품금액·소계 계산
3. 안분 알고리즘 + 잔여 처리
4. 배송비 규칙
5. 환불액 역산 함수
6. **속성 기반 테스트** — 무작위 입력에서 합계 보존 검증

## 6. 완료 기준

### 6.1 기능

| # | 기준 | 측정 방법 | 목표 | 충족 |

[공통 품질 게이트](../QUALITY-GATES.md) 적용. 예외:
