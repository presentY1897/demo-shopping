## 1. 목적

Google OAuth 2.0 인가 코드 흐름을 구현한다. 이메일/비밀번호 가입은 만들지 않으므로 이것이 유일한 실계정 로그인 경로다.

## 2. 범위

### 포함
- Google Cloud 프로젝트·OAuth 클라이언트 생성
- 인가 코드 흐름 (authorize → callback → 토큰 교환 → 프로필 조회)
- 최초 로그인 시 `User` 생성, 재로그인 시 조회
- `state` 파라미터로 CSRF 방지
- 리다이렉트 URI 를 앱별로 등록 (shop/seller/admin)
- 로그인 실패·취소 처리

### 제외
- JWT 발급 (TASK-0022)
- 로그인 화면 UI (TASK-0023)
- 다른 소셜 로그인

## 3. 요구사항

- [ ] Google 계정으로 로그인하면 사용자가 생성되거나 조회된다
- [ ] `state` 검증에 실패하면 로그인이 거부된다
- [ ] 세 앱이 각각 자신의 콜백으로 돌아온다
- [ ] 사용자가 동의를 취소하면 오류 화면 없이 로그인 페이지로 돌아간다

## 4. 설계

```
shop → GET /api/v1/auth/google?app=shop   → Google 동의 화면
                                           ↓
     ← GET /api/v1/auth/google/callback?code&state
       ① state 검증  ② 코드→토큰 교환  ③ 프로필 조회
       ④ User 조회/생성  ⑤ JWT 발급(TASK-0022)  ⑥ 앱으로 리다이렉트
```

- 신규 사용자에게는 기본 역할 BUYER 를 부여한다. SELLER 는 입점 승인(TASK-0026), ADMIN 은 수동 부여만 가능하다
- `seller`/`admin` 앱에서 로그인했는데 해당 역할이 없으면 **로그인은 성립하되 권한 없음 안내**를 보여준다

## 5. 구현 계획

1. Google OAuth 클라이언트 생성, 리다이렉트 URI 3개 등록
2. authorize 엔드포인트 + state 발급·저장
3. callback 엔드포인트 + 토큰 교환
4. 프로필 조회 및 User 생성/조회
5. 오류 경로 처리
6. 로컬·프리뷰·운영 리다이렉트 URI 정리
