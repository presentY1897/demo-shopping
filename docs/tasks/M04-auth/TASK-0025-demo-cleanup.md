## 1. 목적

만료된 데모 계정과 그 계정이 만든 데이터를 자동 삭제한다. 공용 카탈로그와 다른 사용자의 데이터는 건드리지 않는다.

## 2. 범위

### 포함
- 만료 스케줄러 (주기 실행)
- 삭제 대상 정의와 순서 (외래키 역순)
- 공용 데이터 보호 규칙
- **주문에 포함된 상품은 스냅샷 덕분에 이력이 깨지지 않음을 검증**
- 관리자 화면용 강제 만료 API
- 정리 결과 로깅 + 헬스체크에 마지막 실행 시각 노출
- 만료 임박 알림 (남은 시간 1시간 이하 배너 강조)

### 제외
- 관리자 데모 관리 화면 (M14)

## 3. 요구사항

- [ ] 만료된 계정과 개인 데이터가 삭제된다
- [ ] 공용 카탈로그와 다른 사용자 데이터는 남는다
- [ ] 삭제 후에도 과거 주문 이력이 조회된다
- [ ] 스케줄러가 멈추면 헬스체크로 알 수 있다
- [ ] 정리 작업이 실패해도 다음 주기에 재시도된다

## 4. 설계

| 대상 | 처리 |
| --- | --- |
| 장바구니·위시리스트·최근본·알림 | 하드 삭제 |
| 주문·결제·정산 | **보존** (스냅샷 기반이라 사용자 없이도 조회 가능), `User` 는 소프트 삭제 |
| 데모 판매자가 등록한 상품 | 주문에 포함된 적 없으면 삭제, 있으면 숨김 처리 |
| 리뷰·문의 | 하드 삭제 |
| 가상 카드 | 하드 삭제 |

**주문을 보존하는 이유**: 데모 판매자의 상품을 다른 데모 구매자가 샀을 수 있다. 주문을 지우면 상대의 이력이 깨진다. `OrderItem` 이 상품 스냅샷을 갖고 있으므로 상품이 사라져도 주문서는 온전하다.

## 5. 구현 계획

1. 삭제 대상·순서 정의
2. 스케줄러 (주기 15분)
3. 트랜잭션 단위 배치 삭제 (한 계정씩)
4. 실패 시 다음 주기 재시도
5. 헬스체크에 마지막 실행 시각 노출
6. 강제 만료 API
7. 만료 임박 UI
