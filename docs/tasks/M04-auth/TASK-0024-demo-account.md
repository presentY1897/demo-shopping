# TASK-0024: 데모 계정 발급

| 항목 | 내용 |
| --- | --- |
| 마일스톤 | M04 인증·계정 |
| 상태 | 승인됨 |
| 작성일 | 2026-09-02 |
| 브랜치 | `feature/demo-account` |
| 선행 작업 | TASK-0023 |

## 1. 목적

방문자가 가입 없이 즉시 역할별 임시 계정을 받아 전체 기능을 체험하게 한다. **이 프로젝트의 핵심 진입 경로**다.

## 2. 범위

### 포함
- 데모 발급 엔드포인트 (역할별)
- 세 앱 각각의 발급 진입점 (로그인 페이지 + 첫 방문 안내)
- **발급 시 초기 데이터 세팅** — 빈 화면을 보지 않도록 역할별로 미리 채운다 (아래 표)
- 발급 즉시 로그인 상태로 전환
- **관리자 데모의 권한** — `DEMO_ADMIN` 역할 부여 (D-058, 가드는 TASK-0105)
- 남은 시간 표시 배너
- 발급 남용 방지 (IP·세션 기준 rate limit)

### 제외
- 가상 카드 지급 (M08 에서 이 흐름에 연결)
- 만료·정리 (TASK-0025)

## 3. 요구사항

- [ ] 역할을 고르면 5초 안에 로그인 상태가 된다 (초기 데이터 생성 포함)
- [ ] 데모 계정에 기본 데이터가 채워져 있어 **모든 화면이 비어 보이지 않는다**
- [ ] 관리자 데모는 파괴적 작업을 할 수 없다
- [ ] 남은 시간이 화면에 보인다
- [ ] 짧은 시간에 대량 발급이 차단된다

## 4. 설계

```
POST /api/v1/auth/demo { role: BUYER | SELLER | ADMIN }
  → User 생성 (isDemo=true, demoExpiresAt=now+24h)
  → 역할 부여, 초기 데이터 생성
  → JWT 발급 (일반 로그인과 동일 경로)
```

### 역할별 초기 데이터

빈 계정을 주면 방문자가 주문 내역·정산·통계 화면에서 전부 "데이터 없음"을 본다. 기능이 있어도 전달되지 않는다. **발급 시점에 체험 가능한 상태를 만들어 준다.**

| 역할 | 초기 데이터 |
| --- | --- |
| 구매자 | 가상 카드 1장(한도 100만원), 기본 배송지 1개, 쿠폰 3장(플랫폼 2·판매자 1), 적립금 잔액, **진행 중 주문 3건**(결제완료·배송중·배송완료 각 1), 위시리스트 3개, 최근 본 상품 5개 |
| 판매자 | ACTIVE 스토어(브랜드명·로고 자동 생성), **상품 12개**(공용 카탈로그에서 복제, 옵션·재고 포함), **주문 5건**(상품준비중 2·배송중 1·배송완료 1·반품요청 1), 정산 내역 2회차, 리뷰 4건(미답변 2) |
| 관리자 | **처리 대상 데모 데이터** — 승인 대기 판매자 신청 2건, 개입 대기 클레임 1건, 승인 대기 정산서 1건. 카탈로그·주문은 전체 조회로 이미 채워져 있다 |

**주문 3건을 서로 다른 상태로 주는 이유**: 주문 내역 화면에서 상태별 액션 버튼이 어떻게 달라지는지 한눈에 보인다. 배송완료 건이 있어야 구매확정·반품 신청을 바로 눌러볼 수 있다.

**판매자 상품을 복제로 만드는 이유**: 새로 생성하면 이미지가 없어 초라하다. 공용 카탈로그의 상품을 복제해 소유자만 바꾸면 이미지·속성이 그대로 온다.

**관리자 데모에 처리 대상을 만들어주는 이유**: 관리자 업무의 핵심은 승인·개입·지급 처리다. `demo` 스코프(TASK-0105) 때문에 실계정 신청은 건드릴 수 없으므로, 처리 대상이 없으면 관리자 콘솔이 조회만 되는 껍데기가 된다.

혼자 체험하는 경우를 위한 장치이며, **판매자 데모와 관리자 데모를 탭 두 개로 동시에 열면 서로 실제로 처리할 수 있다**(판매자 데모가 입점 신청 → 관리자 데모가 승인).

이 초기 데이터도 만료 시 함께 삭제된다(TASK-0025).

### 데모 계정이 데이터를 자유롭게 다룰 수 있어야 한다

데모의 목적은 **직접 만들고 지워보는 것**이다. 판매자 데모는 초기 상품 12개를 수정·삭제할 수 있고 새로 등록할 수도 있다. 관리자 데모는 카테고리·속성·쿠폰을 **생성**할 수 있되, 다른 계정이 만든 것은 건드릴 수 없다.

### 관리자 데모 권한 (D-058)

**별도 장치를 만들지 않는다.** `DEMO_ADMIN` 역할과 `demo` 스코프로 권한 체계 안에서 표현한다. (TASK-0105)

```
DEMO_ADMIN = ADMIN_OPERATOR 퍼미션 + 리소스 스코프 demo
             → 데모 계정이 만든 데이터만 처리 가능
             → 시드·실계정 데이터는 조회만
             → delete · settlement.pay · user.delete 퍼미션 자체가 없음
```

판단 축은 셋이다.

| 축 | 차단 대상 |
| --- | --- |
| 남에게 피해를 주는가 | 실계정 사용자·판매자의 데이터 변경 |
| 되돌릴 수 없는가 | 삭제, 정산 지급 확정 |
| 공용 자산을 훼손하는가 | 시드 카탈로그·카테고리 파괴 |

**반대로 자기가 만든 것과 다른 데모가 만든 것은 전부 다룰 수 있다.** 어차피 24시간 후 삭제되고, 직접 처리해보는 것이 데모의 목적이다.

UI 에서는 **버튼을 숨기지 않고 비활성 + 사유 툴팁**으로 보여준다. 기능이 있다는 것을 알리는 게 데모의 목적이다.

## 5. 구현 계획

1. 발급 엔드포인트 + 초기 데이터 생성
2. rate limit
3. `DEMO_ADMIN` 역할 부여 (권한 가드는 TASK-0105 에서 구현)
4. 세 앱 발급 UI
5. 남은 시간 배너
6. 관리자 데모 제한 UI 반영
