## 1. 목적

방문자가 가입 없이 즉시 역할별 임시 계정을 받아 전체 기능을 체험하게 한다. **이 프로젝트의 핵심 진입 경로**다.

## 2. 범위

### 포함
- 데모 발급 엔드포인트 (역할별)
- 세 앱 각각의 발급 진입점 (로그인 페이지 + 첫 방문 안내)
- 발급 시 초기 데이터 세팅 (프로필, 기본 배송지, 판매자면 스토어)
- 발급 즉시 로그인 상태로 전환
- **관리자 데모의 권한 제한** (Q-11 결정)
- 남은 시간 표시 배너
- 발급 남용 방지 (IP·세션 기준 rate limit)

### 제외
- 가상 카드 지급 (M08 에서 이 흐름에 연결)
- 만료·정리 (TASK-0025)

## 3. 요구사항

- [ ] 역할을 고르면 3초 안에 로그인 상태가 된다
- [ ] 데모 계정에 기본 데이터가 채워져 있어 바로 기능을 써볼 수 있다
- [ ] 관리자 데모는 파괴적 작업을 할 수 없다
- [ ] 남은 시간이 화면에 보인다
- [ ] 짧은 시간에 대량 발급이 차단된다

## 4. 설계

```
POST /api/v1/auth/demo { role: BUYER | SELLER | ADMIN }
  → User 생성 (isDemo=true, demoExpiresAt=now+24h)
  → 역할 부여, 초기 데이터 생성
  → JWT 발급 (일반 로그인과 동일 경로)
```

**Q-11 관리자 데모 권한 제한안** (이 TASK 에서 확정):

| 허용 | 차단 |
| --- | --- |
| 전체 조회, 대시보드 | 사용자 삭제, 판매자 정지 |
| 카테고리·속성 **생성** | 카테고리·속성 삭제 |
| 자신이 만든 데이터 수정 | 다른 계정이 만든 데이터 수정·삭제 |
| 쿠폰 발행 (자신 소유) | 정산 지급 확정 |

차단은 API 가드에서 `isDemo` 를 검사해 처리하고, UI 에서는 비활성 + 사유 툴팁으로 보여준다. **버튼을 숨기지 않는다** — 기능이 있다는 걸 보여주는 게 데모의 목적이다.

## 5. 구현 계획

1. 발급 엔드포인트 + 초기 데이터 생성
2. rate limit
3. 데모 권한 가드 (`@DenyDemo` 데코레이터)
4. 세 앱 발급 UI
5. 남은 시간 배너
6. 관리자 데모 제한 UI 반영
