# TASK-0112: 프로필 · 배송지 화면

| 항목 | 내용 |
| --- | --- |
| 마일스톤 | M04 인증·계정 |
| 상태 | 승인됨 |
| 작성일 | 2026-09-03 |
| 브랜치 | `feature/profile-address-page` |
| 선행 작업 | TASK-0111, TASK-0023, TASK-0018, TASK-0017, TASK-0107 |

> **분할 유래** — TASK-0027(프로필 · 배송지 관리)의 화면 절반이다. D-208 에 따라 화면과 API 를 나눴고,
> API 는 TASK-0111 이 맡는다. 원본에 있던 **판매자 스토어 설정 화면**은 판매자 도메인으로 옮겨
> TASK-0109 가 담당한다.

## 1. 목적

`apps/shop` 마이페이지에서 프로필 · 표시 설정 · 배송지를 다루는 화면을 만든다. 배송지 입력은 **우편번호
검색 위젯**을 붙여 사용자가 주소를 직접 타이핑하지 않게 한다.

밀도 설정이 여기서 서버로 승격되므로, **밀도 3단계를 실제로 전환해 보는 첫 화면**이기도 하다.

## 2. 범위

### 포함
- `/mypage/settings` — 프로필(이름 · 아바타), 표시 밀도 3단계, 알림 수신 설정
- `/mypage/addresses` — 배송지 목록 · 추가 · 수정 · 삭제 · 기본 지정
- **우편번호 검색 위젯 연동** (외부 스크립트) + **로드 실패 시 수동 입력 폴백**
- **밀도 승격 로직** — 비로그인 localStorage 값을 로그인 직후 `PATCH /me/preferences` 로 올리고, 이후
  서버 값을 단일 출처로 삼는다
- 회원 탈퇴 화면 — 확인 다이얼로그(TASK-0017 의 파괴적 작업 규약) + 결과 안내
- 서버 검증 오류(400 `details`)를 해당 필드에 매핑
- `profileResponseSchema` · `addressSchema` · `userPreferenceSchema` 로 **모킹 데이터를 만들고 `parse` 로 검증**

### 제외 (이번에 하지 않는 것)
- **프로필 · 배송지 · 설정 API** → TASK-0111
- **판매자 스토어 설정 화면** → TASK-0109 로 이관
- 주문서에서의 배송지 선택 UI → M07(TASK-0050). 그 화면은 여기서 만든 배송지 카드 컴포넌트를 재사용한다
- 알림함 화면 → M13(TASK-0090). 이번에는 **수신 여부 스위치**만 만든다
- 실제 API 호출 테스트 — 백엔드는 모킹한다

## 3. 요구사항

### 기능 요구사항
- [ ] 프로필을 수정하면 화면에 즉시 반영된다
- [ ] 배송지를 추가·수정·삭제하고 기본을 지정할 수 있다
- [ ] 기본 배송지가 목록에서 눈에 띄게 구분된다
- [ ] 우편번호 검색으로 도로명·지번·우편번호가 자동 입력된다
- [ ] 검색 위젯 로드가 실패해도 손으로 입력해 저장할 수 있다
- [ ] 밀도를 바꾸면 화면이 즉시 그 밀도로 바뀌고 서버에 저장된다
- [ ] 비로그인에서 바꾼 밀도가 로그인 후에도 유지된다
- [ ] 탈퇴는 확인을 거쳐야 실행된다

### 비기능 요구사항
- **밀도 3단계 전부에서 레이아웃이 정상**이어야 한다 (`apps/shop` 화면이므로 P6 · U4 대상)
- 접근성 — 오류 메시지가 `aria-describedby` 로 필드에 연결된다

## 4. 설계

### 화면 / 컴포넌트

```
apps/shop/app/mypage/settings/page.tsx    프로필 · 밀도 · 알림
apps/shop/app/mypage/addresses/page.tsx   배송지 목록
        ├ AddressCard                     한 건 표시 + 기본 배지 + 수정 · 삭제
        └ AddressForm                     추가 · 수정 (우편번호 검색 포함)
```

`docs/design/pages.md` 1장의 `/mypage/addresses` · `/mypage/settings` 가 그대로 이번 범위다.

### 우편번호 검색

**다음(카카오) 우편번호 서비스를 실제로 붙인다.** 위젯이 준 값을 그대로 폼에 채우고 **정규화는 하지
않는다**. 버전은 8장에 적었다.

```
[우편번호 찾기] → 위젯 → 우편번호 · 도로명 주소 자동 입력 → 상세주소만 사용자 입력
```

**붙이기로 한 근거와 그 대가.** F6 의 측정 방법이 처음부터 "(스텁)" 이다 — 즉 이 TASK 의 게이트는
위젯이 실제로 뜨는 것을 확인하지 않으며, 확인할 수 있는 게이트도 없다(브라우저가 필요하고, 프론트
테스트는 외부 소켓을 열지 못하게 막혀 있다 — `packages/api-mocks` 의 3중 차단). 그래도 붙이는 것은
"주소를 손으로 타이핑하지 않게 한다"(1장)가 이 화면의 목적 절반이기 때문이다. 대신 대가를 문서에
적는다 — **버전을 고정할 수 없다.** 배포 채널이 `prod` 하나이고 파일명에 버전이 없다(8장).

**그래서 세 가지를 설계로 묶는다.**

| | |
| --- | --- |
| 지연 로드 | 스크립트는 배송지 폼이 열릴 때 받는다. 목록·설정 화면의 첫 페인트에 외부 스크립트가 끼지 않는다 |
| 임베드 | 팝업이 아니라 **폼 안 컨테이너에 임베드**한다. 팝업 차단기를 타지 않고, 열고 닫는 것을 우리가 제어한다 |
| 주입 가능한 이음매 | 로더는 `AddressForm` 의 prop 이다. 테스트는 스텁을 넘기고, 실패 경로도 스텁으로 만든다 |

**폴백이 필수인 이유**: 외부 스크립트다. 차단되거나 죽으면 배송지를 아예 추가할 수 없게 되고, 그러면
주문도 못 한다. 로드 실패·타임아웃을 감지하면 세 필드를 직접 입력 가능한 상태로 바꾼다(F6b). 폴백은
예외 경로가 아니라 **기본 경로와 같은 자격**이다 — 스크립트가 없어도 저장까지 갈 수 있어야 한다.

### `/me` 를 부르는 방법 — `ApiClient.request`

`createApiClient` 에는 `/me` 계열 메서드가 **없다.** TASK-0111 은 스키마만 정의하고 클라이언트
메서드를 추가하지 않았고, `packages/shared` 는 이 TASK 의 소유 경로가 아니다.

그래서 이 화면은 `ApiClient.request({ path, schema })` 를 직접 쓰고, **엔드포인트마다 한 번씩만**
`apps/shop/src/lib/profile/client.ts` 에서 이름을 붙인다. 응답 타입은 전부
`packages/shared` 의 zod 스키마에서 나오므로 C1 은 그대로 성립한다 — 메서드가 있는 쪽과 없는 쪽의
차이는 "스키마를 어느 파일에서 한 번 적느냐" 뿐이다.

> **오케스트레이터 판단이 필요한 항목.** `packages/shared` 에 `/me` 메서드를 넣는 것이 옳다면 그것은
> 별도 TASK 이고, 이 파일은 그때 지워진다. 지금 지어내지 않는다.

### 밀도 값의 두 표현

`@shopping/ui` 는 밀도를 `1 | 2 | 3`(`DensityLevel`) 으로, `@shopping/shared` 는
`MINIMAL | STANDARD | MAXIMAL`(`DisplayDensity`) 로 부른다. 전자는 `data-density` 속성이자 CSS 의
입력이고, 후자는 Prisma enum 이다. **둘을 잇는 표는 어느 패키지에도 없고, 이 TASK 가 만든다.**

`apps/shop/src/lib/profile/density-preference.ts` 에 둔다. `packages/ui` 에 두면 컴포넌트
라이브러리가 API 계약을 알게 되고, `packages/shared` 에 두면 API 패키지가 CSS 의 표현을 알게 된다.
밀도 토글을 가진 앱은 `apps/shop` 하나뿐이므로(D-033) 앱이 맞다.

### 밀도 승격

```
비로그인   토글 → localStorage 저장 → 즉시 적용
로그인 직후 localStorage 에 값이 있으면 PATCH /me/preferences 로 1회 승격
이후       서버 값이 단일 출처. 토글은 서버에 저장하고 localStorage 는 캐시로만 유지
```

승격 판단(언제 올릴지)은 **클라이언트의 몫**이다. 서버는 일반 변경과 구분하지 않는다(TASK-0111 4장).

### 절단면 — `packages/shared` 의 zod 스키마

TASK-0111 이 정의한 스키마를 그대로 쓰고, **모킹 응답도 같은 스키마로 만든다.**

| 스키마 | 이 화면에서의 용도 |
| --- | --- |
| `profileResponseSchema` | 프로필 표시. 모킹 응답 `parse` |
| `profileUpdateRequestSchema` | 프로필 폼 클라이언트 검증 (TASK-0017 어댑터) |
| `addressSchema` | 배송지 카드 · 폼의 값 타입. 모킹 목록 `parse` |
| `addressCreateRequestSchema` · `addressUpdateRequestSchema` | 배송지 폼 검증 (우편번호 5자리 규칙 포함) |
| `addressListResponseSchema` | 목록 응답 모킹 |
| `userPreferenceSchema` · `userPreferenceUpdateRequestSchema` | 밀도 · 알림 설정 |

우편번호·전화번호 형식 규칙은 **스키마에만** 있다. 화면에 정규식을 다시 적으면 서버와 어긋난다.

### 실패를 읽는 자리 — `apps/shop` 에 **작은** `api-failure.ts` 를 들인다

TASK-0023 은 `apps/shop` 에 `errors.ts` 를 들이지 않기로 했다. 근거는 "shop 이 마주하는 실패가 둘뿐이라
`Record<UserFacingErrorCode, string>` 을 들이면 **닿는 문장이 하나뿐인 카탈로그**가 생긴다" 였다
(TASK-0023 4장, `docs/HANDOFF.md` 3.3).

**그 전제는 이 TASK 에서 절반만 바뀐다.** 이 화면은 실패를 다섯 가지 만난다 — 400(필드 검증),
401, 404(다른 곳에서 지워진 배송지), **409(기본 배송지 경쟁)**, 5xx. 실패를 **값으로 읽는 것**은
이제 필요하고, **코드 전수 카탈로그**는 여전히 필요하지 않다.

그래서 갈라 놓는다.

| | 넣는 것 | 넣지 않는 것 |
| --- | --- | --- |
| `lib/api-failure.ts` | `apiFailure` · `hasCode` · `quotableRequestId` — 두 콘솔의 것과 같은 판별 | |
| 문구 | 화면이 **실제로 분기하는 코드만** 담은 부분 레코드 (`mypage.errors`) | `Record<UserFacingErrorCode, string>` 전수 카탈로그 |

모르는 코드는 서버의 문장을 그대로 보여준다 — `packages/ui` 의 `serverFieldErrors` 가 이미 그렇게 하고,
빈 오류보다 서버 어휘가 낫다는 판단은 TASK-0117 4.1 의 것이다.

> **합치기는 여전히 이 TASK 의 일이 아니다.** `api-failure.ts` 가 이로써 세 벌이 된다. HANDOFF 3.3 은
> 합치는 일이 "파일 이동이 아니라 보간을 할 것인가 · `hasCode` 를 공통 API 로 둘 것인가 라는 설계
> 결정" 이고 **실제 접점은 TASK-0113 · 0114** 라고 적어 뒀다. 이 파일의 머리말이 나머지 두 벌과
> 무엇이 다른지를 적어, 합칠 때 읽을 것이 남게 한다. **오케스트레이터 판단이 필요한 항목.**

### 역할별 권한

`/mypage/*` 는 로그인한 모든 역할이 자기 계정에 대해 쓴다. 데모 계정도 동일하다 — 데모 사용자가
배송지를 만들어 보는 것이 데모의 목적이다(DECISIONS 2 "데모 데이터 조작").

## 8. 확정된 버전

| 패키지 | 버전 |
| --- | --- |
| 다음(카카오) 우편번호 서비스 v2 | `//t1.daumcdn.net/mapjsapi/bundle/postcode/prod/postcode.v2.js` — **버전 고정 불가** |

**"버전 고정 불가" 를 값으로 적는 이유.** D5 는 "새로 도입한 라이브러리 버전을 기록" 하라고 한다.
이 스크립트에는 적을 버전이 없다 — 배포 채널이 `prod` 하나이고 파일명이 `postcode.v2.js` 로 고정되어
제공자가 언제든 내용을 바꾼다. 빈칸으로 두면 "아직 안 정했다" 로 읽히므로, **고정할 수 없다는 사실
자체**를 값으로 적는다. 이것이 F6b(수동 입력 폴백)를 선택이 아니라 필수로 만드는 근거이기도 하다.

**키·환경변수 없음.** 이 위젯은 API 키를 요구하지 않으므로 `.env.example` 은 바뀌지 않는다(D4).
스크립트 주소는 코드 상수(`apps/shop/src/lib/profile/postcode.ts`)이고, 테스트는 로더를 스텁으로
대체하므로 어떤 게이트도 외부 호스트에 닿지 않는다.
