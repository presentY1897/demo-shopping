## 1. 목적

일반 사용자가 판매자로 입점 신청하고 관리자가 승인하는 흐름을 만든다. SELLER 역할이 부여되는 유일한 경로다.

## 2. 범위

### 포함
- 입점 신청 폼 (브랜드명, 소개, 로고, 연락처)
- `Seller` 상태 머신: PENDING → ACTIVE / REJECTED → SUSPENDED
- 관리자 승인·반려·정지 화면
- 승인 시 SELLER 역할 자동 부여
- 상태별 판매자 앱 접근 제어
- 브랜드명 중복 검사
- 상태 변경 알림 (알림 시스템은 M13, 여기선 기록만)

### 제외
- 스토어 상세 설정 (M14 또는 판매자 설정 화면)
- 사업자 정보 검증

## 3. 요구사항

- [ ] 로그인한 사용자가 입점 신청할 수 있다
- [ ] 관리자가 승인하면 SELLER 역할이 부여된다
- [ ] PENDING 상태에서는 상품 등록이 불가능하다
- [ ] SUSPENDED 상태에서도 기존 주문 처리는 가능하다
- [ ] 브랜드명이 중복되지 않는다

## 4. 설계

상태 전이는 `docs/design/state-machines.md` 6장 참조.

| 상태 | 판매자 앱 | 상품 등록 | 주문 처리 |
| --- | --- | --- | --- |
| PENDING | 안내 화면만 | ✗ | – |
| ACTIVE | 전체 | ✓ | ✓ |
| REJECTED | 사유 표시 + 재신청 | ✗ | – |
| SUSPENDED | 제한 | ✗ | **✓** |

**SUSPENDED 에서 주문 처리를 허용하는 이유**: 이미 결제한 구매자가 있다. 판매자를 정지시켰다고 배송이 멈추면 피해는 구매자가 본다.

## 5. 구현 계획

1. 입점 신청 API + 폼
2. 상태 머신 구현
3. 관리자 승인·반려·정지 API
4. 관리자 화면 (목록·상세·처리)
5. 상태별 접근 제어
6. 데모 판매자는 즉시 ACTIVE 로 생성 (TASK-0024 연동)
