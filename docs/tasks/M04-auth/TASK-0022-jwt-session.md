## 1. 목적

access + refresh 토큰 체계를 구현한다. **세 앱의 세션이 서로 독립**이라는 전제를 코드로 못박는다.

## 2. 범위

### 포함
- access token (짧은 수명, 메모리 보관) / refresh token (httpOnly 쿠키)
- refresh 토큰 저장·회전(rotation)·재사용 감지
- 앱별 세션 분리 (`RefreshToken.app`, 쿠키에 `Domain` 미지정)
- 토큰 갱신 엔드포인트
- 로그아웃 (현재 앱) / 전체 로그아웃 (모든 앱)
- 인증 가드 (`@CurrentUser`) 와 역할 검사 데코레이터
- 만료된 refresh 토큰 정리

### 제외
- 프론트 인증 UI (TASK-0023)
- 데모 계정 발급 (TASK-0024)

## 3. 요구사항

- [ ] shop 에서 로그인해도 seller 는 로그아웃 상태다
- [ ] access 만료 시 자동으로 갱신된다
- [ ] refresh 토큰이 재사용되면 해당 세션 전체가 무효화된다
- [ ] 쿠키가 httpOnly · Secure · SameSite 설정을 갖는다
- [ ] 로그아웃하면 해당 앱의 refresh 토큰이 폐기된다

## 4. 설계

| 토큰 | 수명 | 보관 |
| --- | --- | --- |
| access | 15분 | 클라이언트 메모리 |
| refresh | 14일 | httpOnly 쿠키 (`Domain` 미지정 = 발급 서브도메인 한정) |

**회전 + 재사용 감지**: 갱신 시 새 refresh 를 발급하고 기존 것을 폐기한다. 폐기된 토큰이 다시 오면 탈취로 간주하고 그 사용자의 해당 앱 세션을 전부 끊는다.

**쿠키에 `Domain` 을 지정하지 않는 이유**: 지정하면 서브도메인 간 공유되어 D-028 의 앱별 독립 세션이 깨진다.

## 5. 구현 계획

1. JWT 서명·검증 설정 (시크릿 환경변수)
2. access/refresh 발급 로직
3. refresh 저장(해시)·회전·재사용 감지
4. 갱신·로그아웃 엔드포인트
5. 인증 가드 + 역할 데코레이터
6. 만료 토큰 정리 배치
