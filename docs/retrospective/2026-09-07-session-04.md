## 3. 이 세션이 보여주는 것

### ① 감사는 싸다

세션 03 이 실작업 1시간당 $67.3 을 쓰는 동안, 이 세션은 **10분 47초에 $2.68** 을 썼다.
컨텍스트가 작기 때문이다 — 피크 97,555 토큰으로 세션 03(966,207)의 **10분의 1**이다. **읽을 것을 좁히면 요청당 비용이 그만큼 내려간다**는 것이 같은 저장소·같은 모델에서 대조군처럼 확인된다.

| | 세션 03 | 세션 04 |
| --- | ---: | ---: |
| 피크 컨텍스트 | 966,207 | **97,555** |
| 요청당 평균 비용 | $0.303 | **$0.072** |
| 서브에이전트 | 76 | 0 |

### ② 병행 세션은 저장소 상태를 흔든다

같은 저장소를 두 세션이 동시에 만졌고, 그 결과가 **"main 되돌림"** 이다.
같은 시각(10:43) 세션 03 에는 **"지금 워크트리는 구분안해?"** 라는 프롬프트가 들어갔다. 사용자가 양쪽에서 동시에 규율 문제를 지적하고 있었다는 뜻이다.

→ 병행 세션을 쓸 거면 **읽기 전용 감사**로 한정하는 것이 안전하다. 이 세션은 결과적으로 그렇게 됐다(코드 변경 0줄).

### ③ `cost-state` 의 `totalDuration` 은 활동 시간이 아니다

`cost-state` 는 `totalDuration: 2.55h` 를 보고했지만 트랜스크립트의 실제 활동 구간은 **10분 47초**다. 세션 객체가 열려 있던 시간과 일한 시간은 다르다.
[세션 03 부록](./2026-09-04-session-03.md#부록-측정-방법)에서 두 값을 구분해 쓴 이유가 여기서도 확인된다.
