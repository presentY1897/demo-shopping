## 5. 사용자가 준 피드백

### A. "계속 진행해" — 위임의 언어 (31회)

> "이제 **내가 결정해야할 문제가 나오기 전에는** 계속 승인된 태스크 진행해" (09-05 06:39)
> "마일스톤 끝까지 진행해. **따로 내가 확인해서 결정할거없으면** 마무리까지 진행해" (09-07 14:29)

조건은 나흘 내내 같다 — **"내가 결정할 게 나오기 전까지".** 세션 01 의 D-037 이 운영 규칙으로 자리 잡았다.

### B. **"…라니까" — 같은 지시를 반복해야 했다 (2회) + 1분 간격 재전송 (1회)**

> "응 마일스톤 **계속 진행하라니까**" (09-06 18:14)
> "응 승인된 task **다 하라니까**" (09-07 07:54)
> "마일스톤 끝까지 진행해…" (14:29) → **"마일스톤 14 끝까지 진행해…"** (14:30)

`-라니까` 는 이미 말한 것을 다시 말할 때 쓰는 종결어미다. 14:29→14:30 의 재전송은 **범위를 좁혀 다시 말한** 경우다.
**위임을 명시해도 에이전트가 멈추거나 범위를 넓게 잡아, 사용자가 같은 말을 31번 반복했다.**

### C. 개념 설명 요구 (12회) — 네 세션 연속, 그리고 직접적인 항의

> "`api-failure.ts` 세 벌을 합칠 자리입니다 — 무슨 말인지 설명해" (09-05 03:58)
> "확정은 끝이라는게 무슨말이지?" (09-06 14:08)

**"여전히"** 는 이 문제가 세션을 넘어 이어지고 있음을 사용자가 인지하고 있다는 신호다.

### D. 결정 (9회) — `DECISIONS.md` 에는 2건만 남았다

> "음 웨이브로 가자" · "음 합치는거 먼저하자"(→ D-219) · "권한 등급 나누고 쿠폰은 권한에 맞춰서 허용되는 그룹에 발매가능한식으로"

## 8. 해석

1. **결정 60 → 15 → 2. 설계 투자는 세 번째 세션에서 가장 크게 회수됐다.**
   77시간 자율 실행 동안 `DECISIONS.md` 에 새로 오른 것이 2건뿐이다. 개입 밀도도 8.0 → 1.4/h 로 떨어졌다.

2. **줄은 싸지고 덩어리는 비싸졌다.** 코드 1,000줄당 $17.47 → $14.28(−18%), 실작업 시간당 $103.6 → $79.8(−23%). 반대로 PR 1개당 +184%, 커밋 1개당 +186%.
   → **성숙한 코드베이스에서는 양산이 싸지고 통합이 비싸진다.**

3. **세션 안에서도 뒤로 갈수록 비싸진다 — 커밋 1개당 $1.05 → $11.62 (11배), 서브에이전트 1개당 $21.30 → $32.68 (1.53배).**
   **"오래 돌릴수록 효율이 오른다"는 직관은 이 데이터로 반박된다.**

4. **모델 선택의 지렛대는 거의 쓰이지 않았다.** `Agent` 82개 중 절감이 되는 `sonnet` 지정은 4개뿐(총액의 0.14%). 09-07 에 붙은 `opus` 10개는 기본값과 같아 효과가 없다.
   09-07 에 몰린 작업(F-표 채우기·화면 스캐폴딩)이 정확히 Sonnet 으로 돌렸어야 할 일이었다.

5. **병목은 병렬 폭이 아니라 직렬 도구 실행이었다.** 도구 시간 35:41 이 세션 시간의 47% 다.

6. **위임을 31번 반복해야 했다.** §5-A·B.
   **자율 실행의 실질 상한은 컨텍스트나 비용이 아니라 "에이전트가 스스로 멈추거나 범위를 넓게 잡는 빈도"** 다.

7. **자율 실행이 길어지면 초기 규율부터 흐려진다.** 워크트리 구분(§5-E), 결정 9건 중 7건이 미기록(§5-D).

8. **진행 중 세션의 비용 추정은 단가 증가를 반영해야 한다.** 내 추정이 13.8% 낮았던 이유가 정확히 그것이다(§2).

9. **사용자는 자율 구간과 검토 구간을 스스로 나눴다.** 코드는 나흘 내내 위임했지만 포트폴리오 문서는 "초안만"이라고 했다(§5-F).

## 부록: 측정 방법

- **1차 근거**: 세션 파일의 `cost-state` 레코드 4개. 종료 시점 레코드가 **최종 실측치($3,922.45)** 다.
- **2차 근거**: 트랜스크립트의 `message.usage`(본 스레드만, $1,675.09). `message.id` 중복 제거 필수(assistant 레코드 8,602 → 요청 5,564).
- **서브에이전트 비용**: 최종 `cost-state` − 본 스레드 트랜스크립트 = $2,247.36. 진행 중에는 이 값을 추정해야 하는데, **단가가 시간에 따라 오르므로 직전 구간 평균을 쓰면 낮게 나온다**(§2).
- **시각 처리 주의**: 트랜스크립트 `timestamp` 는 UTC 다. KST 로 비교할 때 tz 인식 값에 9시간을 더하면 **경계 비교가 9시간 어긋난다.** naive KST 로 변환해 비교해야 한다(이 회고의 초기 계산에서 실제로 발생했던 오류다).
- **세션 종료 판정 주의**: 파일 mtime 은 세션을 다시 열기만 해도 갱신된다. **마지막 타임스탬프 레코드**로 판정해야 한다 — 이 세션의 mtime 은 09-09 이지만 실제 마지막 활동은 09-07 22:29 다.
- **코드 줄 수**: `main` 기준(`git ls-tree` + `git show`).
- **실작업 시간**: 레코드 간 10분 초과 공백을 제외한 값. 하네스 `totalDuration`(75:56)과는 정의가 다르다.
- **단가**: Opus 5 — 입력 $5 / 출력 $25 / 캐시 쓰기 5분 $6.25 · 1시간 $10 / 캐시 읽기 $0.50. Sonnet 5 — $2 / $10. Haiku 4.5 — $1 / $5. (per MTok)
- **주의**: 모두 **API 정가 기준 환산값**이다. 실제 청구는 구독 플랜에 따라 다르다.
