2. **줄은 싸지고 덩어리는 비싸졌다.** 코드 1,000줄당 $17.47 → $11.45(−34%), 실작업 시간당 $103.6 → $67.3(−35%). 반대로 PR 1개당 $20.89 → $44.77(+114%), 커밋 1개당 +120%.
   → **성숙한 코드베이스에서는 양산이 싸지고 통합이 비싸진다.**

3. **캐시 읽기가 총액의 81% 로 더 기울었다.** 26억 토큰 = $1,304(09-06 00:42 기준).
   컨텍스트가 96.6% 까지 차고 압축이 **7회** 일어난 것과 같은 원인이다.

4. **모델 선택의 지렛대는 거의 쓰이지 않았다.** `Agent` 76개 중 모델 지정은 8개(sonnet 4·opus 4)뿐, 68개가 기본값이었다. sonnet 4개가 쓴 돈은 총액의 0.3% 다.
   조사·문서화·스펙 작성처럼 판단이 가벼운 작업을 Sonnet 으로 돌리는 것만으로 큰 절감이 가능한데 **활용되지 않았다.**

5. **병목이 병렬 폭에서 직렬 도구 실행으로 옮겨갔다.** Bash 4,334회, 도구 시간 16:53.

6. **위임을 24번 반복해야 했다.** §5-A·B. 한 번 위임하면 끝나야 할 것을 사흘 내내 다시 말했고, 두 번은 `-라니까` 로 나왔다.
   **자율 실행의 실질 상한은 컨텍스트나 비용이 아니라 "에이전트가 스스로 멈추는 빈도"** 였다.

7. **자율 실행이 길어지면 초기 규율부터 흐려진다.** 워크트리 구분(§5-E)이 사흘째에 지적됐다. 결정 8건 중 6건이 `DECISIONS.md` 에 오르지 못한 것(§5-D)도 같은 종류의 이완이다.

8. **`cost-state` 조차 36시간을 놓쳤다.** 장기 세션에서는 하네스 회계와 트랜스크립트를 겹쳐 써야 하고, 그래도 ±4% 폭이 남는다(§2).

## 부록: 측정 방법

- **1차 근거**: 세션 파일의 `cost-state` 레코드 2개. 다만 **마지막 레코드가 09-06 00:42 에 멈춰 36시간 34분을 놓쳤다.**
- **2차 근거**: 트랜스크립트의 `message.usage`(본 스레드만). `message.id` 중복 제거 필수(assistant 레코드 6,957 → 요청 4,510).
- **잔여 구간 추정**: 본 스레드는 실측($564.00), 서브에이전트는 (a) 직전 구간 에이전트당 평균 $21.30 × 38개, (b) 직전 구간 서브에이전트/본 스레드 비율 1.01 × $564 두 가지로 계산해 **범위로 제시**했다.
- **코드 줄 수**: `origin/main` 기준(`git ls-tree` + `git show`). 로컬 `main` 워크트리는 스냅샷 시점에 뒤처져 있었다.
- **실작업 시간**: 레코드 간 10분 초과 공백을 제외한 값. 하네스 `totalDuration` 과는 정의가 다르다.
- **단가**: Opus 5 — 입력 $5 / 출력 $25 / 캐시 쓰기 5분 $6.25 · 1시간 $10 / 캐시 읽기 $0.50. Sonnet 5 — $2 / $10. Haiku 4.5 — $1 / $5. (per MTok)
- **주의**: 모두 **API 정가 기준 환산값**이며, 이 세션은 스냅샷 시점에 **진행 중**이다. 종료 후 재측정이 필요하다.
