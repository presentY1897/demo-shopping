## 8. 해석

1. **결정 60 → 15 → 2. 설계 투자는 세 번째 세션에서 가장 크게 회수됐다.**
   43시간 자율 실행 동안 새로 정할 게 2건뿐이었다. 사람의 개입 밀도가 8.0 → 1.4/h 로 떨어진 것도 같은 이야기다.

2. **단가는 내려가고 덩어리는 커졌다.** 코드 1,000줄당 $17.47 → $11.52(-34%), 실작업 시간당 $103.6 → $59.5(-43%). 반대로 PR 1개당 $20.89 → $31.11(+49%).
   → **성숙한 코드베이스에서는 줄을 찍는 값이 싸지고, 한 기능을 닫는 값이 비싸진다.**

3. **캐시 읽기가 총액의 81% 로 더 기울었다.** 26억 토큰 = $1,304.
   컨텍스트가 96.5% 까지 차고 압축이 4회 일어난 것과 같은 원인이다. **코드베이스가 커질수록 "읽는 값"이 "쓰는 값"을 압도한다.**

4. **모델 선택의 지렛대가 확인됐다.** 서브에이전트 53개 중 `sonnet` 지정은 4개뿐이고 그 4개가 총액의 0.3% 를 썼다.
   조사·문서화처럼 판단이 가벼운 작업을 Sonnet 으로 돌리는 것만으로 큰 폭의 절감이 가능하다는 뜻이다. **49개는 기본값(Opus)으로 돌았다.**

5. **병목이 병렬 폭에서 직렬 도구 실행으로 옮겨갔다.** API 누적(25:42) < 세션 시간(29:41), 도구 시간 16:53.
   세션 02 는 "에이전트를 더 띄우면 빨라지는" 국면이었지만, 이 세션은 **본 스레드의 Bash 2,749회가 시간을 먹었다.**

6. **외부 설정 요구가 35회 → 6회로 줄었다.** 인프라는 한 번만 연결하면 된다. 세션 02 회고에서 "사람이 브라우저에서 눌러야 하는 일은 미리 풀 수 없다"고 썼는데, **한 번 풀면 다시 안 든다**는 것이 이번에 확인됐다.

7. **"낯선 용어에 설명을 붙인다"는 세 세션 연속 미이행이다.** 매번 8~10회씩 설명 요구가 발생한다. 회고에 적는 것만으로는 바뀌지 않는다 — §5-E 에서 커밋 트레일러가 훅으로 강제되기 전까지 고쳐지지 않았던 것과 같은 구조다.

## 부록: 측정 방법

- **1차 근거**: 세션 파일의 `cost-state` 레코드 2개. 서브에이전트를 포함한 하네스 자체 회계다.
