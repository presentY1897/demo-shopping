## M02 배포 파이프라인 — 계정 5개

M01 진행 중에 준비하면 된다. **전부 무료다.**

| # | 서비스 | 할 일 | 비고 |
| --- | --- | --- | --- |
| 1 | **Neon** | 가입(GitHub 로그인) → 프로젝트 생성 → **연결 문자열** 전달 | PostgreSQL. Render 무료 DB 는 30일 만료라 분리 (D-060) |
| 2 | **Render** | 가입 → GitHub 연동 → `demo-shopping` 저장소 접근 허용 | 배포 설정은 `render.yaml` 로 코드에 넣으므로 클릭 작업이 적다 |
| 3 | **Vercel** | 가입 → GitHub 연동 → 같은 저장소 접근 허용 | 웹 3개. Hobby 무료 |
| 4 | **Cloudflare R2** | 대시보드에서 R2 활성화 → API 토큰 발급 | 도메인 구매로 계정은 이미 있음. **결제수단 등록을 요구할 수 있다** (무료 한도 내 미청구) |
| 5 | **Sentry** | 가입 → 프로젝트 2개 생성(Node / Next.js) → **DSN 2개** 전달 | 무료 |
| 6 | **Discord** | 채널 하나에 webhook 생성 → **URL** 전달 | CI 실패 알림. 서버가 있으면 5분 |

**DNS 레코드**(`shop` / `seller` / `admin` / `api`)는 Cloudflare 대시보드에서 직접 만들거나, **API 토큰을 주면 내가 처리**한다.

> 레코드는 반드시 **DNS only(회색 구름)** 로. 프록시를 켜면 Vercel SSL·캐시가 어긋난다 (D-044).

## M04 인증·계정 — Google OAuth

| # | 할 일 | 비고 |
| --- | --- | --- |
| 1 | **Google Cloud 프로젝트 생성** | |
| 2 | **OAuth 동의 화면 구성** | 앱 이름·로고·지원 이메일 |
| 3 | **OAuth 2.0 클라이언트 ID 발급** → **클라이언트 ID / 시크릿** 전달 | |
| 4 | **리다이렉트 URI 등록** | 로컬 3개 + 프리뷰 + 운영 3개. 목록은 내가 만들어 드린다 |

**주의할 점**: OAuth 동의 화면이 "테스트" 모드면 **등록된 테스트 사용자만 로그인**할 수 있다(100명 제한). 채용 담당자가 Google 로그인을 시도하면 막힌다.

`email` · `profile` 스코프만 쓰므로 민감 정보가 아니라 별도 심사 없이 게시할 수 있을 것으로 보이나, **M04 착수 시 실제 정책을 확인**한다. 게시가 어려우면 데모 계정 발급이 주 진입 경로이므로 큰 문제는 아니다.

## 내가 대신 할 수 있는 것

토큰·키를 주시면 클릭 작업을 줄일 수 있다.

| 주시면 | 제가 처리 |
| --- | --- |
| Cloudflare API 토큰 | DNS 레코드 생성·수정 |
| Vercel 토큰 | 프로젝트 생성·환경변수 등록·도메인 연결 |
| Neon API 키 | 프로젝트·브랜치 생성 |
| Unsplash API 키 | 스톡 이미지 수집 스크립트 |
| (이미 있음) `gh` | GitHub Secrets, 브랜치 보호 규칙, 저장소 메타 |

**반드시 직접 하셔야 하는 것**은 가입·약관 동의·결제수단 등록·Google OAuth 동의 화면 구성이다.

## 키 전달 방법

키·토큰은 **채팅에 붙여넣지 말고** 다음 중 하나로 전달한다.

- 워크트리의 `.env.local` 에 직접 기입 (gitignore 되어 있다)
- GitHub Secrets 에 직접 등록 후 이름만 알려주기

커밋되지 않게 `.gitignore` 와 커밋 훅에서 막고 있지만, 채팅 기록에 남는 것은 막을 수 없다.
