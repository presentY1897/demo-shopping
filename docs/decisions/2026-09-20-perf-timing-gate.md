# 2026-09-20 성능 검사의 시간 기준

## D-284 — 시간 예산은 로컬에서 엄격하게, CI 에서는 느슨하게 잰다

2026-09-18, `docs/` 만 바꾼 커밋(`66a83ba`)이 `main` 의 CI 를 빨갛게 만들었다. `orders-performance.spec.ts` 의
「주문 생성 p95 300ms」가 335ms 를 읽었다. 같은 내용의 PR 실행은 몇 분 전에 통과했고, 표본 30개 루프가 그쪽은
2,117ms · 실패한 쪽은 5,609ms 였다 — 같은 코드가 다른 러너에서 2.6배 느렸다. 2026-09-12 의
`demo-performance.spec.ts` 360ms 도 같은 모양이다.

TASK-0097 은 이 흔들림을 알고 `test-api-perf` job 을 따로 뗐지만 그것은 우리 검사끼리의 간섭을 없앤 것이다.
공유 러너 자체의 흔들림은 남았고, `QUALITY-GATES` A1 의 원문은 처음부터 「**로컬** 부하 측정 p95」였다.

**결정.**

- 시간 단언은 전부 `apps/api/test/support/timing.ts` 를 거친다. 표본을 재기 전에 같은 호출을 **2회 버린다**
  (커넥션 풀 · 콜드 코드). 표본 30개의 p95 는 두 번째로 느린 값이라, 워밍업이 없으면 느린 자리 둘 중 하나를
  러너가 아무 일도 하기 전에 써 버린다
- 판정은 두 가지다. **엄격** — p95 < 예산 (A1 원문 그대로). **느슨** — 중앙값 < 예산 × 3
- `PERF_TIMING=strict|loose` 가 고르고, 없으면 `CI` 환경변수가 있을 때 느슨이다. 모르는 값은 조용히 넘어가지
  않고 던진다
- 엄격한 판정은 **로컬에서** 돈다 — API 에 닿는 변경을 담은 푸시의 `pre-push`, 그리고 PR 직전의 `pnpm gate`
- CI 의 `test-api-perf` 는 느슨하게 돈다. 그 러너에서 **정확한 것**은 시간이 아니라 문장 수와 `EXPLAIN` 이고,
  N+1 과 인덱스 누락은 지금까지도 그쪽이 잡아 왔다
- `apps/api` 의 `test` 는 성능 스펙을 뺀다. CI 의 샤드는 처음부터 뺐는데 로컬의 `pnpm test` 는 빼지 않아서,
  로컬 전체 게이트가 시간 검사를 병렬 워커 사이에서 재고 있었다
- `vitest-blob-*` 의 보존은 3일. 1일이면 하루 지난 실행의 `gh run rerun --failed` 가 병합 job 에서
  `ENOENT: scandir .vitest-reports` 로 다시 실패한다

**배수가 3 인 이유.** 관측한 흔들림이 2.6배다. 3 미만은 다시 플레이크가 되고, 3 이면 평소 70ms 인 주문 생성이
900ms 를 넘어야 빨개진다 — 트랜잭션 안의 대기나 수 배의 회귀는 걸리고, 느린 이웃은 걸리지 않는다. 그 사이
(70ms → 250ms)는 로컬 엄격 판정의 몫이다.

**중앙값인 이유.** 표본 30개의 p95 는 값 두 개가 결정한다. 러너가 잠깐 멈추면 그 둘이 튄다. 중앙값은 열다섯
개가 함께 튀어야 움직인다.

**받아들인 것.** `pre-push` 는 `--no-verify` · `SKIP_PERF=1` 로 건너뛸 수 있다. 이 훅은 잠금이 아니라 **잊지
않게 하는 장치**다. CI 의 느슨한 판정이 큰 회귀를 막고, `pnpm gate` 가 PR 직전에 한 번 더 잰다.

**기각한 것.**

- CI 에서 시간 검사를 아예 빼기 — 문장 수는 그대로인데 느려지는 회귀(락을 오래 잡는 트랜잭션, 직렬화)를
  아무도 강제로 재지 않게 된다
- 예산을 올리기(300 → 600) — 어디서 재든 같은 숫자를 쓰는 한, 러너가 흔들릴 때마다 다시 올리게 된다
- 실패하면 자동 재시도 — 플레이크를 숨길 뿐이고 진짜 회귀도 세 번에 한 번은 지나간다
- 셀프 호스티드 러너 · 벤치마크 전용 서비스 — 데모 프로젝트에 과하다
- 로컬 측정 결과를 저장소에 남기고 CI 가 「이 커밋의 기록이 있는가」를 확인하기 — 훅을 잠금으로 만드는
  유일한 길이지만 커밋마다 파일이 하나씩 는다. 필요해지면 여기서 다시 시작한다
