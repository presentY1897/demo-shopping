# 2026-09-18 Render 유료 전환

## D-283 — API · 검색 엔진을 Starter 로 올리고, 플랜은 `render.yaml` 에 적는다

소유자가 Render 대시보드에서 서비스를 유료로 올렸는데 무료로 되돌아가 있었다. `render.yaml` 이 `plan: free` 를
적고 있었고, 2026-09-17 의 PR #154 가 그 파일의 주석을 고치면서 자동 sync 가 돌아 대시보드의 값을 덮은 것으로
보인다(시간대로 본 추정 — 06:21 UTC 머지, 약 45분 뒤부터 검색 엔진이 잠들고 인덱스를 잃었다). 그 결과가
TASK-0143 이 출발한 운영 검색 500 이다.

**결정.**

- `shopping-api` · `shopping-search` 모두 `plan: starter`(0.5 CPU · 512MB, 잠들지 않는다). 월 $7 × 2, 초 단위 일할
- `shopping-search` 에 1GB 디스크를 `/meili_data` 에 붙인다(월 약 $0.25). 재기동해도 인덱스가 남는다
- **플랜은 대시보드가 아니라 `render.yaml` 에서 바꾼다.** 그 파일이 push 되면 — 주석만 고쳐도 — sync 가 돌고,
  대시보드에서 손으로 바꾼 값은 사라진다

**그대로 두는 것.**

- 콜드 스타트 대응(D-280)과 검색 대기(D-282)의 코드. 유료 인스턴스도 배포 · 재기동 때는 잠깐 닿지 않는다
- 자동 재색인. 빈 디스크 · 문서 모양 변경 · 이미지 버전 교체 때 여전히 그것이 채운다
- 「주기 작업 · 깨워 두기를 만들지 않는다」. 근거였던 무료 750h/월은 사라졌지만 어길 이유가 없고, 무료로
  돌아갈 길을 막지 않는다

**기각한 것.**

- Railway 로 이전(옛 「유료 전환 경로」) — 같은 플랫폼에서 플랜만 올리는 편이 바꿀 것이 없다
- 검색 엔진을 Private Service 로 — 주소 · 환경변수 · 헬스 경로가 함께 바뀐다. 필요해지면 별도 TASK 다
- 검색 엔진의 버전을 올릴 때 디스크를 옮기기(덤프 · 마이그레이션) — 인덱스는 PostgreSQL 의 사본이라 버리고
  다시 채우는 쪽이 싸다
