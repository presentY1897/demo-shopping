## 4. 기술 스택

| 영역 | 결정 |
| --- | --- |
| 저장소 형태 | pnpm workspace **모노레포** |
| 프론트엔드 | **Next.js** (App Router) + TypeScript |
| 백엔드 | **NestJS** + TypeScript |
| DB | **PostgreSQL** + Prisma |
| 검색 | **Meilisearch** + 상품 변경 이벤트 기반 인덱싱 파이프라인 |
| 타입 공유 | `packages/shared` 를 프론트/백엔드 공용 단일 출처로 사용 |

### 모노레포 레이아웃

```
apps/web/       Next.js — 구매자 / 판매자 / 관리자 화면
apps/api/       NestJS — REST API
packages/shared 공용 타입, zod 스키마, 상수
packages/config eslint / tsconfig / prettier 공유 설정
```

### 검색 엔진 선정 근거

- **채택(Meilisearch)**: 오타 보정·접두어 검색·패싯·동의어 기본 제공, 한국어 세그멘터 내장, 컨테이너 1개(~100MB)로 운영 가능
- 탈락(PostgreSQL FTS): 한국어 형태소 분석이 약하고 랭킹·패싯을 직접 구현해야 함
- 탈락(Elasticsearch + nori): 한국어 품질은 최상이나 메모리 2GB+ 요구로 배포 비용 과다
- 리스크: 복합명사 분해 정확도가 nori 대비 낮음 → 실제 상품명으로 검증하고 부족하면 동의어 사전으로 보완
