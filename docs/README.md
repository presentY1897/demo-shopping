# 문서 체계

| 디렉터리 | 목적 | 성격 |
| --- | --- | --- |
| [`decisions/`](./decisions/) | 무엇을 하기로 정했는가 | `DECISIONS.md` 는 현재 상태, 세션 파일은 이력 |
| [`design/`](./design/) | 어떻게 생겼는가 | 항상 최신 상태만 유지 |
| [`tasks/`](./tasks/) | 무엇을 언제 만드는가 | **승인 후 구현**이 원칙 |

## 어디서부터 읽나

1. **[`decisions/DECISIONS.md`](./decisions/DECISIONS.md)** — 현재 유효한 모든 결정. 작업 전 필독
2. `design/` — 화면·데이터·상태·금액 규칙
3. `tasks/README.md` — 마일스톤별 진행 상황

## 미확정 항목(Q-NN)은 어디에 있나

| 위치 | 역할 |
| --- | --- |
| `decisions/DECISIONS.md` **14장** | **현재 유효한 미확정 목록.** 여기만 보면 된다 |
| `decisions/YYYY-MM-DD-session-NN.md` | `논의 중` 표(현재) + `해소된 질문` 표(어느 D-NNN 으로 결정됐는지) |
| 각 TASK 문서 **7장 리스크/열린 질문** | 그 Q 를 **언제** 결정할지. 착수 시점에 문서를 열면 그 자리에 다시 적혀 있다 |

Q 는 결정되면 세션 파일의 `해소된 질문` 으로 옮기고 `DECISIONS.md` 14장에서 지운다. 번호는 재사용하지 않는다.

## 진행 흐름

```
아이디어 → TASK 문서 작성 → 사용자 검토·승인 → 구현 → 완료 기준 충족 확인 → 문서 갱신
              ↘ 논의 중 정해진 사항 → 세션 파일에 D-NNN 기록 → DECISIONS.md 갱신
              ↘ 화면·스키마·상태가 바뀌면 → design/ 갱신
```

## 규칙

- **한 TASK = 하나의 작업 목적.** 번호는 전역 4자리 평면 번호이며 재사용하지 않는다.
- TASK 문서의 **정량적 완료 기준을 전부 충족해야** 상태를 `완료` 로 바꾼다.
- `DECISIONS.md` 와 `design/` 은 **현재 상태만** 담는다. 이력은 세션 파일에만 남긴다.
- 세션 파일은 덮어쓰지 않고 추가한다. 결정이 번복되면 "D-NNN 대체" 로 명시한다.
