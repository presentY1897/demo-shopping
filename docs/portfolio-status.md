## 알려진 기능·설계 한계

### 알림 생성 경로 누락 — 확인됨

구매자 `CLAIM_STATUS`는 계약·수신 설정이 있지만 생성 경로가 없다. 판매자 신규 리뷰 알림도
아직 구현하지 않았다. [알림 설계](./design/notifications.md)의 범위와 같다.
후속 구현에서는 실제 클레임 전이·리뷰 생성 뒤 올바른 수신자에게 알림이 생기는지 통합 검증한다.
이번 문서 작업에서는 알림 로직을 수정하지 않았다.

### 외부 환불 성공 후 내부 기록 실패 — 추가 검증 필요

[환불 서비스](../apps/api/src/payment/payment.service.ts)의 `refundWithin`은 프로바이더 환불을
호출한 뒤 내부 Refund·Payment·이력을 같은 DB 트랜잭션에 쓴다.
[토스 취소 요청](../apps/api/src/payment/toss.client.ts)은 요청별 멱등 키를 전달하지 않는다.

외부 시스템이 성공한 직후 DB 쓰기·커밋 또는 응답 수신이 실패하는 구간은 DB 잠금·타임아웃만으로
해결되지 않는다. 이번 검토에서는 그 구간의 장애를 재현하지 않았으므로 중복 환불 발생을
확정된 버그로 기재하지 않는다. 반대로 모든 장애에서 중복이 없다고도 주장하지 않는다.

후속 설계·검증 범위:

1. 환불 시도에 안정적인 식별자를 부여하고 외부 요청·내부 기록을 연결한다.
2. 외부 성공 후 응답 유실·DB 롤백을 각각 재현한다.
3. 재시도·웹훅·대사 뒤 외부 환불 횟수와 내부 누적 환불액을 함께 확인한다.
4. 가상 카드의 별도 트랜잭션 경계에도 같은 질문을 적용한다.

### 문서 상태와 구현이 다른 항목 — 판정 보류

TASK-0009·0011은 진행중, TASK-0012·0013·0024는 승인됨으로 남아 있다.
배포·스토리지 외부 검증과 데모 발급의 개별 완료 기준을 다시 읽어야 한다.
데모 발급 코드가 있다는 이유만으로 미체크 기준까지 완료로 바꾸지 않는다.
전체 인덱스는 우선 TASK 머리표를 따라 집계했다.

## 이번 검증

검증 결과는 실제 실행 후 아래에 기록한다. 기존 성능 기록과 이번 실행을 섞지 않는다.

- `pnpm install --frozen-lockfile`: 성공. Prisma Client 생성 및 shared 빌드 완료.
- `pnpm typecheck`: 워크스페이스 전체 통과.
- `pnpm --filter @shopping/shop exec vitest run test/guide.spec.tsx`: 1개 파일, 8개 테스트 통과.
- `pnpm --filter @shopping/shop exec eslint src/messages/ko.ts --max-warnings 0`: 통과.
- 작성·수정한 문서의 로컬 링크 대상 272개: 누락 0개. 외부 URL 응답과 Markdown 앵커는 별도 검증 대상.
- `git diff --check`: 통과. 신규 초안 문서와 가이드 메시지 파일은 Prettier로 정리.
- DB 통합 테스트·배포 E2E·세 앱을 포함한 신규 환경 전체 실행·Lighthouse는 재실행하지 않음. API·shop 로컬 기동은 아래 캡처 과정에서 확인.

## README에서 분리한 검증 범위

성능 표는 기존 CI 스택 측정 기록이다. README 편집이나 스크린샷 촬영에서 성능을 다시 측정한
값이 아니며 배포 사이트의 응답 시간을 나타내지 않는다. DevTools throttling과 Lantern 결과를
구분하고, API p95는 목표 예산으로 표시한다.

구매 E2E의 데모 발급 버튼은 클릭으로 준비한다. 발급 이후 상품 선택·구매 조작은
Tab·Enter·Space를 사용하지만 검색·장바구니·주문 내역 일부 이동은 URL로 직접 연다.
이는 모든 화면을 키보드만으로 탐색하는 검증과 다르다.

## README 간소화와 캡처 확인

상단 초안 메모와 작업 경위, E2E 조작의 세부 설명은 README에서 이 문서로 옮겼다.
핵심 설계·측정 조건·필수 실행법·알려진 제한은 유지한다.

별도 로컬 환경(PORT_OFFSET=40)에서 infra:up → db:deploy → db:seed → search:reindex를
실행하고, shop 운영 빌드와 API를 기동했다. full 시드 상품 800개·조합 3,595개 생성,
검색 717개 색인 완료. R2는 설정하지 않았다.

검색어 `코트`의 동일한 24개 상품을 유지한 채 밀도 버튼으로 전환해 CSS 열 수 3·4·6을 확인했다.
캡처는 [검토용 후보](./screenshots/density/README.md)에 두고, 사진이 없는 현재 후보는 README에
삽입하지 않았다. 촬영 중 카테고리 없는 검색 필터 요청의 400 응답을 관측해 별도 확인 사항으로 남겼다.

이번 확인은 화면·밀도 비교이며 성능 재측정이나 세 역할 거래 E2E 재실행은 아니다.
